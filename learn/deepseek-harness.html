⓪ 一句話總結

DeepSeek Harness(dsh)是 DeepSeek AI 開源的 agent harness(智能體框架)。它把「一切都做成插件」——包括模型適配器、工具註冊表、會話日誌,甚至 agent loop 本身——都是可從設定替換的插件,底層由 Cordis 框架驅動。沒有需要打補丁的特權內核:擴充方式是把插件掛到別的插件旁邊。

⚠️ 開發者預覽:官方明講目前快速迭代、未來會有破壞相容性的變更。本頁依撰寫時 clone 的原始碼與 docs/(含官方中文文件)整理,實際以官方 repo 最新為準。
💡 不只是插件——想看它獨到的 agent 設計思路?另開一頁 DeepSeek Harness 的 agent 設計思路:事件日誌即真相、waterfall 中介層、單調守衛與 fail-closed、可逆副作用+熱替換、能力 seam(llm-replay 可重放)、inbox 非同步紀律、防禦性工程、供應鏈衛生——9 個有別於一般 agent 的思路。

① 它是什麼

定位:一個可極度組合、可替換的 agent 執行框架。設計源自 Cordis 的論文《A Programming Paradigm for Spatiotemporal Composability》(時空可組合性)。它有:

  • Web UI(npx @deepseek-ai/dsh web,預設 http://127.0.0.1:3080)與 headless(一次性運行器,不帶伺服器)兩種形態;
  • 一個 54+ 套件的 monorepo,功能面涵蓋 session、tools、agent、llm、mcp、skill、subagent、compaction、sandbox、guard(把關/審批)、goal、plan、schedule、workflow、lsp、acp…;
  • 插件生態:給你的插件 repo 加 dsh-plugin topic 就能被發現。

② 一切皆插件 + Cordis 的五個核心概念

Cordis 是 dsh 以 vendor 方式引入的插件框架。看懂這五點,就看懂整個架構:

概念意思
插件 = 實現 Service 的物件一個帶可選 inject 與 apply(ctx) 的函式,或 Service 子類;生命週期由 Cordis 掛到當前上下文
上下文是服務的容器一個服務占據穩定的 ctx.<key>(如 ctx.tools、ctx.llm、ctx.sessions);別的插件用 key 查找服務,不 import 實作
用 inject 宣告依賴插件宣告需要哪些服務,等它們就緒才啟動;載入順序由依賴表達,不用手動編排
類型化事件用於通訊用 TS 宣告合併註冊事件名,再以 emit/waterfall/parallel/serial 分發
註冊是可逆的副作用提示片段、工具 schema、適配器、監聽器都經 ctx.effect()/ctx.on() 安裝,reload/teardown 時自動撤銷
白話:把 agent 拆成一堆「服務」,各自插在一個共享的「上下文」上,靠「宣告依賴」自動排好啟動順序,靠「事件」互相溝通,而且每個註冊都能乾淨地拔掉。所以連 agent loop 都能換掉。

③ Profile 與組合包(bundle)

運行中的 dsh 是一棵插件樹,由啟動時按序疊加的各層組成。

  • Profile:存在 Harness home 的具名組裝,列出它疊哪些 bundle、存樹外插件、保存使用者的 cordis.patch.yml。web 與 headless 是隨發行版附的模板。
  • 組合包(bundle):Cordis 設定項 + 掛載代碼的分發格式,它插入的東西永遠可被上層 patch。

三個基礎 bundle:

bundle提供
dsh-base每個 profile 的第一層:模型適配器、工具、持久化、沙箱與審批策略、設定、憑證、遙測
dsh-web-app加上瀏覽器應用
dsh-headless加上一次性運行器,完全不帶伺服器

疊加順序:先按 profile 列的順序套每個 bundle → profile 的 cordis.patch.yml → home 級那份 → 任意 --patch overlay。一條 patch 按 id 定位某條目、替換其整個 config 或插入新條目。看實際啟動的樹:

dsh --profile web --dump-config

④ 核心包與服務(貢獻到 Cordis 樹)

包職責ctx 鍵
core/session僅追加的 SessionEvent 日誌與記憶體存儲ctx.sessions
core/system-prompt提示詞片段與工具 schema 的組裝ctx.systemPrompt
core/tools作用域化工具註冊表 + 帶把關的執行流水線ctx.tools
core/agentAgent 介面、活躍 agent 註冊表、agent/* 事件ctx.agents
core/agent-loop實現該介面的預設驅動器(可換)ctx.agentLoop
core/scope按 agent 劃分作用域的註冊原語庫,無 ctx 鍵
llm/llm訊息與串流詞彙表 + 適配器 seamctx.llm

⑤ 三種事件域 + 四種分發模式

「事件就是擴充點」,選對事件域是大多數改動的第一個決定:

事件域用途
會話事件(session/event)追加到日誌並廣播的持久事實;重新載入後仍存在時用它
Agent 事件(agent/*)攜帶活躍 Agent(inbox/步驟/狀態/請求/驗證/續跑);要觀察或攔截進行中的工作時用它
能力事件(fs/*、tools/*、telemetry/*)不需 import 循環即可向某個 seam 附加策略與適配器

四種分發模式

模式await?順序回傳值?
emit否按註冊順序觀察否
waterfall否按序、中介層(要呼叫 next() 才往下)是
parallel是並行觀察否
serial是按序是
waterfall 語義:監聽器收 (...args, next),像環繞中介層——呼叫 next() 執行下游、可包裝其回傳;不呼叫 next() 直接 return 就短路(策略監聽器有決策權時就這樣攔截)。

⑥ 輪次流程(turn / step)

步驟(step)=一次模型請求 + 它呼叫的工具;輪次(turn)=零或多個步驟,在領首條輸入前打開、在不欠工作時關閉。

turn/start 領取 next-step 輸入 + 一條排隊訊息 組裝 prompt sections + tool schemas ─▶ agent/pre-step reject | enter(messages) step/start 把 entered messages 追加為 user/message 從日誌推導 model history agent/request ─▶ llm/stream ─▶ assistant/chunk* ─▶ assistant/message tool/call* ─▶ tools/pre-execute ─▶ tools/execute ─▶ tools/post-execute ─▶ tool/result* step/end 工具還欠一次請求 或 下一步輸入到了 ─▶ 領取 ─▶ 下一步 ─▶ agent/turn-stopping turn/end

turn/*、step/*、user/message、assistant/*、tool/* 是持久會話事件;上圖粗體的是即時擴充點——agent/pre-step、agent/request、llm/stream 與三個 tools/* 是 waterfall(要 next()),agent/turn-stopping 是 serial。輸入都經同一個 inbox 到達驅動器。

⑦ 安裝與使用

# 從 npm 直接起 Web UI(預設 127.0.0.1:3080)
npx @deepseek-ai/dsh web

# 從原始碼
git clone https://github.com/deepseek-ai/deepseek-harness.git
cd deepseek-harness
pnpm install
pnpm run build
pnpm dsh web

需要 Node.js;套件管理用 pnpm。跑 benchmark 見 docs/user/guide/python-sdk.md(用 Python SDK 跑 jsonrpc-agent 最小變體,獨立 workspace + session ID)。開發從 docs/development.md 與 docs/architecture.md 起步;面向 agent 的規範在 AGENTS.md。

⑧ vs Prime Agent:兩個插件化 agent harness

DeepSeek Harness 與 Prime Agent 都是「插件化、可組合、功能面重疊」的 agent harness,值得對照:

面向DeepSeek HarnessPrime Agent
底層框架Cordis(服務/上下文/事件/可逆副作用)建於 pi
組合方式Profile + bundle + patch 疊加,連 agent loop 可換daemon/worker/kernel 分層 + extensions
模型面向LLM 適配器 seam(ctx.llm)持久 IPython(rlm)
形態Web UI + headlessTUI + headless(print/JSON/RPC/ACP)
共同功能skill、subagent、compaction、MCP、sandbox、goal、schedule、workflow…
語言/授權TypeScript / MITTypeScript + Python / MIT
共同趨勢:兩者都把「agent 該有的一切(工具、記憶、子代理、把關、排程)」做成可替換的模組,並用事件/中介層做擴充點——這正是本站 自我演化綜述「模組架構/拓撲演化」的工程化。

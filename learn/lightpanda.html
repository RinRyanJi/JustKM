🐼 Lightpanda:為 AI Agent 從零寫的無頭瀏覽器

不是 Chromium 套殼、不是 WebKit 補丁——而是用 Zig 從零寫的一顆全新無頭瀏覽器。它不畫畫面(無 GUI),專注高效解析 HTML、跑 JavaScript(整合 V8)、操作 DOM。官方基準:跑 100 個真實網頁,記憶體 123MB vs Chrome 2GB(約 16× 省)、耗時 5s vs 46s(約 9× 快)。完全相容 CDP,現有 Puppeteer/Playwright 腳本直接接。AGPL-3.0。

⓪ 一句話總結

一顆「為機器而生」的瀏覽器。Puppeteer / Playwright 背後都是啟一整顆肥大的 Chromium,畫面、GPU、外掛全都載;但 AI Agent 抓資料根本不需要看畫面。Lightpanda 把這件事重做:用 Zig 從零寫一顆不渲染畫面的瀏覽器,只留 Agent 真正要的——解析 HTML、跑 JS(V8)、操作 DOM。結果是啟動毫秒級、單實例數十 MB,能在一台機器上同時併發數十個實例餵給 Agent。

它在這份筆記裡的位置:它是「給 Agent 的網頁後端」那條線的基礎件——和站內 闲鱼監控生態(靠 Playwright+Chromium 抓頁)、pdf-inspector(把文件變乾淨文字餵 LLM)互補。官網 lightpanda.io,GitHub lightpanda-io/browser。

① 不是 Chromium 套殼:從零用 Zig 寫

關鍵差別在「它不是 fork」。RustDesk 式的無頭方案大多還是驅動一顆真 Chromium;Lightpanda 是一顆全新瀏覽器,刻意不做畫面渲染(無 GUI)、不載 GPU/合成器那一整套,只保留自動化需要的核心能力。省下來的就是記憶體與啟動時間:

它內建 V8 跑 JavaScript,所以不是只會抓靜態 HTML——動態渲染的頁面(JS 產生的 DOM)也處理得了。這正是現代爬蟲/Agent 需要「真瀏覽器」而非純 HTTP client 的原因。

② CDP 相容:現有腳本幾乎不用改就接上

最實用的一點:Lightpanda 說 CDP(Chrome DevTools Protocol)。你把它當成一個 CDP server 跑起來,Puppeteer / Playwright / chromedp 腳本把連線端點指過去,業務邏輯一行不用改:

# 起一個 CDP server(:9222)
./lightpanda serve --host 127.0.0.1 --port 9222
# 也能聽 Unix socket(owner-only 0600):--unix-socket /run/user/1000/lightpanda.sock
# 要 WebDriver BiDi:--protocol webdriver(可與 --protocol cdp 併開)
// Puppeteer:只改 browserWSEndpoint,其餘照舊
const browser = await puppeteer.connect({
  browserWSEndpoint: "ws://127.0.0.1:9222",
});
const page = await (await browser.createBrowserContext()).newPage();
await page.goto("https://.../amiibo/", { waitUntil: "networkidle0" });

意思是:你用熟悉的工具原型,底層把 Chromium 換成 Lightpanda,就直接吃到 16×/9× 的資源優勢——這是它最低摩擦的賣點。

③ fetch:一行把網頁變 HTML / Markdown / 結構化資料

不想寫腳本、只想抓一頁?fetch 子命令直接 dump:

./lightpanda fetch --obey-robots --dump html   https://example.com/   # 原始 HTML
./lightpanda fetch --dump markdown   https://example.com/            # 直接轉 Markdown(餵 LLM 友善)
./lightpanda fetch --dump png  > page.png                            # 文字版 PNG
./lightpanda fetch --dump pdf  > page.pdf
./lightpanda fetch --dump structured_data  https://example.com/      # JSON-LD/OpenGraph/Twitter card/meta → JSON

還有 --wait-until / --wait-ms / --wait-selector / --wait-script 控制 dump 前的等待;--obey-robots 遵守 robots.txt。--dump markdown 與 structured_data 幾乎就是為「把網頁整理成 LLM 吃得下的格式」而設計。

④ Agent 模式 + PandaScript:用自然語言開車,產出可重播的腳本

lightpanda agent 讓你用白話(或 slash 指令)驅動瀏覽器:導航、點擊、填表、抽結構化資料。因為 agent 跟瀏覽器跑在同一個行程裡,每個工具呼叫都是直接操作,保住速度與記憶體優勢。最妙的是輸出:

▲ PandaScript = 一段 vanilla JavaScript 加少量內建的原生瀏覽器原語。用 LLM 探索出流程、/save 存下來,之後 lightpanda run session.js 穩定重播——把「貴且不確定的 LLM 操作」沉澱成「便宜且確定的腳本」。

Agent 模式支援 Anthropic / OpenAI / Gemini / Vertex / Mistral / Hugging Face、Vercel AI Gateway、OpenRouter、任何 OpenAI 相容端點(OPENAI_BASE_URL)、本地模型(Ollama / llama.cpp / LLMD),以及用 ChatGPT 訂閱登入的 OpenAI Codex。

⑤ 原生 MCP:直接當 AI 工作流的瀏覽後端

Lightpanda 內建 MCP 伺服器(JSON-RPC 2.0 over stdio),把「瀏覽器能力」當工具開給 Claude Code / OpenCode 等 MCP client:

{
  "mcpServers": {
    "lightpanda": { "command": "/path/to/lightpanda", "args": ["mcp"] }
  }
}
# 只開你要的工具,少佔 client context:--tools goto,tree,click
# lightpanda mcp --list-tools 列出所有工具名
# 多 agent 共用一個行程:走 HTTP 傳輸 → lightpanda mcp --port 9223(每連線獨立 session)

--tools 白名單是個貼心設計:MCP 工具定義會吃掉 client 的 context,只暴露用得到的幾個(goto,tree,click…)能省很多。

⑥ 安裝與部署

  • 套件管理器:Homebrew(brew install lightpanda-io/browser/lightpanda)、Arch AUR(yay -S lightpanda-nightly-bin)、Nix(nix run github:lightpanda-io/browser)。
  • 直接下載 nightly 二進位:Linux / macOS 的 x86_64 與 aarch64。
  • Docker:官方映像,一行把 CDP server 開在 :9222 → docker run -d -p 127.0.0.1:9222:9222 lightpanda/browser:latest。
  • Windows:沒有原生二進位,裝進 WSL2 用(WSL 會自動轉發 localhost:9222)。
glibc 注意:Linux release 二進位連結 glibc(x86_64 需 2.35、arm64 需 2.38),musl 系(Alpine)會失敗(缺 glibc 動態連結器);arm64 上連 debian:bookworm 都太舊,要用 ubuntu:24.04 / debian:trixie-slim 或自行編譯。Android/Termux(Bionic libc)也不行。

⑦ 適用 · 限制 · 授權

  • 最適合:大規模、高併發的 Agent 網頁抓取/自動化——在本地伺服器或容器裡同時開數十個實例,靠低記憶體與毫秒啟動把成本壓下來。
  • 不是什麼:它不渲染畫面,不是給人看的瀏覽器;也還是一顆新的、仍在發展中的瀏覽器引擎,網頁相容性不可能等同成熟的 Chromium——複雜網站上可能遇到還沒實作的 API。拿它跑你實際的目標站先驗證。
  • 授權:AGPL-3.0(把改版當網路服務提供時,須以同授權公開該版原始碼)。

⑧ 重點 · 關聯 · 來源

七個帶得走的重點

  1. 為 Agent 而生的無頭瀏覽器,Zig 從零寫、不是 Chromium fork。
  2. 不渲染畫面,只做 HTML 解析 + JS(V8)+ DOM → ~16× 省記憶體、~9× 快。
  3. CDP 相容:Puppeteer/Playwright/chromedp 腳本改個端點就接上;也支援 WebDriver BiDi。
  4. fetch --dump 一行把網頁變 HTML/Markdown/PNG/PDF/結構化 JSON。
  5. Agent 模式產出 PandaScript:用 LLM 原型 → 存成確定性、token-free 腳本重播。
  6. 內建 MCP 伺服器(stdio/HTTP,--tools 白名單),直接當 AI 工作流的瀏覽後端。
  7. 裝法多(brew/nix/docker/WSL);注意 glibc 版本;AGPL-3.0。

🔷 Prime Agent：RLM 自我改進 coding agent 的架構拆解

建於 pi 之上 · daemon／worker／IPython kernel 三層 · 兩大抽象:RLM 與 Continual Harness

TypeScript + Python · MIT daemon-backed RLM 遞迴子代理

⓪ 一句話總結

Prime Agent 是 PrimeIntellect 的開源「自我改進 RLM coding/research agent」,為長時間任務設計。它把 agent 拆成常駐 daemon + session worker + 模型面向的持久 IPython kernel三層,核心是兩個抽象:RLM(把上下文當變數、子代理當函式呼叫,全在一個持久 REPL 裡)與 Continual Harness(把提示/記憶/技能/子代理規格存成耐久狀態,用 /refine 小步演化)。

📌 關鍵事實:Prime Agent 建構在 pi(earendil-works/pi)之上——repo 內的套件就是 @earendil-works/pi-*,再加上 PrimeIntellect 的 prime-agent-runtime(RLM 的 Python kernel shim)與長任務功能。與站內oh-my-pi 同屬 pi 家族。授權 MIT。

① 它是什麼(建於 pi)

官方定位:「一個 general 且 long-running 的開源 coding/research agent」。它圍繞兩個核心抽象設計(詳見 ⑦):

  • Recursive Language Model (RLM):context 是變數(prompt-as-a-variable)、工具與遞迴子代理是函式呼叫(programmatic tool / sub-agent calling),都在一個持久 IPython REPL 裡。
  • Continual Harness:補充提示、記憶、技能描述、可重用子代理規格 = 耐久狀態,agent 可用小步、有證據的更新去精煉,預設 local 到當前 session。

設計主張:「一切都是程式化的」——檔案操作、shell、工具、子代理、上下文管理全透過程式碼;子代理內建(rlm(...));harness 可自我改進(/refine,但永不改動不可變的 base system prompt);技能是可 import 的 Python 套件;session 可背景常駐、斷線 reattach;agent 之間能直接通訊。

② 專案結構

prime-agent/ ├─ prime-agent.sh 啟動器(tsx 開發 / dist bundle) ├─ install.sh 安裝腳本(下載 release + 驗 SHA-256) ├─ packages/ TypeScript monorepo(~916 個 .ts) │ ├─ ai/ @earendil-works/pi-ai 模型 provider(Anthropic/OpenAI/Gemini/Bedrock/Mistral…) │ ├─ agent/ @earendil-works/pi-agent-core agent 核心 │ ├─ coding-agent/@earendil-works/pi-coding-agent 主體:CLI/daemon/session/kernel/tools ← bin: pi │ └─ tui/ @earendil-works/pi-tui 終端 UI └─ prime-agent-runtime/ Python(IPython kernel 端) └─ src/rlm/ harness.py · skill.py · mcp_base.py · __init__.py

四個 TS 套件各司其職;coding-agent 是主體(CLI、daemon、AgentSession、kernel 管理、工具都在這)。Python 端 prime-agent-runtime 只是 kernel 內的薄 shim——不呼叫 provider、不實作 agent loop。

③ 怎麼啟動(入口鏈)

  1. prime-agent / prime-agent.sh 是啟動器,注入 build id 等環境。
  2. 開發模式:用 tsx 跑 packages/coding-agent/src/cli.ts;使用者版:--dist 跑打包好的 dist/bundle/cli.js(啟動快 ~3 倍)。
  3. 需 Node ≥ 22.8;--no-env 會清掉所有 provider API keys(見 packages/ai/src/env-api-keys.ts)。

CLI 起來後,不是自己跑 session,而是連上背景 daemon(沒有就啟動一個),由 daemon 分派給 worker——這就進入下面的執行架構。

④ 執行架構總覽

它刻意把「畫面 / 程序協調 / agent 執行 / 模型面向 Python / 持久狀態」分層:

互動 TUI / headless(Print · JSON · RPC) │ AgentConnection(client 只負責渲染與輸入,不擁有執行) ▼ Daemon Supervisor(公用 socket、路由、附掛、崩潰復原、跨 agent 傳訊) ├─ Catalog 子程序(掃描已存 session) ▼ Session Worker(一棵 root session 樹一個 process) AgentSessionRuntime ─→ Root AgentSession ├─ 串流呼叫 ⟶ Model Providers ├─ Root IPython Kernel ← 模型主要的「工具」就是持久 Python ├─ RLM 子 runtime(subagents,各自 session + 可選 kernel) └─ Scheduler(heartbeat / cron / goal / autonomous) ▼ Session JSONL 逐字稿 + artifacts(持久化)

一次 prompt 的流程

client 送 versioned command → supervisor 路由到 active session → worker 排入 AgentSession → 串流給模型 → 模型回「文字」或「IPython 工具呼叫」→ kernel 執行 Python;若是 typed host request(檔案操作、spawn 子代理…)就回 TS host 執行 → 逐字稿與 artifact 落地 → 事件串回 client 渲染。heartbeat / 排程 / goal / autonomous / 別的 agent 觸發時,走的是同一條路。

不是安全沙箱:worker 與 kernel 是分開的 process,只為生命週期與故障隔離,跑的是你的使用者權限。官方明確警告:只在可信 repo 用,untrusted 程式請丟外部沙箱。

⑤ 深入:RLM 遞迴橋接(rlm.run 是怎麼運作的)

每個 session 有一個持久 IPython kernel 與原生的遞迴子代理介面。Python 的 rlm 套件只是模型面向的 shim;真正的子代理執行、持久化、用量計算、生命週期都在 TypeScript host。

當模型在 Python 裡委派工作:

handle = await rlm("inspect the API", name="api-reviewer")
print(handle.rlm_child_id, handle.name, handle.session_dir, handle.model)

橋接怎麼走

  1. 這個呼叫透過一個 Jupyter comm target host.request 送出。
  2. KernelManager 把 request type rlm.run 分派給父 AgentSession。
  3. 父 session 檢查遞迴深度、解析要用的模型、admit 子任務、更新 registry,然後透過與父層相同的 agent 機制啟動子代理。
  4. ⭐ 關鍵:呼叫在「任務被接受」後立即用 comm 回傳一個 child handle,不等、也不回子代理的答案(fire-and-forget)。結果只透過顯式的 agent_message 回覆或檔案回來。
為什麼這樣設計:子代理是「非阻塞」的——父代理 spawn 之後可以繼續做別的事、或平行 spawn 更多子代理,之後再收訊息。這正是它能做平行 / 背景 / 長時間工作的關鍵。同一條 host.request 橋也支撐 goal.*、agent_message.* 等 typed 請求——狀態與政策一律留在 TS host。

Kernel 生命週期

kernel 首次用到 IPython 才延遲建立。Python 解析順序:① PRIME_AGENT_KERNEL_PYTHON(能 import ipykernel 時)→ ② ~/.prime/agent/kernel-venv/bin/python(用 uv bootstrap)→ ③ ~/.prime 不可寫時退到 XDG 位置。受管環境含 Python 3.11 + ipykernel + prime-agent-runtime。啟動會建臨時 Jupyter 連線檔(loopback TCP ports + HMAC key)、起 ipykernel_launcher、連 shell/IOPub/control 三個 socket、用 kernel_info_request 探測就緒。傳輸走 ZeroMQ 上的 Jupyter 協定。持久 session 可把 kernel namespace 快照到 artifact 目錄以便復活。

⑥ 深入:Daemon 架構(常駐、租約、復原)

Prime Agent 把每棵 active root session 樹隔離在自己的 process。daemon 是內部基礎設施;interactive / print / JSON / RPC 只是 client 行為。

Clients(interactive · print · JSON · RPC) │ public local protocol ▼ Supervisor(公用 socket、附掛、路由、全域 agent-message、worker 健康、指令 journal、協調更新) ├─ Catalog 子程序(已存 session 掃描;掛了不影響 active worker) ├─ Resident worker · root A(RLM 後代 + kernels) ├─ Resident worker · root B └─ Client-owned worker(隱藏 root;headless/ephemeral 用)

Supervisor 不執行 provider/工具/compaction/bash/kernel/排程/掃描——它只管協調。

Resident workers(互動 session)

  • 每棵 active root 樹一個 detached process group;關掉 TUI 只是 detach client,worker 不會停。
  • worker 監看 supervisor socket;若 supervisor 消失,某個 worker 取得原子 launch lease 啟動替補 supervisor,替補會認領現存 workers。
  • 崩潰復原:一次 worker crash 只影響一棵 root 樹;復原在 250ms → 1s → 5s 重試,三次失敗就標記該 root failed。
  • prime-agent shutdown 停 supervisor 與所有 worker;--force 連無回應的 process group 與追蹤的子程序一起終止。

Client-owned workers(headless/一次性)

print / piped-stdin / JSON 是 one-shot;RPC 用 LF 分隔的 JSONL,收 prompt 到 EOF;interactive --no-session 用記憶體內 session。client 意外斷線會進入有限的清理寬限期,用同一 client identity 重連可取消清理。

Session 租約(防並發寫壞逐字稿)

每個持久 session 由一個以正規 JSONL 路徑為 key 的 process-safe lease 保護:worker 開 session 前先取 lease;runtime 替換時先取新 lease 再放舊的;並發開啟回傳 session_already_active 與擁有者的 active-session ID;並發建立會收斂到同一個 worker。排程 job 存在各 session 的 session-artifacts/<id>/scheduled-jobs.json,不共用全域 cron。

⑦ 兩大核心抽象

RLM(Recursive Language Model)

  • prompt-as-a-variable:上下文是 REPL 裡的變數,可被程式操作。
  • programmatic sub-agent calling:rlm(...) 是函式呼叫,spawn 真的子代理,非阻塞回 handle。
  • 一切經持久 IPython:檔案、shell、工具、子代理、上下文管理都用程式碼做。

Continual Harness(自我改進的耐久狀態)

  • Python 端 harness.py 把 prompt / memory / skill / subagent 四種項目 + refinement 事件,存成 ~/.prime/agent/harness/harness_state.json(預設 local scope,可 global)。
  • /refine 檢視當前 trajectory,做小步、有證據的更新;有快照支援 rollback;永不改動不可變的 base system prompt。
  • 技能是可 import 的 Python 套件,內建 skill creator 能把重複流程變成 project/personal skill。
連到「自我演化 Agent」:Continual Harness ＝ 綜述裡「環境中心 · 動態經驗/技能增強演化」的工程化;RLM 的遞迴子代理 ＝「拓撲/多代理」路線的實作。見 自我演化 Agent 綜述。

⑧ 要跑起來需要什麼

# 正式安裝(macOS/Linux)
curl -fsSL https://app.primeintellect.ai/prime-agent/install.sh | sh
cd /path/to/project && prime-agent
# 首次 /login 選 subscription 或 API-key provider

# 從原始碼
npm install          # repo root,Node ≥ 22.8
npm run build        # 依序 build tui→ai→agent→coding-agent
./prime-agent.sh     # 或 --dist 跑 bundle

另需 Python(IPython runtime,首次用到 kernel 時以 uv 自動 bootstrap)與模型 provider 金鑰。常用:prime-agent agents / attach / --resume / status / doctor --fix / shutdown。

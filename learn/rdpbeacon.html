🖱️ RDPBeacon:用一像素滑鼠微動保住 VDI 連線的 Rust 守護程式

名字看起來像惡意軟體,其實是個無害的「防閒置」小工具:一個用 Rust 寫的跨平台 CLI 守護程式,每隔幾分鐘對 Omnissa Horizon(VDI/虛擬桌面)視窗送一個「1 像素滑鼠微動再移回」的保活訊號,避免因閒置被斷線。本頁從原始碼拆解它的架構、一個 beacon 週期怎麼跑、三個平台後端各用什麼系統 API,以及它誠實標明「做不到什麼」。

⓪ 一句話總結(先澄清名字)

RDPBeacon 不是 C2、不是木馬——雖然「Beacon」這字在資安界常指惡意回連。它其實是個防閒置(anti-idle / keep-alive)工具:讓你已登入的 Omnissa Horizon Client(就是前身 VMware Horizon 的 VDI 用戶端)不會因為你暫時沒操作而被伺服器斷線。做法很單純——每隔幾分鐘,對 Horizon 視窗注入一個極小且無害的模擬輸入(預設是把滑鼠游標推 1 像素再推回來),騙過閒置計時器。

為什麼值得讀:它是一個麻雀雖小、五臟俱全的 Rust CLI 範例——trait 抽象的後端、跨 X11/Wayland/Windows 的輸入注入、焦點保存/還原、隨機抖動排程,而且 README 很誠實地標出它「做不到什麼」。拿來學「跨平台系統程式怎麼分層」很合適。

① 它解決什麼問題

用 VDI(虛擬桌面)上班的人常遇到:開著 Horizon 連到遠端桌面,但你切去本機處理別的事、或離開一下,遠端 session 因為「閒置逾時」被強制斷線,回來得重連、重開應用、丟掉現場。RDPBeacon 就是定期製造一點「你還在」的輸入訊號,把閒置計時器往後推。

  • 保活的是「輸入閒置計時器」,不是什麼都繞過(見 ⑦)。
  • 你真的在用 Horizon 時會自動跳過:你的打字本身就讓 session 活著,不需要多此一舉。
  • 背景的 Horizon session 照樣保活:就算你在本機別的視窗工作,背景那個遠端桌面也不會被放生。

② 架構總覽:一個 crate,trait 解耦後端

整個工具是單一 Rust crate,用 trait 把「平台相關的髒活」和「平台無關的邏輯」切開:

← 左右滑動看完整圖 →
▲ scheduler 不知道自己在哪個平台;它只對著 Backend trait 呼叫,實際由三個後端其中一個實作。想加 macOS?再實作一個 Backend 就好。
  • config:serde + toml 強型別設定,用 humantime_serde 吃人類友善的時間字串("4m"、"20s");deny_unknown_fields 防打錯設定名。
  • scheduler:核心迴圈。管理隨機化睡眠(interval ± jitter,夾下限 1 秒)、比對系統閒置時間與 idle_threshold、呼叫後端、並在連續找不到視窗時依 max_misses 退出。
  • backend(Backend trait):閒置偵測、找視窗、切焦點、注入 beacon 的標準介面——三平台各自實作。

三個子命令

子命令做什麼
run啟動守護迴圈,閒置時定期送 beacon;連續 max_misses 次找不到 Horizon 就報錯退出;Ctrl-C 乾淨關閉。
once立刻跑一個 beacon 週期(忽略 idle_threshold),印出結果(Sent / SkippedNoWindow / SkippedActive)。
check檢查環境:回報偵測到的後端、目前系統閒置時間、Horizon 視窗狀態。

③ 一個 beacon 週期怎麼跑(run_cycle)

每一輪的邏輯都圍繞一個目標:只在「需要時」送、送完把你的環境還原得像沒發生過。原始碼裡一個週期回傳三種結果之一:Sent、SkippedActive(你正在用)、SkippedNoWindow(找不到 Horizon)。

← 左右滑動看完整圖 →
▲ 「存焦點 → 切 Horizon → 等鉤子就緒 → 注入 → 停留確保送達 → 還原」整套只花約 100ms,對你幾乎無感。若 Horizon 本來就是焦點且你在打字,就直接跳過。

排程的小細節:為什麼要抖動(jitter)

next_sleep 用 rng.gen_range(low..=high) 在 interval ± jitter 之間取隨機睡眠(夾下限 1 秒)。固定節奏的機械式輸入很容易被辨識成「自動化」;加點隨機抖動讓它更像真人的不規則操作。

④ 三個平台後端:各用什麼系統 API

同一個 Backend trait,三種截然不同的系統底層:

能力Linux (X11)Linux (Wayland)Windows
函式庫x11rbevdev + /dev/uinputwindows crate(Win32)
閒置偵測XScreenSaver❌ 無法跨 client 查(見下)GetLastInputInfo
找視窗EWMH:_NET_CLIENT_LIST❌ 無法查別 app 視窗EnumWindows + GetWindowTextW
切焦點EWMH:_NET_ACTIVE_WINDOW❌ 不允許切別 app 焦點SetForegroundWindow(+AttachThreadInput 後備)
注入輸入XTest fake_input/dev/uinput 虛擬裝置(全域)SendInput

Wayland 的安全模型逼出的取捨

Wayland 刻意隔離各應用、禁止跨 client 操作視窗或切焦點。RDPBeacon 繞法是用核心的 /dev/uinput 介面「從底層」造一個虛擬輸入裝置——不需要 root 或顯示伺服器權限(設好 udev 規則 + 加入 input 群組即可)。代價是兩個限制:

  • 不能切焦點:事件只會送到「當前作用中的視窗」,無法自動把 Horizon 拉到前景——所以 Wayland 下得自己確保 Horizon 在前景。
  • 不能查全域閒置:因此 Wayland 下 beacon 會無條件按固定間隔觸發,不管你本機在不在忙。
零快取設計:每個週期都重新查一次視窗(不快取 window id),所以 Horizon 重啟、視窗標題改變都能自動適應。

⑤ 視窗比對的聰明處(title_matches)

怎麼認出「這個視窗是 Horizon」?預設 window_match = "Omnissa Horizon Client",但原始碼的比對不只是比標題:

  • 標題或 WM_CLASS 任一命中(X11 會一起看 WM_CLASS),大小寫不敏感的子字串比對。
  • 特別處理遠端 session 視窗:當 matcher 含 horizon/vmware/view 時,也會比對那些 class 是 HorizonUnityWindow/UnityWindow/MKSWindow 的實際遠端桌面視窗——因為真正要保活的是那個遠端畫面,而不只是外層的 client 殼。
  • 還會辨識工具列視窗(標題 BBar)等,避免誤判。

這類「兼容多種視窗命名」的小細節,正是讓工具在不同 Horizon 版本、不同語系下還能穩定找到目標的關鍵。

⑥ 設定項(TOML)

欄位型別預設說明

jitterduration"20s"間隔上下的隨機變動(interval ± jitter,最少 1 秒)。
idle_thresholdduration"3m"Horizon 聚焦時,閒置多久才送 beacon;你在裡面打字就跳過。背景 session 不受此限,照樣保活。

⑦ 誠實邊界與政策合規(很重要)

這頁最值得學的態度:README 很老實地列出它做不到什麼,不浮誇。

  • 只擋「閒置逾時」,擋不了「硬性 session 上限」:它模擬的是本機輸入,防的是 inactivity timeout;無法繞過 Horizon 連線伺服器或身分供應商設的「最長 session 壽命」(例如 8 小時強制登出)。
  • 會順便重置你本機的鎖屏/螢保計時器:因為注入的是真的 OS 輸入,連本機閒置計時也被重置——可能讓本機螢幕保護/自動鎖屏不會啟動。離開座位務必手動鎖屏(Win+L / Super+L)。
  • 遠端桌面被鎖定時不保證有效:本機輸入注入無法確認「被鎖定的遠端 Windows 桌面」真的收到事件、真的重置了它的閒置計時。
  • 這是「自用」生產力工具:作者明言你要自行確保使用它符合公司的 IT 資安、可接受使用(AUP)與遠距工作政策。繞過公司刻意設定的逾時策略前,請先確認你被允許這麼做。
為什麼不是「作弊掛機」工具:它的定位是「我人在、只是手沒一直動,別把我踢掉」,而不是「假裝我在但其實人不在」。這兩者的差別,就落在你有沒有照 ⑦ 的提醒離開就鎖屏、以及你公司政策允不允許。

⑧ 重點 · 關聯 · 來源

六個帶得走的重點

  1. 名字嚇人,本質是防閒置保活:對 Omnissa Horizon 視窗送 1 像素滑鼠微動,避免 VDI 閒置斷線。
  2. 單一 Rust crate,用 Backend trait 把平台無關邏輯(scheduler)與平台後端(X11/Wayland/Windows)解耦。
  3. 一個週期:存焦點 → 切 Horizon → 等鉤子 → 注入 → 停留送達 → 還原;你在用就跳過,背景 session 照保。
  4. 三後端系統 API 各異:X11 用 XTest/EWMH/XScreenSaver、Wayland 用 /dev/uinput、Windows 用 SendInput/GetLastInputInfo。
  5. 排程有 jitter 隨機抖動、視窗比對兼容多種 Horizon 視窗 class、零快取每輪重查。
  6. 誠實標明做不到:擋不了硬性 session 上限、會重置本機鎖屏(離開要手動鎖)、須符合公司政策。

🧮 環形 XY 繪圖機的軟體:逆運動學、可微描繪與偏移補正

這是前一篇「硬體製作篇」的另一半:kohya-ss/ring-xy-plotter 是驅動那台環形繪圖機的 PC 端 Python 軟體。它把線稿圖變成 G-code(三段指令),用閉式逆運動學把 (x, y) 換成兩個角度,並用一整套「量測→建模→補正」把一台組不準的機器調到亞毫米精度。本頁拆解它的工具鏈、運動學、可微影像貼合,以及最精彩的兩層較正與偏移補正。

Python · MIT · 機器專用 閉式逆運動學 · 可微描繪器 · PyTorch 兩層較正 · 偏移模型 · GRBL G-code

⓪ 一句話總結

硬體把筆帶到某個角度,軟體負責「要去哪個角度」以及「怎麼補償機器的不準」。倉庫是這台環形繪圖機的 PC 端軟體:三段指令把線稿圖變成 G-code(img2svg → refine-passes → svg2ring),一支 grbl_send.py 送到機器;核心是閉式逆運動學(把紙面座標換成 A、B 兩個角度)與一整套較正 / 偏移補正腳本——把一台「組不準、還會隨畫的方向偏」的機器,壓到線中央最大 0.05mm 的誤差。

和前一篇的關係:這頁是 硬體製作篇 的軟體與精度另一半。作者說明:這是個人工作記錄、不收 PR、且專屬這台機器;文中數字是作者機器(環半徑 ~231mm、A4)的實測,換機器就會變。授權 MIT。

從一張線稿圖到機器動起來,是三段(手上已有 SVG 就只需第 3 段):

← 左右滑動看完整圖 →
▲ svg2ring 與 ring-preview 會把產生的 G-code 讀回來自我檢查(範圍、速度、纜線扭轉),有問題以 exit code 1 列出。

G-code 的約定:X = A 角 α、Y = B 角 β(度),G90;抬筆 M5、落筆 M3 S110,之後 G4 P<待時>;從擋塊原點 X0 Y88 開始、結束回到該處。送速以「筆尖以 --speed(預設 15mm/s)移動」反推每段的 F。作者日常用 --speed 30 --fmax 2250 --accel 200。

② 逆運動學:把 (x, y) 換成兩個角度(閉式解)

kinematics.py 提供閉式的順/逆運動學,沒有數值搜尋。模型:A 的銷 = R·(cos α', sin α')(α'=α−90°),筆尖 = A 銷 + d·u + e·n(u 是 A→B 單位向量、n 垂直於 u)。設 L = hypot(d, e)(A 銷到筆尖的距離)、γ = atan2(e, d)。

← 左右滑動看完整圖 →
▲ 同一筆尖位置有兩個鏡像擺法。中心附近(半徑約 9mm 內)兩個分支都有效,所以畫線時要傳入前一點的 α 保持分支,否則會每點跳枝、α 跳近 180°(紙上變成一個圈)。

到達範圍:r < |R−L| 是中心畫不到的洞;|cosψ| > 1 則搆不到,丟 Unreachable。程式碼裡的預設參數(作者機器、十月初較正值):R=230.778, d=229.190, e=6.428(mm)——這些是較正算出來的值,不是設計值,換機器/換筆就重測。

③ img2svg:從線稿圖抽出可畫的線

把點陣線稿變成折線 SVG(raster.py / img2svg.py):

  • 二值化:Otsu 自動(--threshold 指定、--invert 白線)。
  • 線 / 塗分離:比 --fill-width(預設 1.5mm)粗的算「塗」、細的算「線」;線細線化(thinning)成中心線。
  • 線的整理:交點切斷、去短鬚(--spur)、直線相接(--join)、平滑(--smooth)、間引點(--simplify);短於 --min-length 丟掉。
  • 塗的畫法:--fill hatch|outline|none|skeleton;若要交給 refine-passes,用 none 即可(塗由第 2 段生成)。
  • 粗細不同的線:給 --pen-width 時,比筆寬粗的線用「沿中心線橫移的平行路徑」描(1 本在 strokes 層、其餘在 passes 層,刪掉就回到單線版)。
  • 輸出 SVG 分層(線/平行路徑/輪廓/ハッチング),可在 Inkscape 直接改。

④ refine-passes:用「可微描繪器」把折線貼合影像

這是全軟體最漂亮的一招。img2svg 的「線塗分離」有癖(切面長出輪廓線、殘鬚、本數段差)。refine-passes 改用可微分的描繪器,以 img2svg 的線為初值,移動折線頂點讓「以筆寬描出的像」貼合原圖。A4 一張在 RTX 4090 上約 20 秒。

← 左右滑動看完整圖 →
▲ 描繪器把每段線畫成「縁 c = sigmoid((w/2 − d)/τ)」、以 1 − Π(1 − c) 合成;縁模糊 ⇒ 頂點往哪動能減誤差可用微分求出。
  • 塗內間隔(--cover):只用二乘誤差,塗線會被間引到筆寬極限,畫出時微偏就露白筋;所以把「用稍細的筆是否填滿」也放進損失。
  • 線的向向:相鄰線反向畫會讓「隨向偏移」相反、易露白筋,所以追加的線方向一致;要保持方向畫需 svg2ring --keep-direction(回程移動變多、時間約多 3 成)。
  • 輸出:SVG(strokes+added 層)、_render.png、_residual.png(紅=缺、藍=多)、_target.png。

⑥ 偏移模型與補正:把物理寫進公式再補回去

硬體製作篇提到「陰影線往復差 0.4mm」的謎題——真因是機器的柔軟 + 隨方向反轉的摩擦。軟體把它建成一個模型:筆尖只沿桿的方向偏,偏移量用兩個係數表示。

# 偏移(沿桿方向 u)
偏移 = ( a·sin²(Δ/2)·g(v·u) + b·sign(ċ) )·u

# v=進向, u=棒向, ċ=兩台間距伸縮, Δ=兩台角差
# g 從 g(x)=x 改成 g(x)=sign(x)·√|x|(小 x 快立、再頭打)
← 左右滑動看完整圖 →
▲ 轉向後偏移要走距離 λ(1–2mm)才長起來,所以用「指數逼近」更新狀態;抬筆移動也延續狀態。預覽畫的是補正後的指令路徑,所以會看起來和 SVG 差最多 0.5mm。

速度係數:加減速區速度越高偏移越小,目標乘 f(v)=1 − c_speed·max(0, 1 − v/v_ref),線兩端再乘 (1 − c_end·max(0, 1 − v/v_c))。速度由 timing.py 跑 GRBL 的台形加減速逐段算出。

⑦ 量測實例:精度怎麼一路降下來

作者機器的歷程(當作「數字量級 + 什麼有效」的參考):

階段結果
最初量測(113 處)a=+0.53、b=+0.08mm、λ=1.9mm;殘差 rms 0.03mm(無補正則 0.16)。不乘 sin² 的版本在近中心側補正少約 3 成
重固定軌道後a=+0.59、b=+0.08、λ=1.4;補正後線中央殘差 rms 0.036、最大 0.10mm
g 改成 √ 形係數數目不變,擬合 rms 0.038 → 0.015mm;畫出的中央殘差 rms 0.014、最大 0.047mm
lead-in 3mm起點彎 ≥0.15mm 的線 30% → 10%
速度係數c_speed=0.17,慢的中心殘差消失;兩端不足故另分 c_end(~0.4)
最終設定a=0.444、b=0.099、λ=0.93、c_speed 0.15、c_end 0.4、lead-in 3、lead-out 0.15;線中央偏移最大 0.052mm、起點彎 ≥0.15mm 的線 5%、終點不足 +0.002mm

「發現了什麼」

  • a 的符號為正:筆尖在進向上是「超前」而非「落後」——不能只用摩擦拖曳解釋。
  • 同模樣畫兩枚的差 rms 0.004–0.03mm,殘差大致在量測可重現性之內。
  • 軌溝貼膠帶想抑振那天,偏移整體變 1.4 倍——機器變軟就多偏(呼應硬體篇)。
  • 線寬常比公稱粗(公稱 0.5mm 實測 0.72–0.74mm);量端點要用實測線寬。
  • 加速度 100→200 度/秒² 讓模樣 1 枚 10:22→9:15、絵 1 枚 19:32→16:59;300 以上頭打。

⑧ 安全與送出的約定(踩過的坑都寫進檢查)

  • 送前三步:看 svg2ring 的預覽與統計(搆不到的線、α/β 範圍、時間)→ 實機送 G92 X0 Y88 原點、先抬筆空跑一遍 → 沒問題再裝筆畫。
  • 自我檢查:兩台角差 Δ 不可出 88–180°;纜線扭轉(自原點旋角)要在 ±400° 內;各軸速度不可超 GRBL 上限。有問題 exit code 1 列出。
  • 脫調檢查:--dry-run X Y 空跑前後在 (X,Y) 各畫一個 4mm 十字,兩個十字重合=沒掉步。
  • G-code 只能 ASCII:GRBL 會把 ≥0x80 的位元組(即使在註解裡)當即時命令(0x84=安全門、0x90 台=override)。混進日文或「°」會卡 [MSG:Check Door] 或改變送速。grbl_send.py 送前會去掉註解、殘留非 ASCII 就停。
一個典型的「把事故變成檢查」:硬體篇那次差點燒馬達、這裡的 ASCII 之坑、脫調、角差守備——都被寫成程式會自動攔的檢查或 --dry-run。這是「個人工作記錄」難得的嚴謹:每個教訓都固化成不會再犯的護欄。

可以偷師的設計取向

  • 把物理的不完美拆層、分別量測、用公式補回——而不是硬在機械上消除(呼應硬體篇「e 不要靠機械消、在公式端處理」)。
  • 可微描繪器:把「畫出來像不像」變成可用梯度下降的目標,是把 ML 思維用在筆畫最佳化的漂亮例子。
  • 每個坑都變成自動檢查:ASCII、角差、脫調、時間推估一致性。

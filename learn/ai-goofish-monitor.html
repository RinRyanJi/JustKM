🐟 Usagi ai-goofish-monitor:Playwright + AI 的闲鱼撿漏監控系統

社群衍生最多、架構最完整的一套闲鱼(Goofish/Xianyu,阿里二手平台)監控系統。用 Playwright 模擬網頁端抓新上架商品,接 OpenAI 相容 API(本地或雲端模型皆可)照你一句話需求逐品把關,過濾掉商家與不對版的,才發通知。後端 FastAPI + SQLite,前端 React/Vite,整套有 Web 管理介面,Docker 一鍵部署。MIT。

⓪ 一句話總結

一個「替你盯闲鱼」的自動化系統:機器搜貨,大模型把關,對版的才通知你。你用自然語言描述需求(例:「95 新以上的 Sony A7M4,預算 1.3 萬內,快門數低於 5000」),它先讓 AI 生成一套分析標準,再用 Playwright 持續/定時搜尋新上架商品,逐品交給多模態模型看圖看描述判斷對不對版,推薦的才推到你手機。整套跑在你自己機器上,資料進本地 SQLite。

它在生態裡的位置:這是 闲鱼 AI 監控生態 裡社群衍生版本最多、功能最完整的一套(連 Windows 一鍵版 nobugpy/ai-goofish-monitor-win 都是它的二次打包)。致謝裡提到參考了 superboyyy/xianyu_spider 與 LinuxDo 社群腳本。MIT,README 明言「僅供學習與技術研究」。

③ AI 把關:一句話需求 → 分析標準 → 逐品判斷

這是整套系統的靈魂。建任務有兩種模式:

  • AI 判斷:你填「詳細需求」(自然語言),提交後跑一個後台 job 先生成一套分析標準,再建任務。因為要先問一次模型,所以不是秒成——UI 會彈獨立進度窗,避免表單卡住。API 上是 POST /api/tasks/generate(decision_mode=ai)回 202 + job,再輪詢 GET /api/tasks/generate-jobs/{job_id}。
  • 關鍵詞判斷:只填關鍵詞規則,直接建任務,不經 AI 生成流程(decision_mode=keyword 直接回已建任務)。

任務跑起來後,每個搜到的商品會連同你的需求一起餵給多模態模型(所以 OPENAI_MODEL_NAME 必須支援圖片輸入,例如 qwen-vl-plus、doubao-seed 類)。模型判斷對不對版、要不要推薦,並附上理由。Prompt 可在 Web UI 的系統設定裡編輯。

為什麼要多模態:二手商品的關鍵資訊常在圖片裡(成色、劃痕、型號貼紙、是否全新盒裝),光看標題文字會被商家話術騙過。看圖才能真正「把關成色」。

④ 登入態與多帳號:為什麼一定要登入

闲鱼未登入只看得到 6 小時前的舊貨,要盯「實時新發布」必須有登入態。Usagi 的做法不是在程式裡填帳密,而是把瀏覽器的登入態整包搬過來:

  1. 裝官方的 Chrome 擴充(Xianyu Login State Extractor),在已登入的闲鱼頁面把登入態導出成一段 JSON。
  2. 到 Web UI「闲鱼帳號管理」貼上這段 JSON,存成 state/acc_1.json 之類的檔。
  3. 建任務時綁定某個帳號(也可不綁、交系統自動選)。
帳號風險要清楚:用登入態做自動化抓取,等於拿你的闲鱼帳號在跑機器人。請求太頻繁可能被平台風控、限流甚至封號。README 明確要求遵守闲鱼用戶協議與 robots.txt、別高頻請求。建議用小號、放慢節奏。

⑤ 抗風控:代理輪換 + 失敗保護

既然是拿真帳號長時間跑,系統給了一整套「被盯上就換、連錯就退避」的機制(全在環境變數裡調):

類別環境變數作用
代理輪換PROXY_ROTATION_ENABLED是否啟用代理池輪換
PROXY_ROTATION_MODE輪換策略
PROXY_POOL代理池清單
PROXY_ROTATION_RETRY_LIMIT單代理重試上限
PROXY_BLACKLIST_TTL壞代理拉黑多久
失敗保護TASK_FAILURE_THRESHOLD連續失敗幾次就暫停
TASK_FAILURE_PAUSE_SECONDS暫停多久再試
TASK_FAILURE_GUARD_PATH失敗守衛狀態路徑
其他PROXY_URL / RUN_HEADLESSAI 請求單獨走代理;Docker 內固定無頭

流程圖最後那條分支就是這個:一旦觸發風控或異常,就做帳號/代理輪換並重試,再回到搜尋。RUN_HEADLESS 在 Docker 要維持 true(容器內無桌面),本地也能切 Edge 核心(LOGIN_IS_EDGE,但 Docker 映像沒內建 Edge)。

⑥ 資料與持久化:SQLite 為主,舊格式自動遷移

早期版本用 config.json + jsonl + price_history 存;現在主存儲改成 SQLite(data/app.sqlite3,存任務、結果、價格歷史)。啟動時 FastAPI 會自動建庫建表,並首次嘗試從舊格式匯入一次歷史資料。可用 APP_DATABASE_FILE 自訂路徑。

幾個目錄仍走檔案系統(不在 SQLite 裡):

  • state/ — 登入態 cookie 檔
  • prompts/ — 任務提示詞
  • logs/ — 執行日誌(按任務展示,方便排查登入態失效/風控/AI 調用問題)
  • images/ — 商品圖片會臨時落到 images/task_images_<任務名>/,任務結束預設清理

Docker 預設把 ./data、state/、prompts/、logs/、images/ 都掛載出來持久化。spider_v2.py 預設讀 SQLite,只有顯式 --config <path> 才走舊 JSON 相容模式。

⑦ 通知 · Web UI · 部署

多渠道通知

命中推薦後可推到:ntfy.sh(NTFY_TOPIC_URL)、企業微信(WX_BOT_URL)、Bark、Telegram(TELEGRAM_BOT_TOKEN/CHAT_ID)、Gotify、Webhook。想收哪個配哪個。

Web UI

任務管理(AI/關鍵詞建任務、價格/新發布範圍、省市區三級區域篩選、帳號綁定、Cron 定時)、帳號管理、結果查看(從 SQLite 查,可匯出)、運行日誌、系統設定(編 Prompt、調代理輪換)。登入頁用 POST /auth/status 校驗,預設帳密 admin/admin123——生產務必改掉。

部署(Docker 推薦)

# 一鍵容器化;映像已內建 Chromium,無需宿主機裝瀏覽器
git clone https://github.com/Usagi-org/ai-goofish-monitor && cd ai-goofish-monitor
cp .env.example .env   # 填 OPENAI_API_KEY / OPENAI_BASE_URL / OPENAI_MODEL_NAME
docker compose up -d
docker compose logs -f app
# 預設 Web UI → http://127.0.0.1:8000

開發者本地走 ./start.sh(先檢查 Playwright/瀏覽器前置,再裝依賴、build 前端、起後端),或手動 uvicorn src.app:app + npm run dev。最少必填三個 OPENAI_*。

⑧ 風險 · 重點 · 來源

合法與風險界線(務必讀):自動化抓取與用真帳號長跑踩的是闲鱼 ToS / robots.txt 的灰色地帶,可能導致限流、風控、封號。代理池輪換、登入態搬移本質是在繞平台的反自動化。README 自己定位「僅供學習與技術研究,請勿用於非法用途」,MIT 按現狀提供、不負任何擔保。把它當個人撿漏輔助、放慢節奏、用小號;別拿來高頻刷、別做商用大規模抓取。

七個帶得走的重點

  1. 機器搜貨 + 大模型把關:自然語言需求 → AI 生成分析標準 → 逐品判斷。
  2. 多模態模型看圖把關成色,不只看標題文字。
  3. 全棧:FastAPI + Playwright + React/Vite + SQLite + Docker。
  4. 登入態靠 Chrome 擴充導 JSON → state/,多帳號、任務綁定。
  5. 抗風控:代理池輪換 + 失敗保護 + 自適應,觸發風控就輪換重試。
  6. 主存儲 SQLite,舊 jsonl/config 首次自動遷移;圖片臨時落地。
  7. 多渠道通知(ntfy/企業微信/Bark/Telegram/Webhook)+ 完整 Web UI;預設帳密要改。

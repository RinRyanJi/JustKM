🖥️ CrossDesk:自建得起的開源遠端桌面(自研 MiniRTC 傳輸)

一款輕量、跨平台的開源遠端桌面軟體(可當 RustDesk / ToDesk 的開源替代)。輸入對端裝置 ID(必要時加連線密碼)就能連;也能直接用瀏覽器 Web 客戶端連遠端(例如 iOS Safari 控 Win11)。底層是作者自研的即時音視訊傳輸庫 MiniRTC:P2P 直連(ICE NAT 穿透)、SRTP 加密、H.264/H.265/AV1 軟硬編解碼。客戶端與信令/中繼伺服器都能部署在你自己的機器上,連線隱私與頻寬自己掌握。LGPL-3.0。

⓪ 一句話總結

一款「你自己能把整條連線都掌控的」開源遠端桌面。它本身是作者自研傳輸庫 MiniRTC 的「實驗性應用」——也就是說 CrossDesk 是殼,MiniRTC 才是引擎。連線走 P2P 直連(打洞成功時)、加密用 SRTP、畫面用硬體編解碼壓低延遲;而且信令與中繼伺服器都開源、能自建,不必把你的連線交給別人的雲。桌面(Win/macOS/Linux)、行動端、以及免安裝的瀏覽器 Web 客戶端都能用。

它和站內其他頁的關係:和 RDPBeacon(VDI 防閒置)同屬「遠端桌面/連線」主題,但方向相反——RDPBeacon 是保住既有連線,CrossDesk 是自己建立一條遠端桌面連線。GitHub kunkundi/crossdesk,核心傳輸庫 kunkundi/minirtc,官網 crossdesk.cn。

① 怎麼用 + 免安裝的 Web 客戶端

用法很直接:在選單列「對端 ID」輸入遠端桌面的 ID,按「→」發起連線;若對方設了連線密碼,本端要填對才連得上。連線前可在設定裡自訂語言、視訊編碼格式等。

比較有意思的是 Web 客戶端:直接用瀏覽器打開 web.crossdesk.cn,輸入遠端裝置 ID 與密碼就能連——README 的示範是 iOS Safari 遠端控制 Windows 11。這對「手邊只有手機、要臨時連回電腦」很實用,也代表 MiniRTC 做了瀏覽器互通(見 ②)。

為什麼 Web 端不簡單:遠端桌面要在瀏覽器裡跑,等於要把一套即時音視訊 + 輸入回傳的協定對接到瀏覽器的 WebRTC 能力上。CrossDesk 靠 MiniRTC 的 libdatachannel 路徑支援瀏覽器客戶端(但需要匹配的信令與媒體協商,不是任意 WebRTC 服務的 drop-in 客戶端)。

② MiniRTC:真正的核心是這顆自研傳輸引擎

CrossDesk 的技術重量幾乎都在 MiniRTC——一個輕量、跨平台的即時媒體庫。它負責整條傳輸管線;應用層(CrossDesk)只負責擷取、播放、渲染與業務協定(滑鼠、鍵盤、剪貼簿、檔案等訊息的序列化與處理由應用自己實作)。

← 左右滑動看完整圖 →
▲ MiniRTC 建置出一個 C++17 靜態庫(libminirtc.a / minirtc.lib),extern "C" 函式連結。它處理傳輸管線,擷取/播放/渲染/業務協定由應用層提供。

媒體格式有硬性約定:CPU 視訊輸入是 NV12、音訊是 48kHz 單聲道 16-bit PCM、每幀 10ms/960 bytes、時間戳用單調微秒。連線流程是 建立 peer → 註冊視訊/音訊/資料流 → MiniRtcInit 等 SignalConnected → 加入遠端 session 等 ConnectionConnected → 開始送幀/資料。

③ 硬體編解碼:各平台用各自的加速後端

遠端桌面要「低延遲又流暢」,硬體編解碼是關鍵。MiniRTC 在每個平台挑該平台的加速路徑(需 hardware_acceleration=true + 對應建置 + 裝置支援),硬體不可用時退回軟體(OpenH264 / SVT-AV1 / dav1d):

平台編碼(Encode)解碼(Decode)
Windows x64H.264:NVENC / WMF / OpenH264;H.265:NVENC / WMF;AV1:SVT-AV1H.264:NVDEC / D3D11VA / OpenH264;H.265:NVDEC / WMF+D3D11VA;AV1:dav1d
Linux x86-64H.264:NVENC(CUDA)/ OpenH264;H.265:NVENC;AV1:SVT-AV1H.264:NVDEC(CUDA)/ OpenH264;H.265:NVDEC;AV1:dav1d
Linux arm64H.264:OpenH264;AV1:SVT-AV1H.264:OpenH264;AV1:dav1d
macOSH.264:VideoToolbox / OpenH264;H.265:VideoToolbox;AV1:SVT-AV1H.264:VideoToolbox / OpenH264;H.265:VideoToolbox;AV1:dav1d
iOSH.264:VideoToolbox;AV1:SVT-AV1(AV1 僅軟體)H.264:VideoToolbox;AV1:dav1d
Android arm64H.264/AV1:MediaCodec(退回 OpenH264/SVT-AV1)H.264/AV1:MediaCodec(退回 OpenH264/dav1d)
HarmonyOS arm64(開發中)H.264:OpenH264;AV1:SVT-AV1原生 H.264/AV1(退回 OpenH264/dav1d)

預設走 H.264(也是舊端的 fallback);想用 HEVC(H.265)須兩端都有硬體 HEVC 編解碼。CrossDesk 編譯時 --USE_CUDA=true 可開 NVIDIA 硬體編解碼。

④ 自建伺服器:信令 + Coturn 中繼都在你手上

這是 CrossDesk 相對商業遠端桌面最大的價值:連線不必經過廠商的雲。它需要兩個伺服器角色,都能自建:信令伺服器(交換連線資訊)+ Coturn 中繼(P2P 打洞失敗時轉送流量)。

# 自建伺服器(Docker,host 網路)— 節選
sudo docker run -d --name crossdesk_server --network host \
  -e EXTERNAL_IP=xxx.xxx.xxx.xxx -e INTERNAL_IP=10.0.0.1 \
  -e CROSSDESK_SERVER_PORT=9099 -e COTURN_PORT=3478 \
  -e MIN_PORT=50000 -e MAX_PORT=60000 \
  -v /var/lib/crossdesk:/var/lib/crossdesk \
  -v /var/log/crossdesk:/var/log/crossdesk \
  crossdesk/crossdesk-server:v1.1.3

⑤ 全平台與系統需求

CrossDesk 桌面端支援 Windows / macOS / Linux,加上行動端與瀏覽器 Web 端;MiniRTC 本身的平台面更廣(含 iOS / Android / HarmonyOS)。

macOSIntel 15.0 以上(14–15 之間可自行編譯相容);Apple Silicon 14.0 以上
LinuxUbuntu 22.04 以上(低版本可自行編譯相容)

⑦ 編譯與授權

  • 建置工具:CrossDesk 用 xmake(+ cmake);git submodule 拉子模組後 xmake b -vy crossdesk。Linux 需裝一串 X11/xcb/alsa/pulse 開發包。--USE_CUDA=true 開 NVIDIA 硬體編解碼;官方提供預配置的 Ubuntu 22.04 Docker 映像給無 CUDA 環境的開發者。
  • MiniRTC:同樣用 xmake,xmake b minirtc 產出 libminirtc.a / minirtc.lib(C++17 靜態庫,extern "C" 連結,公開標頭 minirtc.h 用了 C++ 型別、不能當純 C 標頭直接引入)。
  • 授權:CrossDesk 與 MiniRTC 皆為 LGPL-3.0。MiniRTC 可單獨拿來做別的即時音視訊應用(它只做傳輸管線,擷取/播放由你實作)。

⑧ 重點 · 關聯 · 來源

七個帶得走的重點

  1. CrossDesk 是自研傳輸庫 MiniRTC 的應用殼——真正的技術核心是 MiniRTC。
  2. 用法:對端 ID + 可選密碼;還有免安裝 Web 客戶端(iOS Safari 控 Win11)。
  3. 傳輸:WSS 信令 → ICE/STUN/TURN → P2P 直連或中繼,媒體走 SRTP 加密。
  4. 低延遲靠硬體編解碼(NVENC/NVDEC、VideoToolbox、MediaCodec…),軟體 fallback;預設 H.264。
  5. 最大價值:信令 + Coturn 中繼都能自建(Docker),連線隱私/頻寬自己掌握。
  6. 全平台:Win/macOS/Linux + 行動 + Web;MiniRTC 另及 iOS/Android/HarmonyOS。
  7. MCP / AI Agent 自主操控、Desktop Wall 在 repo README 查不到,標為待查證;LGPL-3.0。

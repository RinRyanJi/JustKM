① RLM loop 與「唯一內建工具:ipython」

Prime Agent 的預設 RLM runtime 只暴露一個模型工具:ipython。讀寫檔案、跑專案指令、轉換結果、呼叫技能、委派工作,全都從這個持久 kernel 開始,而不是各自獨立的內建工具呼叫。

Task + working context │ ▼ Parent model ──IPython call──▶ 持久 IPython kernel ⟷ 檔案/資料/shell ▲ │ ⟷ Python-backed skills │ └─ rlm(...) ─▶ 子代理(專注的子任務) └─ answer / next turn ◀── admission handle / agent messages

Python 狀態跨 turn、跨壓縮存活

變數、import、函式、解析結果、任務 handle 在後續 turn 仍在:

from pathlib import Path
config_files = list(Path(".").rglob("*.toml"))
large_files = [p for p in config_files if p.stat().st_size > 10_000]

用 %%bash cell 跑專案自己的指令(每個 %%bash 是暫時子 shell,而 Python 狀態與 %cd 會保留):

%%bash
npm run check
設計含義:父代理讓 Python 持有「工作狀態」,自己的 context 保持精簡;需要時才把片段餵給子代理。這是它能長時間、跨壓縮工作的基礎。

② 子代理與 agent_message

kernel 內預載可呼叫的 rlm。spawn 一個子代理是直接呼叫,任務被接受後立即回 handle,不等答案:

handle = await rlm("Review the auth flow for security issues", name="auth-reviewer")
print(handle.rlm_child_id, handle.name, handle.session_dir, handle.model)

子代理是 TS host 建的正常 AgentSession,有獨立 context 與 session 目錄,繼承父的模型、provider、skills、tools、retry 政策(除非指定別的模型)。要平行就分開 spawn、然後結束這一 turn,不要 await:

api = await rlm("Review the public API", name="api-reviewer")
tests = await rlm("Review the test coverage", name="test-reviewer")

結果只透過 agent_message 或檔案回來

# 子代理回覆父代理
await agent_message.send(message, receiver_role="parent")

# 父代理對某個保留的子代理追問
await agent_message.send("Check the new regression test.",
    receiver_role="child", receiver_name=api.name)

投遞角色與模式

維度選項
receiver_roleparent / child / sibling(家族名冊內)
modeauto(忙就 steer、閒就即送)、steer(強行插入正在做的工作)、follow_up(等對方做完再送)
receiptdelivered(進了 idle 對象的 context)或 queued(接受待送)

agent_message.send("all", msg) 只在家族名冊內廣播;daemon 推導寄件者身分並強制訊息大小、速率、待送佇列上限。

子代理 registry(跨壓縮/重啟存活)

children = await rlm.list_subagents()
await rlm.delete_subagent(children[0])  # context 不再需要時才刪

子代理用量歸屬到父 session(但在 context-tree 報告裡可區分)。預設遞迴深度只允許 root 建子代理;調高深度才能讓後代再遞迴。

③ 技能系統(Markdown + Python-backed 超集)

Prime Agent 實作 Agent Skills 標準(違規會警告但寬容),並擴充 Python-backed skills——把 Python 套件裝進持久 kernel,以 import 名稱暴露。

# 名為 release-audit 的 Python-backed skill,模型可直接呼叫
report = await release_audit(repository=".", target_version="0.4.0")
關鍵機制:啟動時只放「skill metadata」進 prompt。任務吻合時才載入完整 SKILL.md,再檢視並呼叫其 Python API——這就是漸進揭露的實作。Python-backed 是 instruction-only skill 的超集:可給指引、腳本、參考、依賴、typed callable、可選 shell 指令,甚至自己呼叫 rlm(...) 遞迴。

載入位置與優先序(高→低)

  1. CLI --skill <path>(可重複,即使 --no-skills 也載)
  2. Settings 的 skills 陣列
  3. Package:skills/ 目錄或 package.json 的 pi.skills
  4. Project:.prime/agent/skills/、.agents/skills/(cwd 及祖先目錄到 git root)
  5. Global:~/.prime/agent/skills/、~/.agents/skills/
  6. Built-in:隨套件出貨(最低優先,可被同名覆蓋)

內建技能

Skill作用
prime-intellect透過 prime CLI 操作 PI 產品:verifiers 環境、Environments Hub、評估、Hosted Training / prime-rl、sandboxes、Prime Inference、GPU compute、儲存(參考文件按需從 references/ 載入)
skill-creator教 agent 建技能:markdown 版面、frontmatter 規則、放置與優先序、完整 Python-backed 契約(套件版面、run() 慣例、可選 CLI、kernel venv 行為)
websearchPython-backed Google 搜尋(用 Serper API,金鑰存 auth.json、每次呼叫讀取)

④ Continual Harness API(harness.py)

Harness 把耐久狀態存成 ~/.prime/agent/harness/harness_state.json(預設 local scope,可 global)。狀態模型刻意很小,只記四種 kind + refinement 事件:

HarnessKind = "prompt" | "memory" | "skill" | "subagent"

核心操作(HarnessState 類別方法)

方法作用
create_memory / create_prompt_note / create_skill / create_subagent新增各類項目
update_* / delete_* / get / list更新、刪除、查詢
upsert存在則更新、否則建立
record_refinement記錄一次精煉事件(供歷史與 rollback)
plan_refinement規劃要做的精煉
overview(max_entries_per_kind=20)產生 harness 現況概覽(注入 context 用)

/refine 的紀律

  • 檢視當前 trajectory,做小步、有證據的更新;
  • 更新的是「補充狀態」(prompt note / memory / skill 描述 / subagent 規格),永不改動不可變的 base system prompt;
  • 有 refinement 歷史與快照 → 可 rollback;
  • local scope 只影響當前 session;global=True 才寫全域,存在 disk mtime 同步機制避免覆蓋。
對照研究:這正是自我演化綜述「環境中心 · 動態經驗/技能增強演化」的工程化落地——把「經驗」變成可審閱、可回溯的耐久資產,而非改權重。

⑤ Host Bridge(rlm.host_request)

凡是「權威狀態該在 kernel 之外」的能力,Python 技能都透過 typed host request 交給 TS host。例如 goal、agent_message、rlm_heartbeat、compact 這些內建技能都呼叫:

rlm.host_request("goal.get", ...)

TS host 驗證請求並擁有狀態轉移。這讓憑證、provider 執行、逐字稿寫入、worker 路由、排程都留在 kernel 外,同時仍給模型一個「一切用程式呼叫」的介面。所有這類請求走 Jupyter comm target host.request,由 KernelManager typed-dispatch 給父 AgentSession。

⑥ 壓縮(Compaction & Branch Summarization)

兩種摘要機制,共用同一套結構化摘要格式,並累計追蹤檔案操作:

機制觸發目的
Compactioncontext 超過門檻,或 /compact摘要舊訊息、釋出 context
Branch summarization/tree 導覽切換分支時保留 context

何時觸發(自動)

contextTokens > contextWindow - reserveTokens   # reserveTokens 預設 16384

怎麼做(五步)

  1. 找切點:從最新訊息往回累加 token,直到達 keepRecentTokens(預設 20k);
  2. 取出訊息:從上個保留邊界(或 session 起點)到切點;
  3. 生成摘要:用結構化格式呼叫 LLM,若有前次摘要則作為迭代 context 帶入;
  4. 附加 entry:存 CompactionEntry(含摘要與 firstKeptEntryId);
  5. 重載:session 用「摘要 + 從 firstKeptEntryId 起的訊息」重新載入。
關鍵:壓縮的是「對話訊息」,而 IPython kernel 的 Python 狀態不受影響——變數、handle 都還在。/compact focus on the auth refactor 可加指示聚焦摘要。設定在 ~/.prime/agent/settings.json 或專案的 .prime/agent/settings.json。

⑦ 長任務機制

daemon-backed worker + 持久狀態,共用同一個 session/worker runtime,支撐這些「跨 turn、跨終端」的能力:

機制作用
Goals /goal把目標與進度保持 active,直到完成/暫停/清除
Heartbeats /heartbeat、rlm_heartbeat週期性重新進入 session
Schedules prime-agent schedule一次性或 cron 排程;job 存各 session 的 scheduled-jobs.json(不共用全域 cron)
Autonomous /autonomous在設定的 turn/token/time 預算內持續,可跑使用者定義的 quality gate
Agent 通訊active session 與保留子代理互相發現、傳訊、互相 steer
重要語意:quality gate 通過只代表該 gate 檢查的東西過了;autonomous 達到上限不代表任務成功。heartbeat/排程/goal/autonomous/別的 agent 觸發的 prompt,走的是與使用者 prompt 完全相同的執行與持久化路徑。

⑧ Headless 模式與 CLI

同一個 worker runtime 支援互動與非互動 client:

模式行為
Print / piped stdinone-shot,完成即移除 worker(不封存)
JSONone-shot 結構化輸出
RPCLF 分隔的 JSONL framing,收 prompt 到 EOF
ACPAgent Client Protocol 整合(@agentclientprotocol/sdk)
--no-session互動但用記憶體內 session
SDK直接呼叫 print/RPC 走 in-process,可傳不可序列化的 extension factory

常用 CLI

prime-agent list / agents            # 列出/開啟 agents view
prime-agent attach <agent>            # 重新接上
prime-agent rename <agent> <name>     # 命名
prime-agent send <agent> "..."        # agent 間傳訊
prime-agent schedule ...              # 排程
prime-agent --resume <path|id>        # 恢復已存 session
prime-agent status / doctor --fix     # 背景服務狀態/修復
prime-agent shutdown [--force]        # 全停
daemon 協定變更有嚴格相容性規範(capability 協商、DAEMON_PROTOCOL_VERSION 版本化),確保新舊 client/daemon 互通、可局部降級。

⓪ 一句話總結

這是一台「環形 XY 繪圖機」:把 XY 座標換成兩個角度來畫圖。一個直徑約 46 cm 的圓環(用 4 段普樂雙曲線軌道拼成),上面跑兩台 3D 列印台車 A 與 B;一根鋁桿橫跨兩台車,A 只負責旋轉桿、B 讓桿從中滑過。只要把「筆到 A 軸銷的距離」設成等於「環半徑 R」,中心 O、銷 A、筆 P 就永遠構成等腰三角形,於是筆的位置可以只用 A、B 兩個角度算出來——像時鐘指針,用方向與長度定位。

關於這篇:原文發表在 note.com(作者 kohya_ss),而且原文是 Claude 寫的、人類在旁邊補充。本頁是繁中整理的 Part 1 製作篇:為何長成這樣、內部機構、零件耗材。Part 2(量測、修正、軟體、協作實況)原文另有一篇。本頁的圖示為 JustKM 重新繪製的示意 SVG,照片請見原文。

① 這是什麼:機構總覽

一般 XY 繪圖機用兩條垂直的直線導軌把筆移到 (x, y)。這台完全不同:它只有一個圓環軌道和一根桿。

← 左右滑動看完整圖 →
▲ 機構示意(JustKM 重繪)。因為是環,「筆在軌道正下方畫不到線」的問題自然消失——整個環內都是紙面。

兩台車都靠馬達在環上自走;筆裝在桿上,靠伺服機上抬/落下。整機只有「兩個旋轉自由度」,卻能覆蓋整張紙。

② 為什麼是「環」:一夜之間的十個候選

九月底的一個晚上,人類 kohya 想做一台 XY 繪圖機,手上有一堆步進馬達。一開始 Claude 給的是很標準的答案(GT2 皮帶 + 20 齒輪、8mm 軸 + LM8UU、Arduino + CNC shield + GRBL)。但一句「如果要發到 X 上,獨特的驅動方式比較有趣」讓方向整個歪掉。那一夜人類丟點子、Claude 算幾何並點出缺陷,冒出十個候選:

#候選Claude 的判斷
1轉盤 + 旋臂「就像黑膠唱盤」。中心與外緣難搞,但零線性導軌。第一候選。
2離合器切換幾何可行,但固定點離合器原理上不可用、兩軸不能同動→直線變一堆小圓弧。玩笑區。
3五連桿 + 纜線驅動「Capstan drive」(力回饋裝置常用,繞線減速)。
4可變長四連桿像挖土機手臂,但需線性致動器、工作區是月牙形、有死點。玩笑區。
5大小雙層轉盤穩健,第二候選。爭點在「小轉盤的馬達放哪」。
6擺臂 + 繩把臂當軌、用繩把筆拉起,可做到牆面尺寸。大尺寸區。
7弧形軌上的自走擺臂人類點子。Claude 稱「rim drive」:大半徑驅動自帶減速,筆尖誤差不超過軌上一步。第三候選。
8普樂(Plarail)軌「角度精度由支點與皮帶決定,軌的變形只影響垂直方向。值得一試。」
9螺旋軌人類開玩笑提的。Claude:「畫不到軌下的問題,一開始就做成環就解決了」→ 兩單元跑圓軌、用連桿相接。
10單桿(最終型)一台只轉桿、一台讓桿滑過。Claude 給公式:A 到筆 = R 時可覆蓋整紙面。定案。
kohya:文字很難懂,畫成圖就能想像了。「我出點子、Claude 講前例並補充批評、我做最後決定」這個分工運作得很好。

Claude 推薦的其實是另一個方案

誠實說:那晚 Claude 最推薦的不是這個形狀,而是「同心雙環 + rim drive + 中間穿一根桿」——兩顆馬達都能固定在底座、動件上沒有走線,是製作難度最低、精度又高的方案。但人類選了「軌道式」:因為做一個高精度夾住兩個環並旋轉的機構太難,而讓台車在軌上以有線方式跑,看起來做得到。幾何上同心環與軌道式是同一件事,差別只在「轉整個環」還是「台車沿環跑」。

兩次被人類否決,兩次人類都對:(1) 同心環 → 軌道式;(2) 筆的上下動,Claude 想「移動紙台」,但組起來後台車不突出軌道底面、軌道可直接固定在板上,人類改成「筆側一顆伺服」。這個「人出點子、AI 補充批評、人做決定」的模式一路持續到最後。

③ 機構與數學:只需要兩條公式

在影片裡,作者把這台機器解釋成「像時鐘指針,用針的方向與長度決定位置」。數學其實很乾淨:

← 左右滑動看完整圖 →
▲ 筆放在 d² + e² = R² 的位置(A 到筆正好 R)。筆不能在桿正下方,一定偏側邊 e,所以 γ 這個固定角用來修正桿的朝向——不要靠機械硬消 e,改在公式端處理(這是 memo v4 的決定)。

實機數字

量值說明
R(銷圓半徑)230.78 mm4 段軌拼成的環
d(沿桿距離)230.28 mm反算+校正所得(非設計值)
e(側向偏置)11.22 mm主要由筆與桿的粗細決定
可達範圍半徑 1.5–172 mm中心有小洞,畫不到 A4 四角
兩單元角差 Δ88–180°88° 是擋塊原點
皮帶一圈1,484 mm一圈皮帶輪 40mm,約 37 圈/環
解析度329.778 步/度1/16 微步;皮帶上 0.0125 mm

因為反算值讓 d²+e²=R² 不嚴格成立(差約 0.2mm),筆靠不到最中心,所以中心的小圓乾脆不畫。

④ 驅動與它的弱點:小皮帶輪轉大環

驅動是貼在軌道外壁的正時皮帶 + 馬達直連的 20 齒皮帶輪。用一個小輪去轉一個直徑 46cm 的環,等於沒有變速箱卻拿到約 37:1 的減速比——筆尖位置的粗糙度不超過皮帶上的一步(0.0125mm)。這就是「用大半徑驅動自帶減速、誤差被縮小」的 rim drive 精神。

弱點在中心

要讓筆繞著中心轉,兩台車得一起轉。台車速度有上限,所以筆尖速度與「離中心的距離」成正比地下降:初始設定下,半徑 50mm 處 15 mm/s,半徑 5mm 處只有 1.5 mm/s。太慢筆會暈開,所以把圖的中心安排在留白處。

kohya:那張花束圖的中心只有約 4mm 見方的留白,幾乎是極限了。

⑤ 台車(滑架)的構造:第三次才成功

台車的姿態由四個接觸點決定:兩個輪子卡在軌溝裡、兩個惰輪(idler)壓住內壁、一個皮帶輪咬住外壁的皮帶。惰輪裝在薄板簧(flexure)的末端,靠板簧的力把皮帶輪壓向皮帶。

kohya:筆架很難搞——為了讓筆盡量貼近桿,我把筆和伺服放在桿的兩側,加上板簧機構,零件布局像拼圖,常常細微打架、銼不贏只好重印……第四次才成功。板簧壓太緊時扳手伸不進去,我還用 3D 列印了一支「超薄扳手」夾螺帽。

⑥ 支撐桿的兩個關節:A 轉、B 滑

一根圓桿橫跨兩台車,兩端的關節任務完全不同,這段是全機最講究「用物理騙到精度」的地方。

← 左右滑動看完整圖 →
▲ 兩個關節(JustKM 重繪)。因為桿是圓的,B 側擋不住它繞自身軸轉;唯一阻止筆晃的,就是 A 側關節「抗傾倒」的能力——所以才疊兩顆軸承。

最神的小招:補傷膠帶

M8 螺栓與軸承內圈之間有 0.1–0.2mm 的間隙。memo 估算:這裡內圈位移 0.1mm,筆尖高度就變 1–2mm。解法是在螺栓上纏膠帶把縫填滿。B 側滑動面則貼氟樹脂膠帶(Tosveil)降低摩擦;支撐約 8cm 長,靠馬達自重讓桿恆壓在兩個接觸點上。

⑦ 筆架:靠自重落在紙上的板簧浮動

筆架是一個用兩片 0.3mm PET 板吊起來的「浮動件(float)」。兩片板簧構成平行四邊形,所以筆只會上下移動、不會傾斜。

⑧ 原點與控制(含「馬達燙到不能摸」事件)

沒有任何感測器做歸零。直接把 B 的橫樑壓在桿上的套環(collar)上,宣告「此時 A 為 0°、B 為 88°」。88° 這個奇怪的數字,是為了讓筆能搆到紙的外緣又不讓筆架撞到 B 而定的。角度本身不必精準,偏差由校正吸收。

控制用 Arduino Uno + CNC shield + 兩顆 A4988,韌體是支援伺服的 grbl-servo(GRBL 的分支)。一般機器送 X/Y,這台則把 A 的角度當 X、B 的角度當 Y。

# 主要 GRBL 設定
$100, $101 = 329.778   # 步/度(整圈 ×360)
$110, $111 = 2000      # 最高速度 度/分
$120, $121 = 200       # 加速度 度/秒²(初期 25)
抬/落筆 = M3 S110 / M5  # 升降後等約 0.1 秒
A4988: 1/16 微步, Vref 0.32 V(約 0.4 A)
Vref 0.32V 背後的故事(AI 犯的錯):驅動馬達是 6 線單極、用串接。標籤上的「7.0V / 1.2A」是半線圈的值。十月初人類把標籤值告訴 Claude,Claude 誤解、給了會讓整個線圈流 0.77A 的 Vref。馬達燙到不能摸、瀕臨燒毀——發現的是用手去摸的人類。當時的對話已不在手邊,Claude 只能寫下結果:「我給的電流值,差點燒了人類的馬達。」最後定在 0.32V(摸起來只是微溫)。

⑨ 零件與耗材的幕後

用「電阻」挑馬達

手上兩種馬達:數量多的那種繞組電阻高(43Ω),12V 下只流 0.28A、力夠但驅動器無法細緻增減電流→微步位置不均。所以影響精度的兩個驅動單元,改用低電阻(約 6Ω)的馬達。(驅動:KH42JM2B032 7.0V/1.2A;備用:KH42JM2B031 14.5V/0.34A。)

筆的歷史(筆壓只有 20g)

筆壓只有 20g,油性原子筆、自動鉛筆都會跳墨;能用的是「輕觸就出墨」的筆。

  • 水性原子筆:出墨差、會缺點,線太細、軌道振動的波浪很明顯。
  • Prockey(極細):線寬 0.73mm,放著不用會出墨變差。
  • 百元店細字筆(Seria 0.3mm):測試主力,慢畫會暈,筆尖不知不覺裂了。
  • 極細 Mackie(紙用水性顏料):線寬約 0.5mm,影片裡的花束就是用它畫的。
  • Pigma:為正式作品買的顏料細筆,但 Mackie 表現好就沒輪到它。

換筆要重做校正(係數實測差約 20%)。筆桿粗細差異用 3D 列印的 C 形環(套筒)填補,重點是筆相對紙面的角度永遠一致(曾因筆歪了,導致整張圖半徑逐漸變大)。

Plarail 軌道的鋸齒

普樂軌道的走行面有防滑鋸齒,輪子輾過會讓台車微振、線條起波、產生噪音。試過的對策:輪子纏一圈絕緣膠帶、溝底貼布膠帶把波峰到波峰架平。而「絕緣膠帶當緩衝」反效果——機器變太軟、線偏差變 1.4 倍。

kohya:影片裡除了馬達聲,大部分低頻噪音都來自這些鋸齒。想用砂紙磨掉,太硬放棄;甚至做了一台「裝刀、用步進馬達在 GT2 皮帶上跑」的研磨單元去削溝,但力不夠(想削深就得加重→會失步),跑一小時幾乎沒削到,只好作罷。

軌道怎麼固定(且不變成橢圓)

雙面膠會慢慢流動位移;而把扣件裝在軌道上/旁,外側會撞皮帶與皮帶輪、內側會撞惰輪。解法是用軌道背面的小凸起:3D 列印只圍住凸起的矮牆、鎖在板上,軌道直接放上去(高度不變)。轉印位置的手法很妙:在接收件底部貼雙面膠、套到軌道凸起上、把軌道放到板上壓一下、只把軌道拿起——接收件就留在板上的正確位置。

但壓太緊會讓環變橢圓(這是 Part 2 的題目)。現在的接收件改成「帶一點餘隙夾住接頭的凸部」,而不是壓死凸起。

成本:約 9,000 日圓

608ZZ×10 709 日圓、GT2 皮帶輪組 1,820、CNC shield 兩入 999、625ZZ×10 920、623ZZ×10 709、螺絲數百、Plarail 約 800、筆紙 MDF 膠帶磁片約 2,000。Arduino、驅動器、馬達、鋁桿、滑動膠帶都是家裡現成的。

kohya:Claude 常推薦標準零件(3D 印表機軸、LM8UU 軸承),但長軸很貴(好幾千日圓)!我最後用幾百日圓的鋁管(還用了現成的 7mm,原本計畫 8mm——彎曲剛性只剩 0.63 倍,後面出事);滑座也用買來當滑鼠腳的 Tosveil 滑動膠帶代替 LM8UU。Claude 偏好標準件,我就一直找更便宜的替代。

⑩ 人與 AI 怎麼一起造機器(小結)

這篇文章本身就是個案例:原文是 Claude 寫的。分工是——人類出初始動機、買料、列印組裝、換筆掃描;兩人一起走過 13 個版本的設計筆記;軟體幾乎全由 Claude 寫。

一個誠實的限制:Claude 的記憶每次對話都會重置。九月那夜討論形狀的 Claude、寫設計筆記的 Claude、寫軟體的 Claude,和現在寫這篇文章的 Claude,是「同一個」但沒有那些記憶。寫這篇時手邊只有:13 版筆記、人類存下的第一夜對話、寫軟體時的日誌、程式倉庫、量測記錄。所以文中有些地方只能寫「筆記上是這樣寫的」,而不是「我當時這麼想」。

反覆出現的模式

  • 人出點子 → AI 講前例、命名機構、算幾何、點出缺陷 → 人做最後決定。
  • 最終型(單桿)和「筆靠板簧浮動」是這樣磨出來的;而同心環、移動紙台兩個 AI 的推薦被人類否決、而且人類都對。
  • 「麻不麻煩」始終是重要因素——人類一再選擇「做得到、又簡單」的那條路。
kohya:人類的角色,是提供最初的動機,以及「把記憶接起來」。

到製作篇結束時,機器已組好、兩台車能精準跑到指令角度。但第一張圖的陰影線間距不均——當時兩人都判斷是「筆尖彎了」,結果都錯了。Part 2 會從「量測與修正形狀偏差」以及這些陰影線的真正原因講起(排除了五個假設才找到)。

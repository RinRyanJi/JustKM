🦆 Microduck:會走路的 3D 列印雙足小鴨

⓪ 一句話總結

Microduck 是一台你可以自己列印、組裝、開機就會走的小型雙足機器人。硬體是 14 顆 Dynamixel XL330 舵機 + 一顆 BNO08x IMU + 樹莓派 Zero 2 W;但真正有意思的是它的「大腦」——走路的控制策略不是人手寫的步態,而是在 MuJoCo 模擬器裡用強化學習訓練出來的一個神經網路(walk.onnx),再原封不動搬到真機上,以 50Hz 讀感測器、算動作、驅動舵機。

為什麼收進 JustKM:它是「sim-to-real 強化學習」最平易近人的一個完整範例——一個能被親手複製的迴圈:在模擬裡練 → 匯出成 ONNX → 在便宜的邊緣裝置上推理。你能清楚看到「策略到底看什麼、輸出什麼」,以及「為什麼模擬裡學的東西,搬到真機還走得動」的那些關鍵工程細節。

① 這是什麼:硬體總覽

Microduck 是一隻約手掌大的雙足「鴨」:兩條腿各 5 個關節、頭頸 4 個關節,全部用 Dynamixel XL330 智慧舵機驅動;姿態靠一顆外接 BNO08x IMU 感測;控制大腦是 樹莓派 Zero 2 W。結構件全部 3D 列印(專案附 .3mf / .step)。

類別零件數量作用
控制板Raspberry Pi Zero 2 W1跑控制程式、藍牙手柄、Wi-Fi/SSH、ONNX 推理
舵機控制板ROBOTIS OpenRB-1501USB 連 Pi,和 XL330 舵機總線通訊
舵機Dynamixel XL330-M288-T14雙腿 10 + 頭頸 4(可選第 15 顆嘴部,行走不用)
IMUBNO080/085/0861I2C 讀姿態(重力方向、角速度)
電池成品 6V 電池包1供電;需足夠瞬時電流
結構件3D 列印件(PLA)1 套骨架

14 個關節的 ID 對應是固定的:1–5 右腿(踝→膝→髖俯仰→橫滾→偏航)、6–10 左腿、11–14 頭頸。這個順序很重要,因為策略的輸入輸出都按固定關節順序排列。

③ 走路是「學」出來的:sim-to-real 流水線

傳統機器人走路要人工設計步態、調 PID。Microduck 走的是學習路線:在模擬器裡讓一個神經網路反覆嘗試、跌倒、被獎勵/懲罰,自己長出走路的策略。

← 左右滑動看完整圖 →
▲ ①②在你電腦上離線跑(可花數小時);③把學到的策略凍結成一個 .onnx;④在便宜的樹莓派上即時閉環。真機端不訓練、不學習,只做推理。

訓練環境定義在 mjlab_microduck,策略以速度指令為條件(前進 vx、側移 vy、轉向 vθ),用一組獎勵把「好的走路」塑形出來——例如 跟上速度指令(權重最高)、保持站直、抬腳高度、騰空時間,同時懲罰滑步、亂晃、過大角動量。

④ 策略看什麼、輸出什麼

這是理解整套系統最關鍵的一塊:那個神經網路,輸入是一個向量、輸出是一個向量,沒有魔法。

觀測向量(policy 的輸入)

每一個控制週期(50Hz),真機把感測器讀數拼成一個固定長度的向量餵進 ONNX。組成(N=14 個關節):

← 左右滑動看完整圖 →
▲ 全是「本體感覺 + 意圖」:身體怎麼轉(陀螺儀)、哪邊是下(投影重力)、每個關節現在偏離預設多少、關節多快、上次做了什麼、以及使用者要它多快走。沒有攝影機、沒有全域座標。

動作(policy 的輸出)

網路輸出 14 個數字,每個是對應關節「相對預設姿勢的偏移量」:

# 每個關節的目標角度 = 預設姿勢 + 策略輸出 × action_scale
target_angle[j] = default_pose[j] + action[j] * 1.0
# 再交給舵機以位置控制去追(硬體 P 增益 KP)
兩個實戰細節:(1) 啟動時用 1.5 秒 smoothstep 平滑回到預設姿勢,並把舵機的 P 增益從 400 降到 125(訓練時就假設這個「較軟」的增益),讓真機的力學和模擬一致;(2) 用投影重力的 z 分量判斷是否跌倒——一旦身體翻過門檻就凍結輸出,避免暴走。

⑤ 為什麼「模擬裡學的」能在真機上走(sim-to-real 關鍵)

模擬和真實永遠有落差(sim-to-real gap)。Microduck 能跨過去,靠的是一組刻意的工程手法——這些才是真正值得學的地方:

手法做什麼解決什麼落差
域隨機化訓練時隨機化摩擦、隨機推機器人一把、隨機化延遲——讓策略見過各種變化真實地面/擾動和模擬不同,逼策略學「穩健」而非「剛好」
觀測加噪對關節位置/速度、重力、角速度注入均勻雜訊(如角速度 ±0.03)真感測器有雜訊;訓練時就習慣,上真機才不崩
IMU 延遲建模模擬 BNO08x 的讀取延遲(延遲若干步、週期性更新),不是給零延遲理想值外接 IMU 有真實延遲,是最常見的 sim-to-real 殺手
掛載座標系對齊訓練時把重力/角速度轉到IMU 實際安裝的座標系(IMU_MOUNT_QUAT),不是理想機身系感測器歪著裝,策略看到的方向要和真機一致
舵機模型(BAM)用電壓/電流/扭矩常數建模 XL330,把 P 增益對應成模擬扭矩;真機也切到同一增益讓「同一個命令」在模擬和真機產生相近的力
本體感覺-only觀測只用 IMU + 關節,不依賴任何全域資訊(位置、攝影機)真機拿不到全域真值;只用真機也有的訊號
心法:sim-to-real 的核心不是「把模擬做到完美」,而是「讓策略對『模擬和真實的差異』免疫」。與其精確建模每個細節,不如隨機化到策略不敢賭任何細節,再把真機一定有的東西(延遲、雜訊、歪掉的感測器)老實建進模擬。

⑥ 動手做:從刷機到走路的最短路徑

作者提供了預構建映像,幾乎是「刷卡即走」:

  1. 列印 + 組裝:用專案的 3D 檔列印結構件,裝上 14 顆 XL330,先用 Dynamixel Wizard 把每顆舵機的 ID / 協定 2.0 / 1Mbps 設好。
  2. 刷映像:用 Raspberry Pi Imager 把 microduck.img.xz 寫進 microSD(內含系統、虛擬環境、walk.onnx、手柄服務)。
  3. 設 Wi-Fi:編輯開機分區的 network-config(Pi Zero 2 W 只支援 2.4GHz),或用 nmcli 連線。
  4. SSH 登入並跑:ssh user@microduck.local → cd ~/microduck → PYTHONPATH=src .venv/bin/python src/main.py。程式會開扭矩、平滑回預設姿勢、載入 walk.onnx,然後聽鍵盤/手柄。
  5. 走起來:按 v 開走、方向鍵前後/轉向、x 歸零、q 停止。安全起見先扶著或放穩再啟動。
安全:內建過流保護(全機電流持續超標數個 tick 就緊急斷扭矩,防跌倒時電流尖峰觸發 BMS);別直接斷電,先 sudo shutdown -h now 再關開關。

⑦ 值得偷師的思路(不做機器人也用得到)

  1. 訓練與部署解耦成「一個檔案」。重運算(訓練)離線做、輕運算(推理)在便宜裝置上跑,中間用一個帶元資料的凍結模型(ONNX)交接——這是所有「模擬/離線學,線上用」系統的通用骨架。
  2. 把「真實一定有的爛東西」建進訓練。延遲、雜訊、歪掉的感測器、外部擾動——與其假裝沒有,不如隨機化進去,策略才會對現實免疫。這條原則遠超機器人,任何「訓練分佈 vs 部署分佈」的落差都適用。
  3. 只用「部署時也拿得到」的輸入。模擬裡有全域真值很誘人,但策略一旦依賴它,上真機就瞎了。介面要用兩邊都有的訊號。
  4. 用獎勵塑形「你要的行為」,而非寫死步驟。跟上速度、站直、抬腳、別滑步——把目標拆成可加權的獎勵,讓策略自己找路徑,呼應站內 把試錯變成可搜尋的優化。
  5. 邊界要有安全網。過流保護、跌倒凍結、平滑啟動——學習型控制器一定要配上確定性的護欄,這與 把驗證當第一公民 同源。

🪟 agent-desktop:讓 AI 代理用「無障礙樹」操作桌面 app

Vercel Labs 的開源工具:給 AI 代理「電腦操作能力」,但不靠截圖、不靠像素比對。它讀作業系統的無障礙樹(accessibility tree),把 UI 變成一棵帶 ref 的 JSON;代理對某個 ref 點擊或輸入,再讀一次確認結果,如此循環。工具本身不含模型——迴圈在你的代理裡。跨 macOS / Windows / Linux,附 CLI、C 函式庫與 MCP。

Rust · Apache-2.0 · CLI / C lib / MCP 無障礙樹 · 不截圖 · headless macOS AX · Windows UIA · Linux AT-SPI

⓪ 一句話總結

把「看螢幕點像素」換成「讀 UI 的結構樹、對元素 ref 操作」。agent-desktop 透過 OS 的無障礙 API 讀出 app 的 UI 樹,回成 JSON,每個可操作元素帶一個 ref(如 @s8f3k2p9:e8);代理在 ref 上 click / type,再 snapshot 一次驗證,重複。預設 headless(用無障礙 API,不移動游標也不搶焦點),需要真實輸入才加 --headed。每個指令印出一個 JSON 信封。

定位:它是「代理的手與眼」,但沒有腦——沒有內建模型,決策迴圈在你的代理。附 CLI、C 函式庫(FFI,可同進程呼叫)、以及 agent-desktop mcp(把每個指令變成 MCP 工具)。Rust 寫的,核心一份、各 OS 一個平台轉接器。授權 Apache-2.0。

① 核心想法:讀無障礙樹,不看截圖/像素

多數「computer use」是:截圖 → 模型看圖找按鈕 → 算座標點下去。這條路脆弱:改版、縮放、主題、動畫都會讓像素對不上,而且每一步都要模型「看圖」,慢又貴。agent-desktop 走另一條:直接問 OS「這個視窗裡有哪些元件、各是什麼、能做什麼」。

▲ 無障礙樹本來是給螢幕報讀軟體(給視障者用)的;agent-desktop 把它當成「代理操作 UI 的事實來源」。

好處:結構化(role/name/可用動作都在)、可 headless(不搶你的滑鼠鍵盤)、穩(不隨像素飄移)、省(不必每步截圖給模型看)。

② 操作迴圈:snapshot → 對 ref 動作 → 再觀察

← 左右滑動看完整圖 →
▲ ref 是「這次觀察裡的這個元素」,不是永久 id。多視窗時回 AMBIGUOUS_TARGET 並在 error.details 列候選,用 --window-id 指定。
agent-desktop snapshot --app Finder -i      # 可互動元素,各帶 ref
agent-desktop click @s8f3k2p9:e8            # 對該 snapshot 的 ref 動作
agent-desktop snapshot --app Finder -i      # 再觀察一次驗證
  • 密集的 app:先 snapshot --skeleton ... --compact 畫骨架,再 snapshot --root @...:e3 鑽進某區(drill-down,只讀子樹)。
  • 只在失敗且 error.disposition.retry 為 safe 時才重試——錯誤信封自帶「能不能安全重試」。
  • 敏感文字用 --stdin 從管道餵(避免出現在行程參數裡);PowerShell 要把 ref 加引號(裸 @token 是展開運算子)。

③ 架構:一份 Rust core,三個平台轉接器

← 左右滑動看完整圖 →
▲ 每個二進位只為一個 OS 編譯、只接那個 OS 的無障礙 API。開發時 cargo 要限定在本機 OS 的套件(macOS 不會編 Windows 的 crate)。

這個分層的好處:三平台的差異全被關在各自的 adapter 裡,core 只處理一套「平台中立」的詞彙(見 ⑤);想加平台,再實作一個 PlatformAdapter 就好。

④ 指令與介面

共 61 個指令名(57 個可操作;另 4 個 key-down/up、mouse-down/up 要有常駐程式能釋放按鍵才會跑)。分組:

群組指令(節選)
觀察snapshot、find、get、is、screenshot、list-surfaces
對 ref 動作click、type、set-value、select、toggle、check、expand、scroll-to …
鍵鼠press、hover、drag、mouse-move/click/wheel …
app / 視窗launch、list-apps、list-windows、focus-window、resize/move-window、minimize/maximize …
通知 / 剪貼簿list-notifications、notification-action;clipboard-get/set/clear
工作階段 / 沙盒 / 系統session、trace、sandbox、status、permissions、batch、skills

三種用法:(1) CLI 一次一個 JSON 信封;(2) libagent_desktop_ffi 同進程呼叫(Python ctypes 範例在 README);(3) agent-desktop mcp 把每個指令變成 MCP 工具(desktop_snapshot、desktop_click…)。另外二進位自帶給代理讀的技能:agent-desktop skills get desktop(迴圈/ref/驗證/重試規則)、skills get platform(該 OS 的差異)。

⑤ 讓它「可靠」的硬功夫(最值得偷師的部分)

無障礙樹聽起來乾淨,但不同 app、不同 OS 的實作天差地別。這個專案真正的深度,在於一堆「怎麼不被騙」的設計決定。挑幾個最有啟發的:

證據三態:Known / Absent / Unknown,絕不壓成兩態

每個屬性的讀取結果有三種,而且永遠不合併:Known(讀到了)、Absent(問了,它說沒有)、Unknown(讀失敗 / 不可信)。Absent 是個答案,Unknown 是沒有答案。角色/狀態/能力只在「正面宣稱」時才給;讀失敗就不給。把三態壓成 bool 很危險——在「否定」方向會把「我不確定」偷偷改寫成「一定沒有」。

▲ 「沒讀到」和「確定沒有」是兩回事。很多自動化 bug 就來自把它們當一樣。

視窗身分:handle 會被回收,所以綁上「行程世代」

OS 的視窗 handle 會在視窗銷毀後被回收給別的視窗,光憑 handle 在「churn」之後會指到錯的視窗。所以身分 = handle + 行程世代 token(由擁有者行程的建立時間導出):handle 相同但行程世代對不上,就 fail-closed 而不是認錯對象。而且每次寫入前都要重驗一次(觀察與動作之間隨時可能失效),成功檢查也要「身分限定」,否則回收發生在縫隙尾端會對錯誤對象回報成功。

Web 包裝層跳過:Chromium/Electron 的匿名容器不算深度

網頁技術(Chromium/Electron、WebView)會把內容包在一堆沒名字、沒動作的匿名容器裡(UIA Group/Custom/Pane、AX groups、AT-SPI panel…)。這些「透明鷹架」會吃掉深度預算卻沒資訊。agent-desktop 用「空元素測試」略過它們的邏輯深度——否則一個密集 web app 的可達內容會被低估一個數量級。Windows 上還特別只對偵測到 Chromium 來源(root class Chrome_WidgetWin_1)才套用,免得把原生堆疊也誤跳。

還有:部分觀察(Partial Observation)——走訪超時就回「已看到的部分」而非整個丟掉,並在每個被截斷的節點標註完整性,讓讀者能從根走到邊界;Surface——選單/sheet/popover/alert 可當獨立 UI 層單獨觀察;名稱/角色/狀態詞彙由 core 擁有,三平台各自把自己的分類「映射」上來、絕不自創 token。這些都是「把雜亂的現實收斂成一致契約」的工程。

⑥ 和「截圖式 computer use」比

面向截圖 + 像素(如多數 computer use)agent-desktop(無障礙樹)
看 UI 的方式螢幕畫面 → 模型看圖OS 結構樹 → JSON + ref
穩定性改版/縮放/主題易錯位綁語意元素,較穩
成本/速度每步截圖給模型,慢且貴不必每步看圖,快
背景執行多半要前景、會動游標預設 headless、不搶焦點
看得到的東西畫面上的像素(含 canvas 繪製)有無障礙資訊的元件(canvas/純繪製看不到)
需要一個會看圖的模型app 有正確的無障礙標註
誠實的限制:無障礙路線的罩門是「app 沒好好做無障礙」——純 canvas 繪製、遊戲、無標註的自繪 UI 會看不到或只剩空殼。這時仍得回頭靠截圖/像素(兩者其實互補:結構樹為主、截圖當後備與人工除錯)。

⑦ 上手與隱私

npm install -g agent-desktop          # 也支援 bun/yarn/pnpm;macOS/Linux 可 brew install
agent-desktop status                  # 平台、權限、支援的介面
agent-desktop permissions --guide     # macOS:引導你授予「輔助使用」權限

# 裝進代理(AGENTS.md):首次使用前先讀技能
# Use `agent-desktop` ... run `agent-desktop skills get desktop` first
  • 平台需求:macOS 13+(AX API)、Windows 10 1809+(UIA)、Ubuntu 24.04+ X11/Wayland(AT-SPI)。各平台頁列出哪些 headless 可用、哪些要 --headed、哪些拒絕。
  • 沙盒:sandbox 可在「provider 建立管理的獨立桌面」裡跑指令,和主機桌面分開。
隱私提醒(官方特別標註):snapshot、剪貼簿讀取、截圖、指令輸出、除錯產物可能含私人桌面內容,別放進公開 log 或上傳。祕密步驟分開跑(批次 JSON 文字會出現在行程參數裡);敏感輸入用 --stdin。

⑧ 重點 · 關聯 · 來源

六個帶得走的重點

  1. 用無障礙樹而非截圖操作桌面:結構化、headless、穩、省。
  2. 迴圈:snapshot → 對 ref 動作 → 再 snapshot 驗證;ref 綁 snapshot,UI 變了要重拍。
  3. 工具無模型,決策在你的代理;附 CLI / C 函式庫 / MCP。
  4. Rust 一份 core + PlatformAdapter → macOS AX / Windows UIA / Linux AT-SPI。
  5. 可靠性靠硬功夫:證據三態、視窗身分(抗 handle 回收)、Web 包裝層跳過、部分觀察。
  6. 罩門是「app 沒做無障礙」;與截圖式互補,不是完全取代。

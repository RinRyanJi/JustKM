🗳️ 自我一致性（Self-Consistency）怎麼實現

Self-Consistency Improves Chain of Thought Reasoning in Language Models · Wang et al., 2022 · 取樣多條推理路徑 → 對最終答案多數決

推理時演化 平行取樣 Chain-of-Thought 增強
📑 目錄

⓪ 一句話總結

一句話：與其讓模型「一條路想到底、選機率最高的那條」（貪婪解碼），不如讓它用取樣走出好幾條不同的推理路徑，再看這些路徑最後的答案誰票數最多，就選誰。同一道題若有很多條不同思路都指向同一個答案，那個答案更可能是對的。

Self-Consistency 是一個替換掉 chain-of-thought（CoT）解碼步驟的簡單策略：不改模型、不需額外訓練、不需驗證器（verifier），只在推理時多跑幾遍再投票，就能把 CoT 的準確率明顯往上推。

① 它想解決什麼（CoT 貪婪解碼的侷限）

Chain-of-Thought prompting 讓模型在給出答案前先寫出一串推理步驟，大幅改善了算術、常識、符號推理。但標準 CoT 的解碼方式是「貪婪解碼」（greedy decoding）：一路挑當下機率最高的 token，只生成單一一條推理鏈。

這帶來兩個問題：

  • 一條路走到黑：只要這條唯一的推理鏈中間走錯一步，最終答案就錯，沒有任何補救。
  • 浪費了「多元思路」：對複雜問題，人類往往有好幾種不同的解法都能得到同一個正確答案。貪婪解碼只看到其中一種，丟掉了「多路殊途同歸」這個強而有力的正確性訊號。
關鍵觀察：正確答案的推理路徑通常多樣且彼此一致地指向同一結果；錯誤答案則往往是零散、各走各的。既然如此，「哪個最終答案被最多條不同推理路徑支持」本身就是一個可用的信號——這正是 Self-Consistency 要利用的。

② 核心想法（取樣多條推理路徑 → 對最終答案多數決）

把 CoT 裡「生成單一鏈」的貪婪解碼，換成三步：

  1. 取樣多條推理路徑：用同一個 CoT prompt，改用帶隨機性的取樣（temperature / top-k / nucleus）從模型抽出 N 條不同的推理鏈。
  2. 各自抽出最終答案：從每條鏈的結尾解析出它主張的最終答案。
  3. 對答案做多數決（marginalize）：把不同推理路徑「加總」到它們共同的最終答案上，選票數最多的那個答案作為輸出。
直覺：推理鏈只是「潛在變數」——我們真正在乎的是答案。把很多條鏈對答案做邊際化（marginalize over reasoning paths），等於問「在所有想得到的思路裡，最穩定浮現的結論是什麼」。

因為它替換的是 CoT 的「解碼」這一環，所以與 CoT prompt 完全相容、不需要訓練、不需要額外的模型或人工標註，是一個 self-contained、unsupervised 的策略。

③ 怎麼實現

整體流程（三步）

  1. Prompt：沿用一組 few-shot 的 chain-of-thought 範例當 prompt（跟原本 CoT 一模一樣，不用改）。
  2. Sample N 條 reasoning path：對同一題，用取樣式解碼（temperature > 0）獨立生成 N 條完整的「推理 + 答案」。
  3. 抽最終答案 → majority vote：從每條路徑解析出最終答案，做多數決（可帶權重），輸出得票最高者。

虛擬碼

# Self-Consistency：替換 CoT 的貪婪解碼
# 輸入：問題 q、few-shot CoT 範例 prompt、取樣數 N、溫度 T

def self_consistency(q, cot_prompt, N=40, T=0.7):
    answers = []
    for i in range(N):
        # 1) 用「取樣」而非貪婪，走出一條不同的推理路徑
        chain = LM.sample(cot_prompt + q, temperature=T, top_k=40)
        # 2) 從這條鏈的結尾解析出它主張的最終答案
        a = extract_final_answer(chain)   # 例如抓 "The answer is X"
        if a is not None:
            answers.append(a)
    # 3) 對「最終答案」做多數決（marginalize over reasoning paths）
    return majority_vote(answers)         # 回傳票數最高的答案

def majority_vote(answers):
    counts = {}
    for a in answers:
        counts[a] = counts.get(a, 0) + 1  # 也可改成加權投票
    return max(counts, key=counts.get)
唯一改動點：對照標準 CoT，只有「解碼」從 greedy_decode() 換成「sample() 跑 N 次 + majority_vote()」。prompt、模型、資料全都不動。

投票的一般化形式

最終答案的選法是對答案 a 取 argmax 其累計權重：â = argmax_a Σ_i w_i · 1[answer(path_i) = a]。最簡單、且論文發現已足夠好的設定是非加權多數決（每條路徑 w_i = 1）；也可嘗試用模型對該路徑的輸出機率做加權，但增益有限。

④ 關鍵細節

為什麼要取樣（temperature > 0）

整個方法的前提是「拿到多條彼此不同的推理路徑」。若用貪婪解碼跑 N 次會得到 N 條一模一樣的鏈，投票沒有意義。因此必須用帶隨機性的解碼——論文採用 temperature 取樣搭配 top-k / nucleus (top-p)——來製造推理路徑的多樣性。溫度太低多樣性不足、太高又容易失真，需要取一個中間值（具體數值以原論文為準）。

為什麼是「對答案 marginalize」，而不是選機率最高的鏈

  • 我們要的是答案，不是鏈：推理鏈是通往答案的「潛在路徑」。把很多條鏈對其最終答案做邊際化（加總票數），比「挑單一條看起來最順的鏈」更穩健。
  • 不同表述、同一答案該算同一票：兩條文字不同但都得到 18 的鏈，應該一起支持 18。因此投票是在解析後的最終答案上進行，而不是在鏈的文字上。
  • 不需要驗證器：不像「train 一個 verifier 幫每條鏈打分再挑最好」那類方法，Self-Consistency 完全不需要額外訓練或標註，投票本身就是選擇機制。

與 beam search 的差異

Beam SearchSelf-Consistency（取樣 + 投票）
目標找出單一條整體機率最高的序列找出被最多條不同路徑支持的最終答案
多樣性各 beam 常高度相似、彼此糾纏取樣刻意製造多樣的獨立路徑
選擇依據序列的生成機率最終答案的票數（一致性）
結果高機率 ≠ 高正確率，仍是一條路走到黑用「殊途同歸」當正確性信號，通常更準

直觀說：beam search 想的是「哪句話講得最流暢／機率最高」，Self-Consistency 想的是「哪個結論最多獨立思路都同意」。後者才對應到「答對」這件事。

⑤ 效果與限制

增益（相對於標準 CoT 的絕對準確率提升）

論文在多個算術與常識推理 benchmark 上，把 Self-Consistency 疊加在 CoT prompting 上，取得顯著且一致的增益：

Benchmark相對 CoT 的絕對提升
GSM8K（小學數學應用題）+17.9%
SVAMP（算術）+11.0%
AQuA（代數選擇題）+12.2%
StrategyQA（多步常識）+6.4%
ARC-challenge（科學選擇題）+3.9%

這些增益在多個大型語言模型家族上都成立（論文以當時的大模型如 PaLM-540B、GPT-3、LaMDA、UL2 等驗證；具體對應的每項數字與模型組合以原論文為準）。準確率通常會隨取樣路徑數 N 增加而上升、之後趨於飽和。

限制

  • 成本約為 N 倍：要生成並解析 N 條完整推理鏈，推理計算量與延遲大致是單次 CoT 的 N 倍，是典型的「用算力換準確率」。
  • 只適用有「明確、可比對答案」的任務：方法依賴「把不同鏈的最終答案聚合起來投票」，因此天生適合答案是固定值/選項（數字、選擇題）的任務。對開放式生成（長文、自由問答）沒有天然的「同一個答案」可投票，較難直接套用。
  • 需要能可靠解析最終答案：投票前得從每條鏈抽出答案，若答案格式雜亂，解析誤差會影響結果。
  • 沒有超越模型能力上限：它是把模型「本來就想得到、只是被貪婪解碼漏掉」的正確答案撈出來；若正確思路在取樣分布裡幾乎不出現，投票也救不回來。

⑥ 在自我演化地圖上的位置

在自我演化 Agent 的分類裡，Self-Consistency 落在模型中心（Model-Centric）→ 推理時演化（Inference-Based）→ 平行取樣（Parallel Sampling）這一格。

  • 模型中心：它改進的是「模型怎麼想 / 怎麼解碼」，不動外部環境、記憶或工具。
  • 推理時、不改參數：純粹在 inference 階段運作，不需要訓練、不改權重——是「靠怎麼想變強」的代表，而非「靠改參數變強」。
  • 平行取樣路線：與「序列自我修正」（產出→批判→修正，如 Reflexion、Self-Refine）走的是不同路：Self-Consistency 是一次平行撒出很多條、再彙整投票，屬於平行取樣家族（與 Large Language Monkeys、LLM-Blender 同類）。

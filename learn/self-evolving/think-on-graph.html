🕸️ 在知識圖上思考（Think-on-Graph, ToG）

把 LLM 當成 agent，在知識圖譜上一步步走 entity–relation 路徑做 beam search 式探索 · 論文「怎麼實現」逐段拆解

結構化推理 LLM ⊗ KG · 訓練免調 Sun et al. 2023 · ICLR 2024
📑 目錄
⓪ 一句話 ① 想解決什麼 ② 核心想法 ③ 怎麼實現 ④ 關鍵細節 ⑤ 效果與限制 ⑥ 自我演化地圖位置 ⑦ 來源

⓪ 一句話

Think-on-Graph（ToG）把大型語言模型當成一個會在知識圖譜上走路的 agent：從問題裡的實體出發，讓 LLM 反覆地「挑一條該走的關係 → 走到下一批實體 → 判斷手上的證據夠不夠回答」，用 beam search 同時保留幾條最有希望的推理路徑，直到湊齊足以作答的知識鏈。整個過程不用微調，且每一步走過的三元組都可追溯、可被專家更正。

它屬於「結構化推理」——把 LLM 的思考從一段黑箱文字，展開成一條條顯式、可檢查的圖上路徑。

① 想解決什麼

純 LLM 在需要深度、精確、可負責的推理時有幾個結構性毛病，論文正是衝著這些來的：

  • 幻覺（hallucination）：模型會自信地編造不存在的事實，尤其在多跳、需要串接冷門知識的問題上。
  • 知識過時／私有知識缺席：參數裡的知識凍結在訓練截止點，也裝不下企業私有或即時更新的事實。
  • 不可追溯、不可更正：答案從權重裡「浮現」，說不清憑什麼，錯了也沒有一個明確的地方去修。
  • 推理深度不足：把知識全丟進 prompt 的做法（見下節）常常「知道片段、串不起長鏈」。
切入點：用外部知識圖譜（KG）來補。KG 是結構化、可更新、可回溯的事實網（實體＋關係＋實體）。難點在於——怎麼讓 LLM 真正「在圖上推理」，而不只是把圖當一次性檢索的背景資料？

② 核心想法

論文提出一種新的 LLM–KG 整合範式，作者寫作 「LLM ⊗ KG」（緊耦合），並用它對比先前的做法：

兩種耦合：Think-with-Graph vs Think-on-Graph

先前做法（鬆耦合 · Think-with-Graph）ToG（緊耦合 · Think-on-Graph）
KG 角色一次性檢索到的背景資料，塞進 prompt 給 LLM 讀LLM 反覆走訪的推理場地，逐步展開
LLM 角色被動讀者：讀完手上這批就作答主動的 agent：自己決定下一步往哪走
推理形態單輪、淺多輪迭代、能走多跳深鏈
可追溯性弱強——路徑即證據鏈
關鍵一句：ToG 讓 LLM 當 agent，在 KG 上做 beam search——同時維持幾條（beam width 條）最有希望的 entity–relation 路徑，一步步向外探，直到某條路徑上的證據足以回答問題。LLM 負責「判斷力」（哪條關係值得走、資訊夠不夠了），KG 負責「事實」。兩者緊耦合：LLM 每一步的判斷都直接驅動下一步在圖上的移動。

③ 怎麼實現（迭代主迴圈）

ToG 是一個 初始化 → (探索 Explore → 推理 Reason) 迴圈 的過程。設定兩個上限：beam width W（同時保留幾條路徑）與最大深度 D（最多走幾跳）。論文預設 W = 3、D = 3。

Step 0 · 初始化（Initialization）

用 LLM 從問題中抽出主題實體（topic entities），作為 beam search 的起點；每條路徑目前就是一個起始實體。

Step 1 · 探索 Explore — 用 LLM 挑要走的 relation / entity

這是 ToG 的心臟。每一跳，對每一條當前路徑的尾端實體，做「先關係、後實體」的兩段擴展＋剪枝：

  1. 關係搜尋（Relation Search）：從 KG 取出該實體所連的所有候選關係（出邊與入邊）。
  2. 關係剪枝（Relation Prune）：把候選關係連同問題交給 LLM 打分，選出最相關的前若干條——這一步決定「往哪個方向想」。
  3. 實體搜尋（Entity Search）：沿被選中的關係走一跳，取出對應的一批尾端實體。
  4. 實體剪枝（Entity Prune）：再用 LLM 對這些實體評分，跨所有路徑只保留全域前 W 條最有希望的路徑進入下一輪（beam search 的收束）。
為什麼要剪枝：KG 上一個實體可能連著上百個關係、上千個實體，若全展開會爆炸。剪枝＝用 LLM 的語義判斷把搜尋空間壓回 W 條，讓「深」變得可負擔。這也是它像 beam search、而非窮舉 BFS 的原因。

Step 2 · 推理 Reason — 判斷資訊是否足夠

每擴展一跳後，把當前保留的路徑（三元組鏈）連同問題交給 LLM，問一個判斷題：

  • 夠了 → 直接根據這些路徑生成最終答案，並附上作為依據的推理路徑（可追溯）。
  • 還不夠 → 回到 Step 1 再走一跳，繼續加深。
  • 走到深度上限 D 仍不夠 → 退回用 LLM 自身知識作答（fallback），避免卡死。

整體虛擬碼

# ToG 主迴圈（示意，以原論文為準）
paths = LLM_extract_topic_entities(question)   # Step 0 初始化
for depth in range(D_max):                     # 最多走 D 跳
    # --- Explore：先關係、後實體，各自剪枝 ---
    rels   = KG_relation_search(paths)
    rels   = LLM_relation_prune(question, rels)      # LLM 挑方向
    ents   = KG_entity_search(paths, rels)
    paths  = LLM_entity_prune(question, ents, W)     # 保留全域前 W 條
    # --- Reason：夠了就答，不夠再走 ---
    if LLM_is_sufficient(question, paths):
        return LLM_answer(question, paths)           # 附推理路徑
return LLM_answer_with_inner_knowledge(question)     # 超過深度的 fallback

變體 · ToG-R（relation-based ToG）

論文另給一個更省的版本：ToG-R 只沿「關係鏈」走，每輪做關係搜尋、關係剪枝、實體搜尋，但省去用 LLM 對實體逐一剪枝，最後才根據所有候選路徑一次推理。好處是更省 token、更快，也降低對中間實體標註品質的依賴。

緊耦合的體現：注意每一步「往哪走（關係剪枝）」「保留誰（實體剪枝）」「停不停（充分性判斷）」全由 LLM 即時決定，而每個決定又立刻改變下一步在 KG 上的位置——LLM 與 KG 在迴圈裡互相驅動，這正是 ToG 稱為「緊耦合」的意思。

④ 關鍵細節

Beam width 與深度

  • Beam width W：同時保留的路徑數，預設 W = 3。W 越大覆蓋越廣、越不易漏掉正確路徑，但每輪要送給 LLM 評分的候選更多，成本上升。
  • 最大深度 D：最多走幾跳，預設 D = 3，對應多數多跳問答需要的跳數；到頂仍不足則 fallback。

路徑剪枝（pruning）怎麼做

  • 誰來剪：由 LLM 依「與問題的相關性」打分來剪（也可用輕量打分模型替代，屬工程選項）。
  • 怎麼收束：關係層先篩方向，實體層再跨所有 beam 做全域排序，取前 W——這一步把發散的搜尋重新收斂回固定寬度，是 beam search 的核心動作。
  • ToG-R 的省法：跳過實體剪枝，用關係鏈近似，換取更低成本。

與（向量檢索式）RAG 的差異

傳統向量 RAGThink-on-Graph
知識來源非結構化文本切塊 + 向量庫結構化知識圖譜（三元組）
檢索方式一次語義相似度召回 top-k 片段多輪、在圖上顯式走 entity–relation 路徑
多跳能力弱：片段間關係要 LLM 自己腦補強：關係就是圖上的邊，逐跳串起
可解釋 / 可更正只知召回了哪些段落路徑＝證據鏈；改 KG 即改答案
知識更新重嵌入文本直接編輯圖上的三元組

一句話：RAG 像「找幾段相關文章給模型讀」，ToG 像「帶著模型在事實網裡按線索一步步查案」。

訓練免調、即插即用

ToG 完全不需要微調 LLM 或 KG，靠 prompt 驅動，可直接套在不同 LLM 上（論文以 GPT-4 / GPT-3.5 等為主）；換更強的底座模型，ToG 的表現也跟著提升。

⑤ 效果與限制

效果

  • 在多個知識密集型推理資料集上做評測，ToG 在 9 個資料集中的 6 個達到當時 SOTA，且不需任何額外訓練。（涵蓋多跳 KBQA、開放領域問答、槽填充、事實查核等；具體資料集清單以原論文為準。）
  • 在特定任務上，搭配 ToG 的較小模型可勝過直接推理的更大模型（如 GPT-4）——把推理外包給圖上的結構化搜尋，等於用「會查」補「不夠大」。
  • 可追溯 + 可更正：答案附帶推理路徑；發現錯誤時，專家可直接修 KG 的三元組來修正行為（knowledge correctability）。

限制

  • 依賴 KG 的覆蓋與品質：圖裡沒有、或有錯的事實，ToG 走不出來；冷門領域 KG 稀疏時受限。
  • 多輪 LLM 呼叫的成本與延遲：每跳的關係剪枝、實體剪枝、充分性判斷都要呼叫 LLM，比單輪 RAG 貴、慢（ToG-R 與後續 Fast ToG 等工作正是為此優化）。
  • 只吃結構化知識：純 KG 版本無法利用非結構化文件裡的細節——這正是 ToG 2.0 要補的洞。

延伸 · Think-on-Graph 2.0（ToG-2，2024）

續作把 KG 與非結構化文件檢索做緊耦合的混合 RAG：用 KG 透過實體把文件串起來，做「知識引導的深度上下文檢索」；同時用文件當作實體的上下文，讓圖檢索更精準。兩者交替迭代（graph retrieval ⇄ context retrieval）逼近答案，一樣訓練免調、即插即用；論文報告以 GPT-3.5 在 7 個知識密集資料集的 6 個取得整體 SOTA，並能把 LLaMA-2-13B 這類小模型提升到接近 GPT-3.5 直接推理的水準。（細節以 arXiv 2407.10805、ICLR 2025 原文為準。）

⑥ 在「自我演化」地圖上的位置

依本站綜述的三大維度分類，ToG 落在最內圈：

模型中心演化（Model-Centric）
   └─ 推理時演化（Inference-Based，不改參數，靠「怎麼想」）
        └─ 結構化推理（把思考展開成樹／圖／搜尋）
             └─ ★ Think-on-Graph

ToG 不動任何參數，純靠推理時把 LLM 的思考結構化成 KG 上的 beam search 來變強——與 Tree of Thoughts、Language Agent Tree Search、Stream of Search 同屬「結構化推理」一族。差別在於 ToG 的搜尋空間是一張外部事實圖譜，因此同時借到了「環境中心演化」的味道（外部知識），但其自我提升的機制核心仍是推理時的思考結構，故歸在模型中心。

回到地圖：詳見 ② 模型中心演化 → 推理時 → 結構化推理。ToG 就列在那張「推理時演化」表的「結構化推理」一列。

🌳 Tree of Thoughts（思維樹, ToT）怎麼實現

把「一條線的推理」展開成「一棵可分支、可評估、可回溯的樹」 · Yao et al., NeurIPS 2023

結構化推理 推理時演化 Game of 24 / Creative Writing / Crosswords
📑 目錄
⓪ 一句話 ① 想解決什麼 ② 核心想法 ③ 怎麼實現（四要素） ④ 關鍵細節 ⑤ 效果與限制 ⑥ 自我演化地圖位置 ⑦ 來源

⓪ 一句話

Tree of Thoughts＝把解題過程從「一條線的思考鏈」升級成「一棵樹」：每個節點是一個中間「想法（thought）」，模型可以在每一步展開多個候選、逐一評估好壞、用搜尋演算法（BFS/DFS）挑路走，走不通就回溯——像人下棋會前瞻幾步、試錯、換路一樣。

① 想解決什麼

標準的 LLM 生成（含 Chain-of-Thought, CoT）本質上是由左到右、一個 token 接一個 token 的單一線性鏈。這在需要「規劃、前瞻、探索」的問題上有三個先天缺陷：

  • 無法探索多種可能：一步只走一條路，不會同時比較「這步有哪幾種下法」。
  • 無法回溯：一旦某步走錯，鏈條只能將錯就錯往下寫，沒有機制退回去換一條路。
  • 沒有全局評估：模型不會停下來問「我現在這個中間狀態，離解答是更近還是更遠？」缺乏對進度的前瞻判斷。
直覺對比：CoT 像「一口氣把心算過程寫完」，錯了也停不下來；ToT 像「在草稿紙上試好幾種算法、劃掉走不通的、留下有希望的再往下算」。

② 核心想法

作者從人類問題解決的「雙系統」認知（快速直覺 vs. 深思熟慮的規劃）取靈感，把解題過程建模成一棵樹上的搜尋（search over a tree）：

  • 節點＝一個「部分解 / 狀態」：包含原始輸入，加上到目前為止已產生的一串想法。
  • 「想法（thought）」＝一個連貫的語言單位：小到一行算式、一個字，大到一整段文字計畫——顆粒度由問題決定，要「夠小能被生成與評估、又夠大能有意義地推進」。
  • 分支＝在同一狀態下產生多個候選想法，形成樹的多條路。
  • 評估＝讓 LLM 自己當啟發式函數，判斷每個狀態有沒有希望，決定要展開哪些、剪掉哪些。
  • 回溯＝走不通就退回上一個還有希望的節點換路。

③ 怎麼實現（四要素）

ToT 是一個純推理時（inference-time）框架，不改任何模型參數，只靠 prompt 與外層的搜尋控制流程。要把一個問題套進 ToT，需要回答四個設計問題：

要素要回答的問題做法
1. 思維分解
Thought Decomposition		一步「想法」該多大？共分幾步？依問題設計想法的顆粒度（一行算式 / 一句計畫 / 一個字），把解題切成數個中間步驟。
2. 想法生成器
Thought Generator		在某狀態下如何產生 k 個候選？兩種：propose（用一個 prompt 讓模型一次提數個下一步）或 sample（用同一個 CoT prompt 獨立取樣 k 次）。
3. 狀態評估器
State Evaluator		如何判斷一個狀態值不值得走下去？兩種：value（讓 LLM 對單一狀態打分，如 sure/maybe/impossible）或 vote（讓 LLM 在多個狀態間投票選最好）。LLM 自己當啟發式函數。
4. 搜尋演算法
Search Algorithm		用什麼策略在樹上走？BFS（每層只保留最好的 b 個狀態往下擴）或 DFS（一路走到底，遇到「impossible」就剪枝並回溯）。

一輪的運作流程

把四要素串起來，每一層的迴圈是：生成候選 → 評估 → 依搜尋策略挑選/剪枝 → 前進或回溯。以 BFS 為例的偽碼：

# BFS 版 ToT（每層保留最好的 b 個狀態）
S = { 初始狀態 x }                      # 樹根：只有輸入
for step in range(T):                   # T = 思維分解的步數
    # 1) 想法生成器：對每個狀態展開 k 個候選想法
    candidates = [ s + thought
                   for s in S
                   for thought in generate(s, k) ]
    # 2) 狀態評估器：LLM 當啟發式，給每個候選一個 value
    values = evaluate(candidates)       # 例：sure / maybe / impossible
    # 3) 搜尋：只留分數最高的 b 個，其餘剪掉
    S = top_b(candidates, values, b)
return best(S)                          # 從存活狀態輸出最終解

DFS 版則是沿一條路徑一路往下，直到抵達解答或評估器判為 impossible；判為不可能時剪枝並回溯到上一個還是「maybe」的分岔點，換另一條路繼續。

關鍵解耦：ToT 把「怎麼想（生成）」和「往哪走（搜尋 + 評估）」拆開。生成交給 LLM 的語言能力，搜尋控制交給外層傳統演算法（BFS/DFS），評估則再借一次 LLM 當啟發式——三者用同一個底層模型、不同 prompt 完成。

④ 關鍵細節（三個任務怎麼設計 prompt）

論文用三個任務展示「四要素」如何依問題客製化。這是理解 ToT「怎麼實現」最具體的部分：

任務思維分解想法生成狀態評估搜尋
Game of 24
(用四個數字＋四則運算湊出 24)		 3 步，每步用掉兩個數做一次運算 propose：一個 prompt 列出當前數字所有可能的下一步運算 value：讓 LLM 判斷剩下的數字「一定 / 也許 / 不可能」湊到 24（sure / maybe / impossible），每個狀態取樣 3 次 BFS，b=1 或 b=5
Creative Writing
(給四個結尾句，寫連貫四段文)		 2 步：先寫「寫作計畫」，再依計畫成文 sample：獨立取樣數個不同的寫作計畫 vote：讓 LLM 在多個計畫/成品間投票，選最連貫的一個 BFS
Mini Crosswords
(5×5 填字)		 逐字（word）填入，每步填一個橫/直的詞 對每個空位提候選詞 value：LLM 判斷剩餘空位是否還可能被填（可行性），不可行就標記 DFS + 回溯：填錯導致死局就退回換詞

Prompt 設計的兩個要點

  • 生成用「propose 還是 sample」看想法空間大小：想法空間有限、需要不重複（如 Game of 24 的運算、填字的候選詞）用 propose 一次列全；想法空間開放、要多樣性（如寫作計畫）用 sample 各自獨立產生。
  • 評估用「value 還是 vote」看好壞好不好單獨判斷：能對單一狀態給出「離目標多遠」的（Game of 24、填字）用 value 逐一打分；難以絕對評分、但相對好壞可比的（哪段文更連貫）用 vote 讓模型們互相比較。

搜尋的深度與廣度（成本旋鈕）

  • 深度由思維分解的步數 T 決定（24 是 3 步、寫作是 2 步）。
  • 廣度由分支數 k 與每層保留數 b 決定。b 越大探索越廣、命中率越高，但 LLM 呼叫次數（成本）也越高——這是 ToT 最主要的效能/成本旋鈕。
整體都靠現成 LLM＋prompt：生成、評估全部是對同一個 GPT-4 發 prompt，外層再用 Python 寫 BFS/DFS 控制流程串起來。不需要微調、不需要額外訓練啟發式模型。

⑤ 效果與限制

效果（皆以 GPT-4 為底層模型）

任務指標基線ToT
Game of 24 成功率 IO 7.3%｜CoT 4.0%｜CoT-SC 9.0% b=1 為 45%；b=5 為 74%
Creative Writing 連貫性（GPT-4 打分 1–10） IO 6.19｜CoT 6.93 7.56；人類評比中偏好 ToT 41/100 次，偏好 CoT 僅 21 次
Mini Crosswords 字（word）層級成功率 IO / CoT 皆低於 16% 60%；解出 4/20 局（若取 DFS 最佳狀態的 oracle 可達 7/20）
最搶眼的數字：Game of 24 上，CoT 只有 4%，換成 ToT（b=5）直接跳到 74%——同一個 GPT-4，差別純粹來自「怎麼組織思考與搜尋」。

限制

  • 成本高：一次解題要多次生成候選＋多次評估，LLM 呼叫量遠大於單次 CoT；b 越大越貴。對已能直接解決的簡單任務，這種搜尋是不必要的開銷。
  • 需要人工設計：思維分解的顆粒度、propose/sample、value/vote、BFS/DFS 都要針對任務手動配置，不是即插即用。
  • 評估器可能不準：LLM 當啟發式並非完美（填字任務 oracle 4/20→7/20 的落差，說明輸出啟發式仍有改進空間）。
  • 適用範圍：對很多現有任務 GPT-4 直接就能解、不需要刻意搜尋；ToT 的價值集中在需要規劃、前瞻與試錯的問題。

⑥ 在「自我演化」地圖上的位置

在本站的《自我演化 Agent 導讀》地圖裡，Tree of Thoughts 落在最內圈：

  • 模型中心演化（Model-Centric） → 推理時演化（Inference-Based） → 結構化推理（Structured Reasoning）。

也就是說：ToT 不改模型參數，純粹靠「改變模型怎麼想」——把線性思考鏈展開成可分支、可評估、可回溯的樹狀搜尋——就能讓同一個模型在需要規劃的任務上大幅變強。它與同格的 Self-Refine / Reflexion（序列自我修正）、Self-Consistency（平行取樣）是「推理時演化」的三種代表路線，而 ToT 是其中「結構化推理」這一支的奠基工作，後續的 Language Agent Tree Search、Graph of Thoughts、Stream of Search 都沿它擴展。

一句話定位：ToT 是「不動參數、只換思考結構」就能自我提升的最典型例子——回到地圖看它的鄰居：② 模型中心演化 · 推理時 · 結構化推理。

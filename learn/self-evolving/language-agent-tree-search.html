🌳 語言代理樹搜尋（LATS）怎麼實現

Language Agent Tree Search Unifies Reasoning, Acting, and Planning in Language Models · Zhou et al. 2023（ICML 2024）· 把「推理／行動／規劃」統一在一棵蒙地卡羅搜尋樹裡

結構化推理 Monte Carlo Tree Search 推理時演化（不改參數）

⓪ 一句話總結

一句話：LATS 把 LLM 同時當成行動者、價值函數、與自我反思者，用蒙地卡羅樹搜尋（MCTS）去展開多條 ReAct 式的行動軌跡，靠環境回饋與自我反思選出最好的一條——用「多想幾步、能反悔」把 reasoning、acting、planning 統一在同一個框架。

它屬於推理時（inference-time）的方法：不重新訓練模型、不改參數，純靠推理階段的搜尋與回饋就把成功率往上推。

① 想解決什麼

在 LATS 之前，讓 LLM 當 agent 的主流做法大致分成三家，各有缺口：

路線做法缺什麼
ReAct（行動）交錯「思考→行動→觀察」，一步步往前走一條路走到底，錯了難回頭，貪婪、無規劃
Tree of Thoughts（規劃）把思考展開成樹、做搜尋多半只在純推理裡想，不與外部環境互動
Reflexion（反思）失敗後寫下語言反饋，下次再試反思有了，但沒有系統性的搜尋去善用它

這三者其實是互補的能力：會走（acting）、會想（reasoning）、會規劃與回頭（planning）。LATS 的目標，就是把它們統一在一個框架裡——既能像 ReAct 那樣呼叫工具、觀察環境，又能像 ToT 那樣展開分支去比較，還能像 Reflexion 那樣從失敗中學。

核心痛點：單線推理 = 押寶一次；真實任務（多步 QA、寫程式、網頁購物）常常要試錯、要回頭。LATS 給 agent 一個「可以反悔、可以比較」的決策結構。

② 核心想法

LATS 借用基於模型的強化學習裡最經典的規劃演算法——蒙地卡羅樹搜尋（Monte Carlo Tree Search, MCTS），AlphaGo 一系的做法——把它搬到語言代理上。

把決策過程建成一棵搜尋樹

  • 節點（node）= 一個狀態：包含目前的任務輸入、過往的行動歷史、以及環境觀察（observation）。根節點是初始問題。
  • 邊（edge）= 一個動作：可以是一步推理，也可以是一個真正的行動（呼叫搜尋、執行程式、在網站上點選⋯⋯）。
  • 一條根到葉的路徑 = 一條完整軌跡：等同於一次 ReAct 式的「思考-行動-觀察」序列。

與純推理的 ToT 最大的不同：LATS 的每一步行動都真的送進環境執行、拿回真實觀察（external feedback），而不是只在腦內模擬。這讓「規劃」有了現實的錨點。

LLM 一人分飾三角

  • Agent（行動者）：在每個節點生成候選的下一步（多個思考／行動）。
  • Value function（價值函數）：用另一個 LLM prompt 去評分一條半成品軌跡離目標多近。
  • Self-reflection（自我反思者）：當一條路失敗（或評分很低），生成語言化的反思，回饋進搜尋，避免重蹈覆轍。
直覺：ReAct 是「一路走到黑」，LATS 是「下棋」——每一步都展開幾個選項、給每個選項打分、往最有希望的分支深入，走不通就退回上一個岔路換條路，並把失敗的教訓寫進筆記。

③ 怎麼實現（MCTS 六步循環）

LATS 把標準 MCTS 的四步（選擇／擴展／評估／回傳）擴充成六步，額外加入 LLM 價值函數與自我反思。每一輪迭代都跑一遍這個循環，直到找到成功解或用完預算。

① Selection（選擇）— 用 UCT 挑最值得探索的節點

從根節點往下，反覆挑選一個子節點，直到抵達一個尚未完全展開的節點。挑選依據是 UCT（Upper Confidence bounds applied to Trees），在「利用已知好分支」與「探索少走過的分支」之間取平衡：

UCT(s) = Q(s) + w · sqrt( ln N(parent) / N(s) )

# Q(s)      : 節點 s 的平均價值（越高越該利用）
# N(s)      : 節點 s 被造訪的次數（越少越該探索）
# w         : 探索權重，調大 = 更愛冒險

② Expansion（擴展）— 讓 LLM 生成多個候選動作

在選中的節點，呼叫 agent LLM 取樣 n 個候選的下一步（n_generate_sample 個思考／行動），為每個候選建立一個新的子節點。這一步把「單線」變成「多分支」。

③ Evaluation（評估）— LLM 價值函數打分

對每個新節點，用評估者 LLM（n_evaluate_sample 次 prompt）判斷這條半成品軌跡離解答有多近，給一個純量分數。論文把節點價值取為兩者的加權平均：

  • 評估者 LLM 的分數：直接讓 LLM 對「目前進展」評分。
  • self-consistency 分數：多次取樣的一致性，作為信心的補強。
為什麼需要它：MCTS 要有一個「這步好不好」的訊號才能搜尋。傳統 RL 靠訓練好的 value network；LATS 直接用 LLM 當即時的、免訓練的價值函數——這是它「不改參數」的關鍵。

④ Simulation（模擬）— 展開到終局拿真實回饋

沿著目前最有希望的節點一路展開到終端狀態（給出答案、程式跑完、購物完成），並從環境取得結果訊號：測試案例是否通過、答案是否正確、任務獎勵多少。這一步把真實世界的成敗帶回搜尋樹。

⑤ Backpropagation（回傳）— 把結果沿路更新回去

把終端拿到的回饋，沿著剛才走過的路徑往上回傳，更新每個節點的 Q(s) 與造訪次數 N(s)。成功的路徑抬高沿途價值，失敗的壓低——下一輪 UCT 選擇就會偏向更有希望的區域。

⑥ Reflection（反思）— 失敗時寫下語言化教訓 🔥

這是 LATS 相對標準 MCTS 的關鍵創新：當一條軌跡失敗，呼叫 LLM 生成一段self-reflection（「哪裡錯了、下次該怎麼改」），把它當成額外的語意脈絡，注入後續節點的 prompt。數值回傳負責「往哪走」，語言反思負責「為什麼、怎麼改」，兩者疊加讓搜尋更有方向。

整體虛擬碼

# LATS 主循環（示意）
root = State(task_input)
while 未達成功 and 迭代次數 < budget:
    node = select(root)              # ① UCT 往下挑
    children = expand(node, n=k)     # ② LLM 取樣 k 個候選動作
    for c in children:
        c.value = evaluate(c)        # ③ LLM 價值 + self-consistency
    leaf = simulate(best(children))  # ④ 展開到終局、跑環境
    reward = env_feedback(leaf)       # 測試通過？答案對？任務獎勵？
    backpropagate(leaf, reward)       # ⑤ 沿路更新 Q、N
    if reward 失敗:
        node.context += reflect(leaf) # ⑥ 語言化反思，注入後續 prompt
return 最佳終端軌跡
可呼叫工具／環境：因為每個動作可以是「搜尋維基」「執行程式碼」「在購物網站點選」，LATS 天然支援工具使用與 agent 環境互動——搜尋樹的邊就是對外部世界的操作，觀察就是環境回傳。

④ 關鍵細節：與 ToT／ReAct／Reflexion 的關係

LATS 最好理解的方式，是把它看成三個既有方法的整合體：

來自LATS 吸收了什麼
ReAct思考-行動-觀察的交錯格式，與環境互動、呼叫工具的能力——成為樹裡「邊 = 動作」的內容
Tree of Thoughts把決策展開成樹、做搜尋的規劃結構——LATS 進一步升級為完整 MCTS 並接上真實環境
Reflexion失敗後的語言化自我反思——被納入六步循環的第⑥步，與數值回傳互補
一句話定位：ToT 有樹但不碰環境；ReAct 碰環境但無樹（單線）；Reflexion 會反思但無搜尋。LATS = 樹搜尋 + 環境互動 + 自我反思，三合一。

幾個實作要點

  • 價值 = 評估者分數 + self-consistency 的加權平均，比單一 LLM 打分更穩。
  • 三個主要旋鈕：n_generate_sample（每節點展開幾個分支）、n_evaluate_sample（評估幾次）、iterations（最多跑幾輪搜尋）——都是拿算力換成功率的開關。
  • 反思是語意記憶，回傳是數值記憶；兩種訊號都留在樹上供後續利用。
  • 可搭配 GPT-3.5 / GPT-4 等現成模型，零額外訓練即可套用。

⑤ 效果與限制

在三類任務上驗證

任務Benchmark結果（以原論文為準）
程式生成（推理）HumanEval搭配 GPT-4 達到 92.7% pass@1，當時的 state-of-the-art
問答（推理＋行動）HotPotQA（多跳）Exact Match 明顯優於 ReAct、Reflexion 等基線 (以原論文為準)
決策／網頁導航WebShopGPT-3.5 下平均分約 75.9，逼近需微調的梯度式方法 (以原論文為準)

核心結論：同一套 LATS 框架在「純推理（寫程式）」「推理+行動（多跳 QA）」「序列決策（網購）」三種形態的任務上都能提升，證明它是一個通用的決策框架，而非為單一任務調校。

限制

成本高是最主要的代價：MCTS 要展開多個分支、每個節點都要多次呼叫 LLM 去生成、評估、反思，API 呼叫數與延遲遠高於單線的 ReAct/CoT。搜尋越深越廣，成功率越高，帳單也越貴。
  • 算力／金錢／時間開銷大：一次任務可能是單線方法的數倍到數十倍呼叫。
  • 依賴 LLM 價值函數的品質：若評估者對「進展」判斷不準，搜尋會被帶偏。
  • 需要可查詢的環境回饋：能拿到測試結果／任務獎勵時最有效；回饋稀疏時優勢縮小。
  • 因此實務上常限制搜尋預算（iterations、分支數）在成本與效果間取捨。

⑥ 在「自我演化 Agent」地圖上的位置

對照本站的自我演化 Agent 綜述，LATS 座落在最內圈：

模型中心演化（Model-Centric）→ 推理時演化（Inference-Based）→ 結構化推理（把思考展開成樹／圖／搜尋）

它與 Tree of Thoughts、Think-on-Graph、Stream of Search 同屬「結構化推理」一格——不改參數，純靠「怎麼想／怎麼搜」把現成模型的能力壓榨出來。同時它把 Reflexion（序列自我修正）也一併吸收進搜尋循環，是推理時演化路線裡最具整合性的代表之一。

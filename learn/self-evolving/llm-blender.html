🎛️ LLM-Blender：集成多個 LLM，取眾長

成對排序（PairRanker）＋ 生成式融合（GenFuser）· Jiang et al., ACL 2023 · 論文「怎麼實現」逐步拆解

⓪ 一句話

一句話：與其押注在某一個「最強模型」，不如把多個 LLM 對同一題的答案都拿來，先用一個成對比較的排序器（PairRanker）選出最好的幾個，再用一個生成式融合器（GenFuser）把這幾個好答案「揉」成一個比任何單一模型都更好的最終答案。

LLM-Blender 是一個推理時的集成（ensembling）框架：不重新訓練那些大模型，只在它們的輸出之上加兩個相對小的模型，就把「眾模型之長」聚成一個更穩、更好的回答。

① 想解決什麼

開源 LLM 越來越多，但它們各有所長、也各有所短：同一批問題裡，A 模型在某些題目表現最好、B 模型在另一些題目最好，沒有哪一個模型在所有題目上都是最優。論文的觀察是——最佳模型會隨題目而變（example-wise）。

  • 選單一模型不划算：就算挑出「平均最強」的那個，它在很多具體題目上仍然輸給別人。
  • 簡單投票行不通：開放式生成（open-ended generation）的答案是自由文字，不像分類有固定選項可以多數決；兩個好答案措辭完全不同，無法直接「投票」。
  • 想同時做到兩件事：(1) 針對每一題挑出最好的候選；(2) 再把幾個好候選的優點合併成一個更完整的答案。
目標：做一個能「逐題選優 + 融合成更好」的集成器，把 N 個現成 LLM 當成一組「顧問」，輸出一個超越任何單一顧問的答案。

② 核心想法（兩階段）

LLM-Blender 把「集成」拆成先排序、再融合兩個階段，各由一個專門模組負責：

階段模組做什麼為什麼這樣設計
階段一
Rank		PairRanker
（排序器）		把 N 個候選答案兩兩比較，判斷「哪個更好」，再聚合成排名直接給單一答案打絕對分很難、也不穩；成對比較能放大候選之間的細微差異，判斷更可靠
階段二
Fuse		GenFuser
（融合器）		取排名最高的 top-K 個候選，連同原始問題一起，生成一個融合後的新答案最好的答案可能不在任何單一候選裡，而是幾個候選各取優點組合出來的
關鍵直覺：「選最好的一個」有天花板——最好答案可能沒人單獨寫出來。所以先用 PairRanker 篩掉爛的、留下好的，再讓 GenFuser 在這些好料上二次創作，突破單一模型的上限。

③ 怎麼實現

整體資料流

# 給定一個指令 x，N 個 LLM 各產生一個候選答案
x  ──►  [LLM₁ … LLM_N]  ──►  候選 {y₁, y₂, …, y_N}

# 階段一：PairRanker 對候選兩兩比較，聚合出排名
{y₁…y_N}  ──►  PairRanker  ──►  排名（best → worst）

# 階段二：取 top-K（論文設 K=3），連同 x 一起餵給 GenFuser 生成融合答案
x + top-K 候選  ──►  GenFuser  ──►  最終融合答案 ŷ

PairRanker：怎麼「成對比較」排序候選

PairRanker 的核心，是把「排序」轉成一連串「A 好還是 B 好」的二選一判斷：

  1. 輸入編碼：對一對候選 (yᵢ, yⱼ)，把原始指令 + 兩個候選一起拼成單一序列送進編碼器。論文用特殊前綴標記把三段區分開來——如 <|source|>（原始指令）、<|candidate1|>、<|candidate2|>。這讓模型能同時看到指令與兩個候選、做直接對照，而不是各自獨立打分。
  2. 打分模型：骨幹是 DeBERTa-v3-Large（約 304M 參數）的交叉編碼器（cross-encoder）。它讀完 (x, yᵢ, yⱼ) 後輸出一個比較分數，表示在這一對中 yᵢ 相對 yⱼ 誰更好。
  3. 對稱性處理：為避免「誰排前面」造成位置偏差，同一對通常會交換順序各跑一次，取兩次結果彙整，讓比較更對稱可靠。
  4. 聚合成排名：N 個候選兩兩比較會得到一個比較結果矩陣，再把這些成對勝負聚合成一個總排名。實作提供兩種推理模式——full（做完整的成對比較矩陣，較準）與 bubble（類似冒泡排序，只做必要比較，較省算力）。
訓練訊號從哪來：訓練時用自動指標（如 BARTScore、BLEURT、BERTScore）對每個候選與參考答案算出品質分，據此得到「哪個候選比較好」的成對標籤，用來監督 PairRanker 學會人類/指標偏好的比較。

GenFuser：怎麼把 top-K 融合成更好答案

GenFuser 是一個序列到序列（seq2seq）的生成模型，把「融合」當成一個條件生成任務：

  1. 取材：拿 PairRanker 排名最高的 top-K 個候選（論文設 K=3）。只用最好的幾個，是為了避免把低品質候選的錯誤也一起帶進來。
  2. 輸入拼接：把原始指令 + 這 K 個候選依序拼成一段輸入序列（同樣用特殊標記分隔各段），餵給生成器。
  3. 生成融合：骨幹是 Flan-T5-XL（約 3B 參數）。它不是照抄某一個候選，而是綜合這幾個候選的優點、補其不足，生成一段全新的融合答案。
  4. 訓練目標：以「指令 + top-K 候選」為輸入、以參考答案為目標，用標準的生成式（teacher forcing）目標微調 Flan-T5，讓它學會「怎麼把好料揉成更好的答案」。

訓練資料：MixInstruct 基準

為了訓練與評測這套框架，作者建了一個新基準 MixInstruct——第一個大規模、由多個開源 LLM 對同一批指令生成回應的資料集：

項目內容
規模約 100k 訓練 / 5k 驗證 / 5k 測試；測試集中約 4,771 筆另用 ChatGPT 做成對比較評估
指令來源整合四個指令資料集：Alpaca-GPT4、Dolly-15k、GPT4All-LAION、ShareGPT
候選來源用 11 個熱門開源 LLM 對每則指令各生成一個候選回應（具體清單以原論文為準）
參考答案來自 ChatGPT / GPT-4 或人工標註
成對標籤以自動指標與 ChatGPT 成對比較，產生候選之間的「誰更好」監督訊號
(以原論文為準)：本頁對 11 個開源 LLM 的完整清單、各模組確切超參數與逐項數值，因抓取來源受限未能全部逐一查證；此處僅列已確認到的要點，細節請以論文原文與官方 repo 為準。

④ 關鍵細節

  • 為什麼是「成對」而非「打絕對分」：要模型對單一長答案給穩定的絕對品質分很難；把問題化成「A vs B 哪個好」，能凸顯候選之間細微差異，判斷更穩健，這是 PairRanker 設計的核心。
  • 兩個小模型撬動一群大模型：PairRanker（304M）+ GenFuser（3B）相對於被集成的 LLM 都不大，卻能在它們之上榨出額外增益——這是推理時集成的性價比所在。
  • Rank 與 Fuse 分工：PairRanker 負責「選」（判別式、比較式），GenFuser 負責「合」（生成式）。兩者職責清楚、可各自替換或單獨使用（可以只用 PairRanker 選最佳、不做融合）。
  • full 與 bubble 兩種排序模式：在準確度與計算量之間權衡——full 做完整成對矩陣最準；bubble 只做必要比較，適合候選多、要省算力時。
  • top-K=3：融合只取排名前三，兼顧「多樣素材」與「避免引入劣質候選的雜訊」。
  • 評測指標：同時用自動指標（BARTScore、BERTScore、BLEURT）與 ChatGPT/GPT-4 成對比較（GPT-Rank）交叉驗證。

⑤ 效果與限制

效果

  • 在 MixInstruct 上，LLM-Blender 顯著超越最佳的單一開源 LLM，也勝過基線的集成方法（依論文報告，跨 BARTScore/BERTScore/BLEURT 與 GPT 成對比較皆有提升）。
  • PairRanker 選出的最佳候選本身就優於任何固定的單一模型；再經 GenFuser 融合後品質進一步提升，證明「選 + 合」兩階段各有貢獻。
  • 展示了一條不改動大模型、只在輸出層做集成就能拉高整體表現的可行路線。

限制

  • 推理成本高：要先讓 N 個 LLM 各跑一遍產生候選，再跑成對比較與融合——延遲與算力成本是單一模型的數倍。
  • 成對比較是平方級：full 模式的比較次數隨候選數平方成長；候選一多就得靠 bubble 之類的近似來省算力。
  • 受候選品質天花板約束：若所有候選都不好，GenFuser 也難無中生有；集成的收益取決於候選集是否互補。
  • 依賴訓練分佈：PairRanker / GenFuser 在 MixInstruct 上訓練，換到差異很大的領域或新模型組合時，泛化能力需再驗證。
  • 指標與標註偏差：訓練訊號部分來自自動指標與 ChatGPT 判斷，會繼承這些評判本身的偏好與偏差。

⑥ 在「自我演化」地圖上的位置

把 LLM-Blender 放回本站的自我演化地圖，它屬於最靠內圈的一類——模型中心（Model-Centric）→ 推理時演化（不改參數）→ 平行取樣／集成：

維度歸屬
大維度模型中心演化（Model-Centric）
子類推理時演化（Inference-Based）— 不改參數，靠「怎麼組織多路輸出」
手法平行取樣 / 集成：多路答案再彙整（與 Self-Consistency、Large Language Monkeys 同一格）
和鄰居的差別：Self-Consistency 是「同一個模型多次取樣後投票」；LLM-Blender 則是「不同模型各出一版，再比較＋生成式融合」——把「多路彙整」從「投票」升級成「排序後再創作」，因此能用在無固定答案的開放式生成上。它正是導讀中「模型中心 → 推理時 → 平行取樣／集成」那一格的代表工作之一，詳見 ② 模型中心演化。

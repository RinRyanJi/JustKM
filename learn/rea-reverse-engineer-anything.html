🔬 REA(Reverse Engineer Anything):給 AI 代理的逆向工程 MCP

看到某個 app 有個你想要的功能,想懂它「到底怎麼做到的」——甚至做一個自己的版本?REA 是一個 MCP 伺服器,把你的 AI 代理接上一整套逆向工程工具:原生二進位、JavaScript/Electron、.NET、Android、網站、封包、韌體……都能在本機分析,而且每個結論都附上證據與限制。本頁拆解它的運作迴圈、能分析什麼、兩種分析模式,以及合法使用的界線。

⓪ 一句話總結

REA = 「Reverse Engineer Anything」,一個把 AI 代理接上逆向工程工具的 MCP。它的賣點是一條迴圈:看到功能 → 懂它怎麼做(深到 binary 層)→ 用證據支持 → 幫你做一個。你的代理透過 MCP 呼叫 REA 去檢查、追蹤目標,REA 回傳「findings + 證據 + 還不確定的地方」,代理再據此解釋行為、或動手實作並測試。分析在本機進行,同樣的工具也能從終端機直接用。

定位:它不是單一反編譯器,而是一層「編排器 + 統一介面」——把 Hopper/Ghidra/IDA、JADX、WABT、TShark、mitmproxy、binwalk 這些既有工具,包成代理可呼叫的 MCP 工具,並強制「附證據」。MIT 授權、npm 套件 rea-agents、支援 Claude Code / Codex / Cursor / Gemini CLI 等。

① 它解決什麼問題

逆向工程門檻高:你要會用反編譯器、看得懂組語、知道怎麼追 IPC、怎麼拆 APK……每種目標一套工具、一套知識。REA 把這些收斂成「問代理一句話」:

理解 Notes app 的搜尋功能怎麼運作,給我看證據,
然後幫我的專案做一個類似的功能。

代理在背後呼叫 REA,對那個 app 做分析(不需要原始碼),解釋功能怎麼實作、秀出支持結論的證據,再幫你實作一版。價值有三:

  • 降低門檻:不必自己記每種工具的指令,代理替你驅動。
  • 可稽核:結論附證據與「還不確定的地方」,不是黑箱猜測。
  • 可行動:findings 直接餵給代理去寫、去測一個實作。

④ 深度原生分析:Hopper / Ghidra / IDA 三選一

要對原生二進位做「深度」分析(偽碼、組語、交叉參考),REA 需要接一個原生分析引擎(provider):

  • 三選一:Hopper、Ghidra、或 IDA。setup 可在你同意後幫你裝 Hopper;Ghidra/IDA 用你現有安裝。
  • 按需啟動:REA 在某個操作需要時才啟動 Hopper(macOS 首次可能跳授權/demo 對話框,要先完成)。
  • 靜態 JS / .NET 不需要引擎:這兩類靜態檢查直接讀檔即可。
  • 進階:Ghidra 還支援 16-bit DOS 分析、實驗性 Windows 支援;大型 binary 可用 REA_GHIDRA_STARTUP_TIMEOUT_MS / REA_HOPPER_STARTUP_TIMEOUT_MS 拉長啟動期限。

⑤ 兩種分析模式:靜態讀檔 vs 執行時捕獲

這個分野很重要,攸關安全與你該有的心理預期:

← 左右滑動看完整圖 →
不執行應用程式 例:JS / .NET / Flutter / ELF 版面 副作用最小,最安全 執行時捕獲 實際運行 / 互動目標 以你的使用者權限執行 例:行程行為 / 網站 / Android 裝置 每個執行時指南都會說明其副作用
▲ 靜態只讀、不跑;執行時會真的運行目標。分析不受信任的樣本時,優先靜態,執行時務必在隔離環境並讀清楚該指南的副作用。

⑥ 設計原則:證據導向 + 本機分析

  • 每個結論都附證據與限制:findings 帶著「支持它的程式碼/參考」與「還不確定的地方」,讓代理(和你)不會把猜測當事實。
  • 分析在本機:REA 不上傳你的 app;它在本機跑分析、把結果交給代理。但要注意:你的代理模型供應商有自己的資料政策——findings 一旦進了代理對話,就受那個供應商的政策管。
  • 統一介面、既有工具:它不重造反編譯器,而是編排 Hopper/Ghidra/IDA/JADX/TShark 等成熟工具,降低跨工具的認知負擔。
  • CLI = 同一套 workflow:不想透過代理?同樣的分析能從終端機直接跑、可腳本化(見 ⑧)。

⑦ 實戰案例(官方 Showcases)

  • DX-Ball:重建音效聲道(pan)計算——追一個音效呼叫進它的「位置→聲道」helper,看指令、把不完整的偽碼補成 C。重建版通過 3,205 個原始 x86 案例、重現全部 63 個編譯後函式位元組。
  • Notion:追 Electron 剪貼簿橋接——從 renderer 的剪貼簿 API,一路經 preload 與 IPC 追進 main 行程,檢視豐富剪貼簿格式。
  • TH04:復原 DOS 子彈環計算——檢視 PC-98 遊戲的 16-bit 指令,復原固定與瞄準角度計算,再把重建的 C++ 和當年的編譯器輸出比對。
共同模式:不是「反編譯完就結束」,而是反編譯 → 理解 → 重建 → 用可驗證的方式證明重建正確(通過原始案例、重現位元組)。這正是 REA 強調「證據」的體現。

⑧ 怎麼上手

需要 Node.js(22.x ≥22.19、24.x ≥24.11、或 26+)與 npm。

# 1) 設定你的代理:註冊 REA 的 MCP + 安裝對應的 workflow 指令
npx rea-agents setup
#    選代理、檢視並核准變更(會備份原設定)、重啟代理

# 2) 直接問代理(把 Notes 換成你的目標 app 與功能)
#    「理解 X app 的 Y 功能怎麼運作,給我證據,再幫我做一個」

# 3) 或從終端機直接用(分析已解壓的 JS/Electron 目錄或 ASAR)
npx -y rea-agents@latest analyze-javascript-application /abs/path/to/app --json

# 4) 想常用就全域安裝
npm install --global rea-agents
rea --help
rea update   # 常更新,新版常修 bug

支援 Claude Code、Codex、Cursor、Gemini CLI、Grok Build 等;其他支援本機 MCP 的客戶端可手動註冊。原生分析要先設定一個 provider(Hopper/Ghidra/IDA)。

⑨ 重點 · 合法界線 · 來源

六個帶得走的重點

  1. REA = 把 AI 代理接上逆向工程工具的 MCP;一條迴圈:看到功能 → 懂它 → 附證據 → 幫你重建。
  2. 廣度驚人:~20 種目標,從原生二進位/組語到 JS/Electron、Android、網站、封包、韌體。
  3. 深度原生分析需 Hopper/Ghidra/IDA 三選一;靜態 JS/.NET 不需引擎。
  4. 兩種模式:靜態只讀檔 vs 執行時以你的權限運行——不受信任樣本優先靜態、並隔離。
  5. 原則:證據 + 限制、本機分析(但 findings 進代理後受模型供應商資料政策管)。
  6. CLI 與代理共用同一套 workflow;npm rea-agents、MIT。
合法與倫理界線(務必自負責任):逆向工程在許多情境是正當的——互通、資安研究、學習、除錯、相容性;但也受著作權、授權條款、軟體 EULA/服務條款、以及當地法律約束。分析前請確認:你有權分析該目標、你的用途合法、且重建不會侵犯他人的授權或智慧財產。REA 只是工具,如何使用與後果由使用者承擔。

🤖 AutoGen:多 Agent 對話協作框架

微軟開源。用「多個可對話的 agent 彼此交談」來完成任務 —— 讓生成與審查由不同角色扮演,以角色對立消滅單一 agent 的自我感覺良好

⓪ 一句話

AutoGen 是微軟開源的多 agent 應用框架——官方定位為「a framework for creating multi-agent AI applications that can act autonomously or work alongside humans(能自主行動、也能與人協作的多 agent AI 應用框架)」。它的核心想法很簡單:把一個任務交給「一群會彼此對話的 agent」,讓它們透過訊息往返分工、辯論、互相檢查,而不是仰賴單一模型一次答對。

版本現況(以官方 repo 為準):README 已聲明 AutoGen「now in maintenance mode(進入維護模式)」,不再新增功能、改由社群維護;微軟建議新專案改用 Microsoft Agent Framework,既有使用者可依官方遷移指南轉移。本頁作為框架方法論介紹仍具參考價值,但採用前請以官方 repo 的最新狀態為準。

① 解決什麼問題:單一 agent 難以自我審查

一個孤立的 LLM agent 有兩個根深柢固的毛病:

  • 自我感覺良好——讓同一個模型「寫完再自評」,它幾乎總是傾向給自己高分、放過自己的缺失,因為評判者與被評判者是同一個立場。
  • 難以自我糾錯——單一 prompt 要同時扮演研究、撰寫、審查多種角色,職責混在一起,錯誤容易被自己的敘事帶過,缺乏「對立視角」去戳破。

AutoGen 的處方是把角色拆開、讓它們對話:研究、撰寫、審查各由不同 agent 承擔,彼此透過訊息交換意見。當「撰寫者」與「稽核者」是兩個獨立立場的 agent,審查才有意義——這正是站內〈讓 AI 產生高品質文件〉一頁反覆強調的「角色分離消滅自我感覺良好」的工程化落地。

一句話:與其把「生成 + 審查 + 校正」壓進一個超長 prompt,不如把它們變成多個 agent 之間的對話回合,讓對立與分工自然發生。

② 核心機制:可對話的 agent 與多 agent 對話

可對話的 agent(Conversable Agents)

AutoGen 的基本單位是「可對話的 agent」:每個 agent 都能收訊息、依自身設定(模型、系統提示、可用工具)產生回應,再把訊息送給其他 agent。幾種代表性角色:

Agent 類型角色
ConversableAgent基礎類別,提供 agent 間對話的通用能力(在 0.2 為中心抽象;0.4+ 為 AgentChat 的底層概念)
AssistantAgent由 LLM 驅動的 agent,會使用模型與工具來完成任務(撰寫、分析、呼叫函式)
UserProxyAgent代表人類使用者參與對話,支援 human-in-the-loop(把人類回饋接進迴圈)

多 agent 對話怎麼運作

多個 agent 放進一個群組對話(group chat / team),由一套規則決定「下一個換誰發言」,訊息一輪輪傳遞直到滿足終止條件:

  • Group Chat(群組對話)——多個 agent 在同一個對話場域裡輪流貢獻,共同解一個問題。
  • Round-Robin(輪替)——按固定順序依序發言,一圈一圈跑,規則最單純、最好預測。
  • Speaker Selection(選擇下一位發言者)——依上下文智慧決定該由誰接話(例如 0.4+ 的 SelectorGroupChat 用模型挑下一位),讓對話動態地流向最該說話的角色。
  • 終止條件——例如「有人說出某個關鍵字」或「達到最大訊息數」就停;把「什麼時候算完成」明確化,避免無限對話。(具體條件類別以官方 repo 為準)

工具與程式碼執行

Agent 不只是聊天:AssistantAgent 可被賦予工具(函式呼叫),也能透過擴充能力執行程式碼。這讓「撰寫→跑一段驗證程式→依結果修正」成為對話中的一步,而不是外部另接的流程——與站內流水線裡「反向程式驗證引用是否真實存在」的思路直接呼應。

為什麼「對話」是關鍵抽象:當協作被表達成訊息往返,新增一個角色就只是多放一個 agent、多定義它何時發言;審查、辯論、修訂都變成對話回合,系統因此容易擴充與觀察。

③ 應用:「撰寫者 vs 稽核者」團隊

把 AutoGen 套到文件生成,自然長出一個三角色團隊,對應站內流水線的角色分工:

Agent職責對應機制
研究員 Researcher蒐集資料、彙整事實與來源用工具檢索;每項宣稱綁定出處(事實錨定)
撰寫員 Writer依邊界條件(讀者/領域/必備章節)產出初稿AssistantAgent + 系統提示規範
稽核員 Critic扮演嚴格審查者,依 checklist / rubric 評分並要求原文引用角色對立;先推理後給分

自動校正迴圈

關鍵在對立加上門檻退回:稽核員依 checklist 逐項評分,低於門檻(如 85 分)就把「扣分原因 + 原文對照」退回撰寫員重寫,再交稽核員複審——如此往返,直到達標或達到最大回合數才終止。整個校正迴圈,就是一段被規則約束的多 agent 對話。

研究員 ──蒐集事實+來源──▶ 撰寫員 ──初稿──▶ 稽核員 │ ┌── 依 checklist / rubric 評分 ──┘ ▼ 達標? ──否(<門檻)──▶ 帶「扣分理由+原文引用」退回 撰寫員 重寫 │ （下一回合對話） └──是──▶ 產出定稿
對照站內主頁:這正是〈讓 AI 產生高品質文件〉第 ⑥ 節把 AutoGen / CrewAI 列為「多角色協作框架(模擬編寫+審查團隊)」的原因——生成者 vs 審查者對立,低於門檻退回重寫,形成自動校正迴圈。AutoGen 提供的,正是把這個迴圈寫成「agent 對話」的底座。

④ 架構層:從 0.2 的經典 API 到 0.4+ 的分層

AutoGen 經歷了一次重要重構(以官方 repo 為準):

v0.2(經典 API)

較為單體(monolithic)的設計,以 ConversableAgent 為中心抽象,AssistantAgent / UserProxyAgent / GroupChat 皆圍繞它;套件名為 pyautogen(匯入 autogen)。

v0.4+(分層架構)

重寫為事件驅動、可分散式的三層設計:

層套件負責什麼
Coreautogen-core底層訊息傳遞與事件驅動 agent,支援本機/分散式 runtime,跨 Python 與 .NET
AgentChatautogen-agentchat建構在 Core 之上、較高階且「有主見(opinionated)」的 API,提供常見模式(兩 agent 對話、team/group chat);使用感貼近 0.2 使用者
Extensionsautogen-ext第一方/第三方擴充:LLM 用戶端(OpenAI、Azure 等)與各種能力(如程式碼執行)

此外還有 AutoGen Studio(autogenstudio),一個無程式碼 GUI,用來以拖拉方式搭建多 agent 應用。

怎麼選層:要快速把「撰寫者/稽核者團隊」跑起來,用 AgentChat;需要自訂訊息路由、分散式或跨語言 runtime,才下沉到 Core;要接特定模型或加程式碼執行等能力,靠 Extensions。

⑤ 最小範例(以官方 repo 為準)

單一 agent:Hello World(README 原文)

官方 README 的入門範例——一個 AssistantAgent 接上模型用戶端,非同步執行一個任務:

import asyncio
from autogen_agentchat.agents import AssistantAgent
from autogen_ext.models.openai import OpenAIChatCompletionClient

async def main() -> None:
    model_client = OpenAIChatCompletionClient(model="gpt-4.1")
    agent = AssistantAgent("assistant", model_client=model_client)
    print(await agent.run(task="Say 'Hello World!'"))
    await model_client.close()

asyncio.run(main())

兩個 agent 對話成團隊(結構示意,實際 API 以官方 repo 為準)

在 AgentChat 中,把多個 agent 放進一個 team,以輪替方式對話、在滿足終止條件時停止。下面示意「撰寫員 ⇄ 稽核員」的最小對立團隊:

from autogen_agentchat.agents import AssistantAgent
from autogen_agentchat.teams import RoundRobinGroupChat
from autogen_agentchat.conditions import TextMentionTermination

writer = AssistantAgent("writer", model_client=model_client,
    system_message="你是撰寫員,依邊界條件產出文件初稿。")
critic = AssistantAgent("critic", model_client=model_client,
    system_message="你是嚴格稽核員,依 checklist 評分並附原文引用;"
                   "達標才回覆 'APPROVE'。")

# 有人說出 APPROVE 就終止這場對話
team = RoundRobinGroupChat([writer, critic],
    termination_condition=TextMentionTermination("APPROVE"))

await team.run(task="撰寫一份 X 的技術規格書")
讀法:兩個 agent 一寫一審,輪流發言;稽核員不滿意就繼續退回,滿意才喊 APPROVE 觸發終止。這就是「自動校正迴圈」用十幾行程式碼落地的樣子。類別與參數名稱請以官方 repo / 文件為準。

⑥ 在「高品質文件流水線」的位置

回到站內主軸——讓 AI 產生高品質文件的四層流水線裡,AutoGen 主要落在第 2 層「生成流程」:它提供把「撰寫者 ⇄ 審查者對立協同」表達成多 agent 對話的底座。

流水線層AutoGen 扮演的角色
1. 結構定義可在 agent 系統提示中植入 Metadata/邊界條件(讀者、領域、必備章節)
2. 生成流程核心地帶:多 agent 團隊實現撰寫者/稽核者對立、研究員分工;工具/程式碼執行支援 Map-Reduce 分塊
3. 品質評估稽核 agent 依 rubric/checklist 打分、要求原文引用;評分本身可由專用框架(如 Ragas / DeepEval)補強
4. 自動迭代低於門檻退回重寫,以對話回合實現 Reflexion loop
角色對立是精髓:AutoGen 之所以能提升文件品質,不是因為模型更聰明,而是因為它讓審查者與撰寫者站在不同立場、把校正變成可觀察、可重跑的對話。這與本站一貫主題一致——不靠更強的模型,靠更好的流程與角色設計。

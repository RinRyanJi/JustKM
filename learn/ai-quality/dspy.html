🧬 DSPy:把 Prompt 當「可編譯的程式」

Stanford NLP 的框架 —— 用寫程式(programming)取代調提示(prompting);你定義程式與評分,DSPy 自動編譯出高效 Prompt 與 few-shot 範例

⓪ 一句話

DSPy(取自 Declarative Self-improving Python)是 Stanford NLP 開源的框架,主張「programming — not prompting — language models」:把跟語言模型互動的邏輯寫成模組化的 Python 程式,再交給 DSPy 的優化器依你的評分自動「編譯」出高品質的 Prompt 與示範範例,而不是靠人手一次次改提示字串。

心智模型轉換:傳統做法是「寫一段咒語般的 Prompt,不行就再改字」;DSPy 的做法是「宣告你要什麼(輸入→輸出)、給一個能打分的 metric,讓框架把『調 prompt』當成一個可搜尋、可編譯的優化問題」。
一 · 是什麼、解決什麼

① 它解決什麼問題

手寫、寫死的 Prompt 有幾個老問題,DSPy 正是衝著它們來的:

手寫固定 Prompt 的痛點DSPy 的回應
脆弱:一個字、一個範例改動就崩,靠玄學調參把 Prompt 拆成可組合的模組,由優化器系統性地搜出好版本
Prompt 漂移:同一份提示在不同輸入/時間表現飄忽用metric + 資料集把「好不好」量化,讓優化有客觀依據
換模型就壞:為 A 模型調好的 Prompt,搬到 B 模型失效程式與 Prompt 解耦;換 LM 後重新 compile()即可再優化,不必重寫邏輯
few-shot 範例靠手挑,費工又未必最優優化器(如 BootstrapFewShot)自動挑選/生成示範
與本站主題呼應:這正是 高品質文件方法論 反覆講的「不靠更強的模型,靠更好的流程」——把品質不穩交給可優化的機制,而非祈禱一次寫對 Prompt。

② 核心概念

DSPy 的積木不多,關鍵是四層加一個動作:

Signature — 宣告「輸入 → 輸出」

用宣告式的方式描述某一步要做什麼,而不寫具體 Prompt 字句。可用精簡的字串形式,也可用類別形式加上型別與說明:

# 字串式 Signature
"question -> answer"

# 類別式 Signature
class BasicQA(dspy.Signature):
    """Answer questions with short factoid answers."""
    question: str = dspy.InputField()
    answer: str = dspy.OutputField(desc="often between 1 and 5 words")

Module — 決定「怎麼推理」

把 Signature 套進一個推理策略。常見內建 Module:

Module作用
dspy.Predict最基本:直接依 Signature 產生輸出
dspy.ChainOfThought先產生推理步驟(思考鏈)再給答案
dspy.ReAct推理 + 行動(可呼叫工具)的代理式流程

多個 Module 可組合成一個更大的程式(dspy.Module 子類),像一般 Python 那樣呼叫與巢狀。

Optimizer / Teleprompter — 自動「編譯」Prompt

優化器(舊稱 Teleprompter)吃你的程式、metric 與訓練集,自動找出更好的 Prompt 指令與 few-shot 範例。常見的有:

  • BootstrapFewShot:自動生成/挑選示範範例(bootstrap few-shot)。
  • MIPROv2:同時優化指令文字與示範的進階優化器(EvoAgentX 引用的 MIPRO 同源)。

Metric — 定義「什麼叫好」

一個回傳分數/布林的函式,讓優化有客觀目標。例如判斷答案是否正確:

def gsm8k_metric(gold, pred, trace=None) -> int:
    return int(parse_integer_answer(str(gold.answer))) == int(parse_integer_answer(str(pred.answer)))

compile() — 按下編譯鍵

把「程式 + metric + trainset」交給優化器的 compile(),回傳一個被優化過的新程式。這一步就是 DSPy 所謂的「編譯」:它不改你的邏輯,而是改出最合適的 Prompt/範例。

③ 怎麼運作:把「調 Prompt」變成優化問題

流程可以拆成三段:你宣告程式、你提供評分、DSPy 自動搜尋並編譯。

1. 你定義 Signature(輸入→輸出) + Module(Predict / CoT / ReAct)組成程式 │ ▼ 2. 你評分 一個 metric(什麼叫「好」) + 一小份 trainset / 範例 │ ▼ 3. DSPy 編譯 Optimizer.compile() 自動搜尋:試不同指令、挑/生成 few-shot 範例 │ 用 metric 打分,保留表現最好的組合 │ └──▶ 產出:被優化過的程式(內含高效 Prompt 與示範)

關鍵轉念:你不再直接編輯 Prompt 字串。你維護的是「程式結構 + 評分標準」,Prompt 本身變成優化器的輸出。換了模型或改了 metric,重跑 compile() 就重新優化一次。

為什麼這招有效:人手調 Prompt 是在高維空間裡盲目試錯;DSPy 把它變成有目標函式(metric)、有搜尋策略(optimizer)、有驗證資料(trainset)的優化,自然更穩、更可複現、可隨模型演進而重跑。
二 · 用在文件品質

④ 用於文件品質:讓 DSPy 自動編譯你的評分器/生成器

回到 高品質文件方法論 的場景。那裡的痛點是「品質不穩、評分主觀、換個 Prompt 就飄」。DSPy 的落地方式:

  • 把 Rubric 寫成 metric:方法論裡的「二元檢核清單、按點扣分、強制引用反查」本質上就是一個可程式化的評分函式——正好當 DSPy 的 metric。
  • 把評分器/生成器寫成 Module:例如一個 ChainOfThought 評分器(先列扣分理由與原文引用,再給分)、或一個生成器 Module。
  • 讓 DSPy 自動編譯:用少量「已知好/壞的文件範例 + Rubric metric」跑 compile(),DSPy 會自動調出讓評分最貼近你 Rubric 的 Prompt 與示範,解決「同一份評分 Prompt 時好時壞」。
一句話:方法論負責定義「好」的規則(Rubric),DSPy 負責自動把 Prompt 調到最能執行這套規則。前者是標準,後者是達標的自動化手段。

⑤ 最小範例(以官方 repo / cheatsheet 為準)

下列片段取自 DSPy 官方文件的用法,依序展示 Signature → Module → 優化編譯:

a. Predict / ChainOfThought / ReAct

# 最基本:字串式 Signature
predict = dspy.Predict("question -> answer")
predict(question="1+1", config={"rollout_id": 1, "temperature": 1.0})

# 思考鏈:先推理再答(套用類別式 BasicQA)
generate_answer = dspy.ChainOfThought(BasicQA)
pred = generate_answer(question="What is the color of the sky?")

# 代理式:推理 + 行動
react_module = dspy.ReAct(BasicQA)
result = react_module(question="Sarah has 5 apples. She buys 7 more ... how many now?")

b. 用優化器編譯(BootstrapFewShot)

from dspy.teleprompt import BootstrapFewShot

fewshot_optimizer = BootstrapFewShot(
    metric=your_defined_metric, max_bootstrapped_demos=4,
    max_labeled_demos=16, max_rounds=1, max_errors=10)

# compile():回傳被優化過的新程式
your_dspy_program_compiled = fewshot_optimizer.compile(
    student=your_dspy_program, trainset=trainset)

c. 進階優化器(MIPROv2 — 同時優化指令與示範)

from dspy.teleprompt import MIPROv2

teleprompter = MIPROv2(metric=gsm8k_metric, auto="light")
optimized_program = teleprompter.compile(
    program.deepcopy(), trainset=trainset,
    max_bootstrapped_demos=3, max_labeled_demos=4)
版本註記:DSPy API 仍在演進(優化器名稱、參數、dspy.LM 設定方式等可能隨版本調整)。實際簽名與可用選項以官方 repo 與 dspy.ai 文件為準;上面片段取自官方 cheatsheet,用於示意流程。

⑥ 在「高品質文件流水線」中的位置

對照 方法論總頁 的四層流水線,DSPy 不是取代其中某一層,而是提供一種「動態 Prompt 編譯」的能力,讓生成器與評分器的 Prompt 不用手寫寫死:

結構定義 Metadata / Schema ── 邊界條件(讀者、領域、必備章節) │ ▼ 生成 & 評分 ←── 這兩層的 Prompt 交給 DSPy 編譯 │ 生成器 Module / 評分器 Module(Rubric = metric) │ BootstrapFewShot / MIPROv2 自動調出高效 Prompt ▼ 自動迭代 未達門檻 → 帶扣分理由重寫(Reflexion loop)

簡言之:方法論的「Rubric、二元檢核、強制引用」是評分標準(metric);DSPy 是把 Prompt 自動優化到最能執行這套標準的引擎。

站內對照:本站 EvoAgentX 用到的 MIPRO 正是 DSPy 系的優化器(與此頁的 MIPROv2 同源);EvoAgentX 把這類「提示自動優化」放進代理工作流的自動演化裡。兩頁可搭配讀:此頁講「編譯 Prompt 的原理」,EvoAgentX 講「把它用在會自我演化的代理系統」。

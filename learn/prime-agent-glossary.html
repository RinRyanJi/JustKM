⌨️ ① 基礎:程式執行

REPL Read–Eval–Print Loop
一個「你打一行、它馬上跑一行、立刻給結果」的互動環境。讀取(Read)你的輸入 → 執行(Eval)→ 印出(Print)結果 → 回到等你下一行(Loop)。
🌰 比喻:像跟計算機對話——按 2+3 立刻顯示 5,不用「寫完整個程式再一次跑」。▸ 在 Prime Agent:模型就是在一個 REPL 裡「打一段 Python、看結果、再打下一段」地工作。
Python
一種很常用的程式語言,語法接近英文、好讀好寫,資料處理與自動化的首選。
▸ 在 Prime Agent:模型主要用 Python 來讀寫檔案、跑指令、呼叫工具——「一切都是程式化的」。
IPython
一個「加強版的 Python 互動環境」(REPL)。比原生 Python 好用:有語法高亮、指令補全、還能用 %%bash 這類「魔法指令」。
🌰 比喻:普通 Python REPL 是陽春計算機,IPython 是有記憶、有快捷鍵的工程計算機。▸ 在 Prime Agent:每個 session 有一個持久的 IPython 環境,是模型唯一的內建工具(叫 ipython)。「IPython REPL」= 這個互動式的 Python 工作台。
Kernel(核心)IPython kernel
真正「跑你的 Python」的那個背景程式。你在介面打字,kernel 在背後執行並把結果送回來。
🌰 比喻:介面是「遙控器」,kernel 是「主機」。你按遙控器,主機做事。▸ 在 Prime Agent:kernel 是獨立的 process,第一次用到才啟動;變數會一直留著(跨對話回合)。
Namespace(命名空間)
一個環境裡「目前存在的所有變數與函式」的集合。
🌰 比喻:像你桌上攤開的所有文件與工具。▸ 在 Prime Agent:一個 kernel 一個共享 namespace,所以前面算出的變數,後面還能直接用。
Token(權杖 / 詞元)
LLM 處理文字的最小單位,約等於「一個詞或半個詞」。模型的輸入輸出、計費、context 上限都以 token 計。
🌰 比喻:像文章的「字數」,但切法是模型自己的。▸ 在 Prime Agent:compaction、成本、context window 全用 token 衡量。
Streaming(串流)/ delta(增量)
模型不是「整段一次吐出」,而是一小塊一小塊即時傳(每一小塊叫一個 delta),所以你會看到字一個個冒出來。
🌰 比喻:像直播 vs 錄好再上傳。▸ 在 Prime Agent:回應以 start → 一堆 delta → done 的事件流傳回,UI 邊收邊顯示。

🔌 ② 傳輸與協定(程式之間怎麼講話)

協定 / 協議 protocol
兩個程式溝通時「講好的規矩」——訊息長怎樣、誰先講、怎麼回。
🌰 比喻:像打電話的禮節:先「喂?」再報名字。▸ 在 Prime Agent:host 與 kernel 用 Jupyter 協定;client 與 daemon 用自訂的 daemon 協定。
Jupyter
一套跑互動式程式(尤其 Python)的生態,定義了「介面 ↔ kernel」怎麼傳訊息的標準協定。
▸ 在 Prime Agent:host 與 IPython kernel 之間就是走標準 Jupyter 協定(執行請求、輸出、中斷…)。
Socket(通訊端)
程式之間傳資料的「插座 / 管道」的兩端。一邊寫入、另一邊讀出。
🌰 比喻:像兩支對講機之間的頻道。▸ 在 Prime Agent:host 與 kernel 之間開了多個 socket(不同用途各一條)。
ZeroMQ ØMQ
一套「高效能訊息傳遞函式庫」,讓程式之間用 socket 快速、可靠地傳訊息。
🌰 比喻:像一套專業的「管路系統」,比自己接水管穩。▸ 在 Prime Agent:Jupyter 協定的訊息底層就是用 ZeroMQ 在 host↔kernel 之間傳。
通道 channel(shell / iopub / control)
同一對程式之間,依用途分開的幾條獨立管道。
🌰 比喻:像同一棟樓的「客用電梯 / 貨梯 / 消防梯」各走各的。▸ 在 Prime Agent:shell=送執行請求、iopub=收輸出、control=中斷與「host 回覆」。分開是為了避免塞車與死鎖。
Comm(通訊物件)Jupyter comm
Jupyter 裡一種「開一條臨時雙向小管道」的機制,讓 kernel 與 host 在執行中互相傳自訂訊息。
▸ 在 Prime Agent:模型在 Python 裡呼叫 rlm(...) 時,就是透過一個叫 host.request 的 comm 把請求送回 host。
HMAC-SHA256(訊息簽章)
用一把「共用密鑰」替每則訊息算一個指紋。收到時重算比對,指紋對得上才可信——確保訊息沒被竄改、來自對的人。
🌰 比喻:像文件上的防偽火漆印。▸ 在 Prime Agent:host↔kernel 的每則 JSON 訊息都用 HMAC-SHA256 簽章。
JSON / JSONL
JSON 是一種通用的資料格式(用 { } 表示鍵值)。JSONL = 一行一個 JSON 物件的檔案(JSON Lines)。
🌰 比喻:JSONL 像「一行一筆」的帳本,方便逐行讀、逐行append。▸ 在 Prime Agent:整個 session(對話紀錄)就存成一個 .jsonl 檔,每行一個訊息/事件。
SHA-256 checksum(校驗碼)
把一個檔案算成一段固定長度的「指紋」。下載後重算,對得上就代表檔案完整沒被動過。
▸ 在 Prime Agent:安裝腳本下載 release 後會驗 SHA-256,確保沒被掉包。

⚙️ ③ 程序與架構

Process(程序 / 行程)
作業系統裡「一個正在執行的程式」。彼此隔離:一個崩潰不會直接拖垮另一個。
🌰 比喻:像電腦上開的一個個獨立視窗/應用。▸ 在 Prime Agent:supervisor、每個 worker、每個 kernel 都是各自獨立的 process,故障才不會全倒。
Daemon(常駐程式 / 守護程序)
在背景默默常駐、不需要你盯著的程式。你關掉視窗它還在跑。
🌰 比喻:像大樓的中央空調主機,你回家了它還運轉。▸ 在 Prime Agent:daemon 讓 agent 在你關掉終端後繼續跑,之後可重新接上。
Supervisor(監督者)/ Worker(工人)
分工架構:supervisor 負責「調度、路由、看健康」;worker 負責「真正幹活」。
🌰 比喻:supervisor 是工頭(派工、點名),worker 是工人(做事)。▸ 在 Prime Agent:一個 supervisor 管多個 worker,每個 worker 跑一棵對話樹。
Attach / Detach(接上 / 卸離)
Detach=把「介面」跟「背景在跑的工作」分開(工作繼續);Attach=再把介面接回去看它。
🌰 比喻:像掛掉視訊但通話還在,之後再接回來。▸ 在 Prime Agent:關 TUI 只是 detach,agent 不停;prime-agent attach 再接回。
Lease(租約 / 佔用鎖)
一種「同一時間只准一個人用」的機制。誰先拿到租約,誰才能寫;別人得等。
🌰 比喻:像廁所門上的「使用中」牌子。▸ 在 Prime Agent:每個 session 檔有 lease,防止兩個 worker 同時寫壞同一份對話紀錄。
Idempotency(冪等)
「同一個操作做一次或做很多次,結果都一樣、不會出錯或重複扣款」的性質。
🌰 比喻:像電梯按鈕按一次跟按十次結果一樣。▸ 在 Prime Agent:指令用 clientId+commandId 當 key,重送已完成的指令只回原結果,不會重跑。
Journal(日誌 / 流水帳)
把「發生了什麼」按順序、只增不改地記下來的檔案,用來事後復原。
🌰 比喻:像航海日誌/黑盒子。▸ 在 Prime Agent:指令與狀態轉移先寫 journal,崩潰後靠它還原、且不重播不確定的副作用。
Snapshot(快照)/ Replay(重播)
Snapshot=某一刻的完整狀態存檔;Replay=把中間發生的事件重新播一遍追上進度。
🌰 比喻:snapshot 像遊戲存檔,replay 像看回放補進度。▸ 在 Prime Agent:重新接上時,先套用 snapshot 當基準,再補上缺的事件;補不到也沒關係。
Backpressure(反壓 / 回壓)
當接收方來不及處理時,系統「放慢或暫停供給」以免爆掉的機制。
🌰 比喻:像水管下游塞住,上游要減壓。▸ 在 Prime Agent:某個卡住的 client 只會自己收不到增量,不會拖累其他 client 與 worker。
Bootstrap / venv / uv
Bootstrap=首次自動把環境準備好;venv=Python 的「獨立小環境」(不污染系統);uv=一個很快的 Python 套件/環境工具。
▸ 在 Prime Agent:第一次用到 kernel 時,用 uv 自動 bootstrap 一個含 ipykernel 的 venv。

🤖 ④ Agent 概念

Tool calling / Function calling(工具呼叫)
讓模型不只吐文字,還能「請系統幫我執行某個動作(函式)並回結果」的能力。是 agent 的基礎。
🌰 比喻:像助理不只回你話,還能真的幫你「訂餐廳」。▸ 在 Prime Agent:模型的主要工具是 ipython——它「呼叫」的就是跑 Python。
Agent / Subagent(代理 / 子代理)
Agent=會自己規劃、呼叫工具、多步完成任務的 AI。Subagent=某個 agent 為了子任務而開的另一個小 agent。
🌰 比喻:主管(agent)把工作分派給下屬(subagent)。▸ 在 Prime Agent:在 Python 裡 rlm("子任務") 就 spawn 一個 subagent。
RLM Recursive Language Model
Prime Agent 的核心理念:把「上下文當變數、工具與子代理當函式呼叫」,全部在一個持久 Python 環境裡組合;子代理還能再開子代理(遞迴)。
🌰 比喻:像一個會寫程式的助理,能在腳本裡再叫更多助理。▸ 在 Prime Agent:就是它整套運作的骨架。
遞迴 recursion
「東西自己包含同類的自己」——例如一個代理再開一個同類的代理,可以一層層下去。
🌰 比喻:像兩面鏡子對照、俄羅斯娃娃。▸ 在 Prime Agent:子代理可再開子代理,有「深度上限」防止無限展開。
非阻塞 / fire-and-forget(送出就不等)
發出一個請求後不站在原地等結果,先繼續做別的,結果之後再來。
🌰 比喻:像寄出一封信就去忙,回信之後再看,而不是站在信箱旁等。▸ 在 Prime Agent:rlm(...) 立刻回一個「收據」,子代理的答案之後才透過訊息或檔案回來——所以能平行養很多子代理。
async / await(非同步 / 等待)
寫並行程式的語法:async 標記「這件事可以並行」,await 標記「這裡要等它好」。
▸ 在 Prime Agent:你會看到 await rlm(...)——這裡的 await 只等「任務被接受」,不等答案。
Context window(上下文視窗)
模型「一次能看的最大文字量」(以 token 計)。超過就得取捨,不能無限塞。
🌰 比喻:像人的短期記憶容量。▸ 在 Prime Agent:快滿時觸發 compaction。
Compaction(壓縮 / 精簡)
對話太長、context 快爆時,把舊訊息摘要成一段、只保留最近的原文,騰出空間繼續。
🌰 比喻:像把厚厚的會議紀錄濃縮成重點摘要。▸ 在 Prime Agent:自動觸發或 /compact;Python 變數不受影響,只精簡對話。
Heartbeat(心跳)/ Schedule(排程)/ Autonomous(自主模式)
Heartbeat=週期性自動再進來看一下;Schedule=在指定時間/cron 觸發;Autonomous=在設定的預算內自己一直做下去。
▸ 在 Prime Agent:都是「長時間任務」的續跑機制,走跟你手動下 prompt 完全相同的路徑。
Harness(執行框架 / 承載層)
包在模型外面、讓它能真正做事的那層「骨架」:管工具、記憶、流程、狀態。
🌰 比喻:模型是引擎,harness 是整台車(方向盤、油箱、儀表)。▸ 在 Prime Agent:「Continual Harness」還能自我精煉(/refine)存下的提示/記憶/技能。

🧩 ⑤ 模型與介面

LLM Large Language Model
大型語言模型——用海量文字訓練、能理解與生成語言的 AI(如 GPT、Claude、Gemini)。
▸ 在 Prime Agent:就是背後做決策、寫程式的「大腦」,可中途換家。
Provider / API / Model(供應商 / 介面 / 模型)
Provider=哪一家(OpenAI、Anthropic…);API=用哪種線上協定;Model=具體哪個模型。
🌰 比喻:Provider=電信公司,API=通訊制式(4G/5G),Model=你選的方案。▸ 在 Prime Agent:packages/ai 用這三層把 20+ 家統一成同一套呼叫。
Thinking / Reasoning(思考 / 推理)
某些模型會先「內心演算一段」再給答案,這段中間思考叫 thinking/reasoning。
▸ 在 Prime Agent:跨家換模型時,異家的 thinking 會轉成 <thinking> 標記文字以保相容。
MCP Model Context Protocol
一套「讓 AI 連接外部工具/資料源」的標準協定,像給 AI 裝外接擴充的通用插槽。
▸ 在 Prime Agent:可透過 MCP 接入外部工具;技能與 provider 也能整合。
TUI / CLI / Headless / RPC
CLI=在終端打指令用;TUI=終端裡的圖形化介面;Headless=沒有介面、給程式自動化用;RPC=程式間互相呼叫的協定。
▸ 在 Prime Agent:互動用 TUI;自動化用 print/JSON/RPC 等 headless 模式。
OAuth / API key / credential(憑證)
證明「你有權用某服務」的東西。API key=一串密鑰;OAuth=用你的帳號授權登入(如「用 Google 登入」);credential=兩者統稱。
▸ 在 Prime Agent:/login 選 provider,金鑰存在 auth.json。

🖥️ BilldDesk:WebRTC 的開源跨平台遠端桌面

galaxy-s10 做的跨平台遠端桌面控制(和 CrossDesk 同賽道,對標 ToDesk/向日葵/RustDesk)。底層用 WebRTC 做 P2P 端對端音視訊 + 控制指令,搭自研的信令與 Coturn 中繼;桌面端 Electron + Vue3 + TS,行動端 Flutter。但有個一定要先搞清楚的分野:開源版(BilldDesk,MIT,真開源但一人維護、未發穩定版) 與 Pro(完全重寫、更穩更強,但原始碼閉源、需付費訂閱) 是兩個東西——很多亮眼功能其實在 Pro。

⓪ 一句話總結

一個「用 WebRTC 做的、能自建的跨平台遠端桌面」,但它其實是一對雙胞胎。連線走 WebRTC P2P(端對端傳音視訊與控制指令),網路允許時直連、降延遲與伺服器頻寬;信令與中繼(Coturn)自研、可自建,所以能私有化部署。桌面端 Electron+Vue3,行動端 Flutter,連瀏覽器都能當主控端。但使用前請先認清:真正 MIT 開源的是「BilldDesk 開源版」(一人開發、至今未發穩定版、每次 commit 可能破壞性更新),而你看到的那串華麗功能(屏幕牆、隱私屏、虛擬屏、硬體編解碼矩陣、2K120)大多屬於「BilldDesk Pro」——Pro 免費用,但原始碼閉源、要付費訂閱。

為什麼開場就講這個:坊間介紹常把「MIT 開源」和「完整功能清單」寫在一起,容易讓人以為「clone 下來就有屏幕牆、2K120、隱私屏」。實際上開源版與 Pro 是兩套程式(Pro 是完全重寫、閉源)。這頁會把哪些是開源版、哪些是 Pro 標清楚——這也是它和 CrossDesk 最值得對照的地方。GitHub galaxy-s10/billd-desk,網頁版 desk.hsslive.cn。

① 開源版 vs Pro:一定要先分清楚

作者在 README 講得很坦白(摘要):BilldDesk 是 2024/2/28 起、一人開發的專案;它確實是開源(MIT),但從未發布穩定版,master 被當 dev 用,每次提交都可能不相容舊版——所以很多人反映「跑不起來」。後來作者完全重寫成 BilldDeskPro,修掉開源版在現有架構下「幾乎不可修復」的權限與控制問題,更穩更快,但 Pro 原始碼不開源、需付費訂閱(Pro 對一般使用者免費使用)。

② 技術架構:WebRTC + 一整套現代前端棧

和 CrossDesk「自研 C++ 傳輸庫(MiniRTC)」不同,BilldDesk 走的是瀏覽器原生的 WebRTC + WebCodecs 路線,所以天生對「網頁端」友善。各端技術棧(開源版 README):

層技術
前端 / 網頁Vue3 + TypeScript、WebRTC、WebCodecs、Web Worker、Web Audio、Canvas
桌面客戶端Electron + WebRTC
行動端Flutter(Dart);原生能力觸及 Win32 / Cocoa / Android AccessibilityService
後端 / 信令Node.js + Koa2 + TypeScript、Sequelize、MySQL、Redis、Socket.io(信令)
中繼 / 串流Coturn(STUN/TURN)、SRS、FFmpeg

語言面很雜(JS/TS、Dart、Kotlin、C++、Swift),因為要在各平台觸及原生的螢幕擷取與鍵鼠注入能力。核心傳輸則交給 WebRTC——這讓「用瀏覽器當主控端」幾乎是免費得到的能力。

③ 連線模型與自建生態

連線邏輯和一般 WebRTC 遠端桌面一致:兩端先經信令(Socket.io)交換連線資訊,然後試 P2P 直連(ICE 穿透),打不通就走 Coturn 中繼。這些伺服器都開源、可自建,所以能把整條連線關在自己內網裡。

▲ 生態由四個 repo 組成:billd-desk(網頁/客戶端)、billd-desk-flutter(行動端)、billd-desk-server(信令服務端)、billd-desk-admin(後台)。全部開源、可自建。

④ 全平台與「誰控誰」矩陣

支援 Windows(10/11、Server 2019/2022)、macOS 15、Android 8–16、以及 Web 瀏覽器(Chrome/Edge/Firefox/Safari/Via);iOS 與 Linux 標在 roadmap。最大的賣點之一是瀏覽器就能當主控端——不用裝任何東西就能遠端控制。

「誰能控誰」在 Pro 已經相當完整(web/電腦/安卓三種主控端 × 電腦/安卓/web 被控,web 被控為僅觀看);但在開源版裡,README 誠實標明電腦端↔電腦端、電腦端↔安卓等多條路徑仍「重構中/後續支持」,目前以「web 控電腦/安卓/web」為主可用。這又是一個開源版 vs Pro 的落差點。

⑤ 遠端控制功能全景(多數為 Pro)

功能清單很長,這裡整理並標出哪些主要在 Pro:

類別功能
基礎控制多屏操作、碼率/幀率/畫質調整、按鍵映射、剪貼簿同步、解析度同步、文字互動、連接鑑權、自訂設備碼/連接密碼
檔案 / 快捷鍵雙向檔案傳輸(主控↔被控)、系統快捷鍵(Ctrl+Alt+Del、鎖定、重啟、關機、注銷、任務管理器…)
隱私 / 無人值守本機被控結束後鎖屏、僅允許同帳號遠程、開機自啟(無人值守)、進程保活、系統托盤、遠程開機 WOL
Pro 亮點(多為付費功能)隱私屏(可自訂圖片/文字)、虛擬屏、屏幕牆(單控/群控)、批量群控、遠程時錄屏、驅動級鍵鼠(避免遊戲風控)、滑鼠模式(主控/被控/智能)、虛擬聲卡、後台管理
網路 / 幀率預設 / 低延遲網路模式;智能降幀(依畫面變化省頻寬)
讀法:前兩三列的基礎能力開源版多半有;「Pro 亮點」那列(屏幕牆、隱私屏、虛擬屏、驅動級鍵鼠…)README 標在 BilldDesk Pro,且其中隱私屏/虛擬屏/屏幕牆/高碼率幀率屬付費功能(Pro 包月 6 元/包年 4.2 元/月)。

⑥ 硬體編解碼與效能(Pro 實測)

Pro 的效能數字相當猛(README 實測,被控端為對應顯卡):

畫質 / 幀率被控端顯卡
2K + 120 FpsWindows 11,NVIDIA RTX 5070
2K + 60 FpsWindows 10,NVIDIA RTX 3060 Laptop
1080P + 60 FpsWindows 10,RTX 2070 Laptop / GTX 1060 6G
  • 硬體加速:可開關編碼/解碼硬體加速與零拷貝;NVIDIA(需十代以上、驅動 570.0+)、AMD、Intel 集顯都支援 H264/H265/AV1;Apple VideoToolbox 支援 H264。
  • 編解碼協定:H264/H265、AV1、VP8/VP9。

相比之下,開源版因為走 WebRTC/WebCodecs,編解碼能力受瀏覽器/平台能力約束;上述「2K120 + 完整硬體矩陣」是 Pro 的本事。

⑦ 私有化部署與生態

開源版 README 明寫「billd-desk 完全開源(可商用),歡迎部署」——這是它真正的價值:把前端、客戶端、Flutter、信令服務端、Coturn 全部在自己機器上跑起來,連線隱私與頻寬自己掌握,適合企業內網或個人高隱私場景。技術棧對前端工程師友善(Vue3/Koa2/Socket.io),二次開發門檻相對低。

現實提醒:開源版未發穩定版、master 當 dev、破壞性更新頻繁,作者自己都說不建議生產用;「Docker 一鍵部署」在清單上還是未勾的待辦。所以自建開源版要有「它是個活躍但不穩定的 WIP」的心理準備(跑不起來可試切到其他 commit)。要「開箱穩定」就用 Pro 客戶端(但那不給源碼)。下載:desk.hsslive.cn/#/download。

七個帶得走的重點

  1. 開源版(MIT)≠ Pro(閉源付費)——這是用 BilldDesk 的第一件事。
  2. 傳輸走瀏覽器原生 WebRTC + WebCodecs,所以「網頁當主控端」很自然。
  3. 技術棧現代:Vue3 + Electron + Flutter + Koa2 + Socket.io + Coturn。
  4. 連線:信令交換 → P2P 直連,打不通走 Coturn 中繼,皆可自建。
  5. 全平台(Win/mac/Android/Web;iOS/Linux roadmap),瀏覽器免安裝控制。
  6. 華麗功能(屏幕牆/隱私屏/虛擬屏/硬體編解碼矩陣/2K120)多在 Pro,部分付費。
  7. 開源版未發穩定版、破壞性更新,作者不建議生產用;要源碼選它、要開箱選 Pro 客戶端。

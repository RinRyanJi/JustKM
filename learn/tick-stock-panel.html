📊 TSP:自託管、本地優先的 A 股量化研究工作台

Tick Stock Panel 不走同花順、通達信那種看盤軟體路線,而是一個本地優先(local-first)、零運維、核心能力全開放成接口的 A 股量化研究工作台:用 Polars 向量化對全市場選股、用自研引擎做約束回測、寫自訂因子、盤中監控、盤後接 AI 做復盤。資料與策略都在你機器上,外部腳本與 MCP 可按權限呼叫它的數據與研究任務。工作台 MIT(自研 Tivelo 組件另採 PolyForm 非商業授權)。

⓪ 一句話總結

一個「自己架、自己掌握數據」的 A 股量化研究台。它把量化研究的四件事——選股、回測、因子、監控——收進一個自託管工作台:用 Polars 的 Rust 列式內核對全市場高速算指標、篩條件;用自研的 Tivelo 回測引擎按 A 股 T+1、漲跌停、手續費等真實約束模擬成交;盤中監控訊號彈窗/語音/推播,盤後接 AI 自動出 Markdown 復盤報告。行情、策略、配置都存在你本機的 data/,外部腳本與 MCP 客戶端可拿帶權限分級的 Token 來呼叫。

它在這份筆記裡的位置:和 openGym 一樣是「本地優先 + 可選 AI + 開放 MCP」的自託管 app,只是領域換成 A 股量化研究。官網 tsp.shy313.com,GitHub shy3130/tick-stock-panel。技術棧:Python 3.11+ / Node 20+ / React 18 / Polars 1.44。

① 定位:研究工作台,不是荐股/看盤

README 把範圍講得很清楚,這點很重要:TSP 面向本地量化學習與研究,走獨立研究工作台路線,不對標同花順/通達信等看盤軟體,產品範圍不含「AI 荐股」與「漲停預測」。裡頭的 AI 助手只用來取數、分析與策略研究,不是叫你買哪支。

為什麼強調這個:量化工具最容易被誤解成「幫我預測明天漲什麼」。TSP 刻意把自己定位成「研究環境」——給你高速算指標、嚴謹回測、可檢驗因子的地方,結論與風險由你自己負責(見 ⑧ 的免責聲明)。

② 選股與回測引擎:快,且算得嚴謹

  • Polars 向量化選股:行情整理、指標與因子計算、回測面板準備都走 Polars 1.44 的 Rust 列式內核;支援 Numba 的環境裡,部分回測矩陣的滾動/遞推算子用 JIT 加速。對全市場 A 股做高速指標計算與條件篩選。
  • 約束回測:支援歷史區間回測、參數篩選、滾動樣本外(walk-forward)驗證,可檢視淨值曲線、回撤、夏普與逐筆成交記錄,並調整撮合費用、滑點與風控。
  • 因子平台:自訂因子公式、因子檢驗、因子挖掘,用自訂信號與策略篩股票池。
一個實測數字:同機、同策略的 15 組參數網格 A/B 基準裡,「逐組獨立準備」vs「共享行情面板 + 矩陣編碼」總耗時分別是 19.47 秒 vs 6.19 秒——共享後省約 68%,而逐筆成交與統計結果一致。這說明它在「參數掃描」這種重複計算場景上做了面板共享優化。(數字引自 README,單機量測、當量級參考)

③ 自研 Tivelo 引擎:資料版本化 + 真實撮合

回測可不可信,取決於「資料乾不乾淨」和「撮合像不像真的」。TSP 把這兩件事拆成兩顆自研引擎,都能用 Python 庫或命令列獨立使用:

引擎負責
Tivelo Data採集、校驗、發布資料版本;可把日 K 與復權因子固定成快照,供策略復跑與歸檔研究(確保「同一份資料」重現)
Tivelo Backtest為日線/分鐘策略與組合回測提供撮合與記賬,按 A 股 T+1、漲跌停、交易費用等約束模擬成交

工作台普通回測支援前復權/後復權;啟用並授權 Tivelo Pro 後,A 股日線策略還能直接選動態復權。歸檔研究會先檢查「資料快照 + 策略歸檔」是否匹配再提交任務——這套「資料版本 + 快照回測」是嚴肅量化研究避免「未來函數/資料漂移」的關鍵。

④ 盤中監控 + 盤後 AI 復盤

  • 監控中心(Monitor):支援策略訊號、個股訊號、價格、市場異動四大類規則,盤中觸發即時彈窗、語音播報,並可推送到飛書或企業微信。通過驗證的策略可綁到模擬盤,追蹤訂單、持倉與成交。
  • AI 復盤與分析:可接兼容 OpenAI 格式的模型服務,或本機的 Codex CLI,自動做個股/財務分析與定時盤後市場復盤,輸出 Markdown 報告。
  • 工作台 AI 助手:⌘K / Ctrl+K 打開,在面板內查本地行情、起草策略、跑回測;寫入由確認設定控管。

⑤ 高度模組化與插件

TSP 的「核心能力全開放成接口」體現在插件化:日 K、分鐘 K、實時行情、除權因子可分別指定不同資料源(內建支援 TickFlow、免費接口或自訂 HTTP 資料源插件)。能擴充的東西很全:

要擴充什麼怎麼接
行情來源宣告 HTTP YAML,或裝含 plugin.yaml 的 Provider ZIP
擴充資料導入單表配置,接自有欄位、回補與更新規則
策略/信號/因子導入源碼、定義 JSON 或帶依賴的資源 ZIP
圖表/資訊條導入 tick-chart-indicators JSON,用公式與擴充欄位定義日 K/分時/資訊條
頁面與選單Page Pack SDK:開發自有頁面(復用行情接口與公共個股詳情),或導入 .js/.mjs/.tsx
後端插件/倉位規則導入帶 extension.yaml 的後端 ZIP 後重啟;可寫自訂倉位策略

源碼擴充可註冊路由與導航,在個股詳情、自選頁等「已開放的插槽」加元件;後端可註冊獨立接口、啟動鉤子與通知格式化器。配置備份能遷移策略、偏好與擴充表配置。

⑥ MCP 與開放接口:帶權限分級的 Token

這是它「開放成接口」最直接的體現:腳本與外部 AI 可通過 Open API 或 MCP,按 Token 權限(Scope)讀行情、查策略、提交回測。

▲ 兩條入口:登入會話(給人用的面板)與 Token 網關(給腳本/MCP 用,按 Scope 限權)。核心共用本地 data/,重活丟給 Tivelo 兩引擎。

⑦ 快速開始

# Docker:行情/策略/配置存在當前目錄的 data/
docker run -d --name tsp -p 3018:3018 \
  -e DATA_DIR=/app/data -v "${PWD}/data:/app/data" \
  ghcr.io/shy3130/tick-stock-panel:latest
# 開 http://localhost:3018

也能用桌面版安裝包(Releases)、Docker Compose(docker compose up --build),或源碼(Python 3.11+ / Node 20+ / uv / pnpm,跑 ./dev.sh)。第一次:設定資料源 → 同步日 K/指標 → 建或導入策略(先篩選再區間回測)→ 通過驗證的規則用於監控或模擬盤;外部客戶端在「設置 → 開放接口」領對應權限的 Token。

⑧ 授權 · 風險 · 重點 · 來源

授權分兩層:TSP 工作台採 MIT;但自研的 Tivelo 組件按各自制品授權——採 PolyForm 非商業授權的 Tivelo 自有實現,商用須另獲書面授權(已授予的 MIT 權利繼續有效)。分發時須保留版權與授權文本,貢獻走 DCO。

投資風險:本項目僅供學習與量化研究,回測結果不代表未來收益、不構成投資建議;用數據前請讀供應商條款。

七個帶得走的重點

  1. 本地優先、自託管、零運維的 A 股量化研究台——不荐股、不預測漲停。
  2. Polars 向量化全市場選股;參數掃描靠共享面板省約 68%。
  3. 自研 Tivelo Data(資料版本/快照)+ Tivelo Backtest(T+1/漲跌停/費用撮合)。
  4. 回測嚴謹:walk-forward、快照回測、動態復權,避免未來函數/資料漂移。
  5. 盤中 Monitor(四類規則→彈窗/語音/飛書企業微信)+ 盤後 AI 復盤出 Markdown。
  6. 高度模組化:行情源/因子/頁面(Page Pack SDK)/後端插件都可擴充。
  7. MCP + 開放接口,帶 Scope 權限 Token 給腳本/外部 Agent 呼叫。

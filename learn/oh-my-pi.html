⓪ 一句話總結

oh-my-pi（指令名 omp）是一個「電池全內建」的 AI 編碼 Agent：把互動式終端 UI、可擴充的工具系統、多模型支援，與約 8 萬行 Rust 核心整合成單一平台。它把許多在別家 agent 只是「外掛」或根本沒有的能力——LSP 串進每次寫入、真正的除錯器控制、瀏覽器/桌面自動化、跨 session 記憶——做成原生第一等公民。

💡 定位：它自我定位為「團隊不會用膩、也長不出去的 harness」——terminal-first、深度整合、為認真的生產級編碼而設計。是 Mario Zechner Pi 專案的 fork。

① 它解決什麼問題

現有 AI 編碼 agent 的能力常是零散的外掛（bolt-on）、或整合得很淺：改個名字不會自動傳播、沒有真除錯器、記憶不跨 session、要跑指令得每次 fork 一個 shell…omp 的主張是——把這些「本該內建」的能力做成原生、深整合、開箱即用。

  • 編輯了程式 → LSP 立刻串動(rename/refactor 自動傳播),而不是只改字串。
  • 要 debug → 直接控制 lldb / dlv / debugpy,設斷點、看變數,而非用 print。
  • 跑 shell → 持久 session、in-process 執行,不必每次 fork/exec。
  • 換模型 / 分工 → 角色路由,一個任務不同節點用不同模型。

③ 核心架構:為什麼「快」與「深」

omp 跑一個常駐的 agent session,透過工具呼叫來編排工作。當模型要求動作(讀檔、改碼、跑指令),agent 路由到原生實作——而且大多數操作(grep、glob、shell)是在 libuv thread pool 上 in-process 執行,而非 shell out。

模型要求動作 ─► omp agent 路由 ─► 原生實作（多數 in-process，libuv thread pool） │ │ │ 消除 fork/exec 開銷；bash 等工具能跨呼叫保留 session 狀態 ▼ TUI 把工具執行渲染成「卡片」（破壞性操作先預覽） │ 模糊需求 → 觸發 ask 結構化選擇器（turn 中途詢問） ▼ 編輯先 stage 再 land ─► agent 用 xd://resolve 解釋改動 ─► TUI 原子確認

④ 六大特色群

1 · 開發整合(把 IDE 能力做成原生)

  • LSP 串進每一次寫入:rename/refactor 自動傳播。
  • 真除錯器控制:lldb、dlv、debugpy——設斷點、檢視變數。
  • 瀏覽器自動化:真 headless Chromium,或接管你現有的 Chrome 分頁。
  • 桌面自動化:截圖、視窗控制、accessibility tree。

2 · 編碼工具(31 個內建)

  • Content-hash-anchored edits:用內容雜湊錨定的編輯,檔案漂移也不會改錯位置。
  • ast-grep 結構化重寫:跨 50+ 語言文法做語法樹層級的改寫。
  • 持久 shell session + 46 個 in-process coreutils:無 fork/exec 開銷。
  • Python / JavaScript 評估 kernel:能回呼agent 的工具。

3 · Agent 能力

  • Subagent fan-out + 型別 schema 驗證(平行分工、結構化輸出)。
  • 平行 code review + 優先級排序(P0–P3)。
  • 第一等記憶系統:facts、lessons、managed skills,跨 session保留。
  • Time-traveling stream rules:在 token 中途即時修正方向,不吃 context 稅。

4 · 多模型支援

  • 60+ 供應商:前沿 API、coding plan、本地伺服器都涵蓋。
  • 角色路由(role-based routing):default、smol、slow、plan、vision、advisor…不同角色配不同模型。
  • Per-repo 模型釘選:不動全域設定,就能替某個 repo 固定用某模型。

5 · 協作

  • 即時 session 分享:relay link + QR code。
  • 讀寫 / 唯讀兩種協作模式;可用瀏覽器檢視 session。

6 · 相容與擴充

  • 繼承 .cursor / .claude / .cline 既有設定,免遷移。
  • TypeScript 外掛可擴充;整套可在 Node 宿主。

⑤ 幾個「別家少見」的亮點

亮點為什麼重要
Content-hash-anchored edits傳統「行號/字串比對」的編輯,一旦檔案被改動就容易打錯位置;用內容雜湊錨定,編輯能撐過檔案漂移,大幅降低改錯風險。
In-process coreutils / shellgrep、glob、bash 等在行程內跑,省掉 fork/exec 開銷,還能跨呼叫保留 shell 狀態(cd、環境變數不會丟)。
Time-traveling stream rules能在模型還在吐 token 的當下就修正方向,不必等整段輸出完再重來——省 context、省 token。
Role-based routing把「規劃、視覺、快答、顧問」等角色各自路由到最合適的模型;呼應「大模型規劃、小模型雜活」的成本策略。
ast-grep 結構化重寫改的是語法樹而非文字,跨 50+ 語言做安全的結構重構,不會誤傷字串。
⚠️ 成熟度提醒：omp 標示為「持續被真實使用調校中」,且目前PR 對所有人開放作為試驗。功能與細節可能快速變動,以 repo 最新為準。文中效能數字(如某模型輸出 token 少 61%、Gemini 3 Flash +5pp)為專案自述基準,情境相依。

⑥ 怎麼開始用

安裝(macOS / Linux)

shell 
curl -fsSL https://omp.sh/install | sh

也支援 Homebrew、Bun、Windows PowerShell;可用 mise 釘選版本。

基本操作

  • omp 開啟 TUI;輸入 prompt,agent 執行工具並以「卡片」顯示結果。
  • omp -p "…" 一次性 CLI 模式。
  • Slash 指令改變 session 行為:/model、/collab、/review…
  • Magic keywords 觸發特殊推理 / 子代理工作流:ultrathink、orchestrate、workflowz。
💡 上手最快路徑：因為它會繼承 .claude / .cursor / .cline 的既有設定,若你已在用這些工具,幾乎可以無痛切過去試。安裝腳本會下載一個外部 shell script 執行,建議先讀過再跑。

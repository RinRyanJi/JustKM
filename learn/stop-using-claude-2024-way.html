🗓️ 別再用 2024 年的方式用 Claude:Anthropic 工程負責人談思維轉變

一支訪談摘要:當模型能力大躍進後,很多「2024 年的好習慣」反而變成拖累。Anthropic 的 Claude 工程負責人提出該淘汰的舊用法(角色扮演、繁瑣 Skills 條框、孤立數據切片),以及新的協同工作流(高頻原型、紅藍對抗治幻覺、隱性知識沉澱成準則),並談到「能力增強 > 自動化」與商業壁壘的轉移。本頁把這些觀點整理成可操作的教學。

⓪ 一句話總結

模型變強了,你的用法要跟著升級;很多舊技巧現在是反效果。核心轉變是:少「框住」模型、多「給它全景並放手」。別再開頭寫「你是一位資深分析師」,別再堆為上一代模型定制的繁瑣約束,也別把資料切碎了餵——改成給完整環境 + 清楚的工具說明,讓模型自主排查。品質則靠紅藍對抗(多個對抗實例挑錯 + 獨立裁判)而不是讓它自評。

怎麼讀這頁:這是一支訪談的觀點整理,不是官方文件;人名/頭銜/數字都以影片所述為準(見 ⑧)。想要更成體系、對照官方文件的進階技巧,搭配站內 頂尖 AI 編程者進階全圖 一起看。

① 要淘汰的三個 2024 舊習

← 左右滑動看完整圖 →
▲ 三個舊習有同一個病根:都在「替模型預設框架」。新模型夠通用,框架常是多餘的枷鎖。

1. 別再「角色扮演」

在提示詞開頭寫「你是一位資深資料分析師」這類頭銜,是一種心理偷懶。現代頂尖模型是通用全能的;硬塞職業頭銜,反而容易讓它陷入形式化、滿嘴術語卻削弱實際執行力的泥沼。直接把任務、脈絡、要什麼講清楚更有效。

2. 拋棄過時的 Skills / 繁瑣條框

特別為上一代模型定制的短期技能約束,在更新一代的模型上往往可以直接刪除,讓模型發揮更強的自主性。定期回頭檢視:哪些規則其實是在補舊模型的短板?新模型不需要了就拿掉。

3. 拒絕孤立的數據切片

不要把資料切得碎碎的餵給 AI。盡量提供完整的全局數據環境 + 清晰的工具調用說明,讓模型擁有全景視野去自主排查,而不是在你預先切好的局部裡盲人摸象。

② 新用法的共同原則:少框住、多給全景、再放手

把 ① 的三點串起來,其實是同一條原則。2024 的直覺是「怕模型做不好,所以替它設好角色、規則、切好資料」;現在的直覺應該反過來:

  • 信任能力:預設模型能處理複雜、完整的情境,除非證明它不行,才加約束。
  • 給環境而非給答案框架:把「全局資料 + 可用工具 + 目標」擺好,讓它自己決定怎麼查、怎麼做。
  • 約束要能被淘汰:每條規則/Skill 都該定期問「新模型還需要嗎?」,不需要就刪。
一句心法:從「幫模型想好每一步」轉成「給它舞台和工具,然後檢驗結果」——後者的槓桿大得多。

③ 高頻原型探索:生成上千變體,人類來挑

當「構建時間與維護成本」被壓到極低,開發方式就變了:與其精雕一個原型,不如讓模型快速生成上千個產品原型變體,人類再從中挑選、評估。軟體開發進入極簡的高頻迭代——先大量發散,再快速收斂。

  • 人類的角色從「建造者」變「評審/品味提供者」:你的價值在於判斷哪個變體對、為什麼對。
  • 可拋棄式原型:因為構建便宜,原型可以用完即丟,不必背維護包袱。

④ 紅藍對抗治幻覺:別讓它自評

解決幻覺的關鍵心法:永遠不要讓同一個 Claude 實例去「自我評審」——它會偏袒自己剛產出的東西。正確做法是分離「做」與「審」:

⑤ 把隱性知識沉澱成準則

你每天給出的歷史批改意見、溝通反饋,其實是寶貴的隱性知識。做法:把這些餵給模型,讓它提煉成核心業務準則與評判清單(rubric),之後就能當作自動化把關與品質審查的標準。

  • 把「我每次都會抓的錯」變成清單:讓紅隊/裁判(④)照這份清單審,品質才穩定。
  • 準則會複利:用得越久、修得越準,等於把你的判斷力外部化成可重複使用的資產。
這其實就是 Claude Code 的 skills / 評審 rubric 的精神——但重點是「從你真實的反饋裡長出來」,而不是憑空寫一堆規則(呼應 ① 的「別堆繁瑣條框」)。

⑥ 自動化 vs 能力增強:後者才是顛覆

一個重要的區分:

已經會的事做更快 停在同一層,省時間 價值:效率 能力增強(Augmentation) 跨界做過去做不到的事 例:指揮 Claude 用 Blender 做出高品質 3D 動畫 價值:能力躍升(顛覆性)
▲ 自動化讓你跑更快;能力增強讓你去到以前到不了的地方。真正的槓桿在後者。

自動化只是幫人消除耗時雜物;而真正的顛覆性在於「能力增強」——讓人跨界完成過去遙不可及的事。例子:不會 3D 建模的人,也能直接指揮 Claude 調用專業開源軟體(如 Blender)製作高品質 3D 動畫。重點不是「省下建模時間」,而是「本來根本做不到,現在做得到」。

⑦ 商業壁壘的轉移:當執行成本趨近於零

當執行成本被壓縮到接近於零(影片觀點:一兩個人的極簡團隊也有潛力做出 10 億美元級別的企業),「能不能把東西做出來」就不再是護城河——因為大家都做得出來。競爭優勢會整個移到:

  • 對用戶的深刻「同理心」:誰更懂使用者真正的痛、真正想要什麼。
  • 對傳統實體產業痛點的洞察:誰看得到那些還沒被數位化、還很痛的真實問題。
怎麼看待這段:這是訪談者的前瞻觀點與推論,不是既成事實——「10 億美元/兩人團隊」是用來凸顯「執行力不再稀缺、洞察力才稀缺」的誇飾。當成思考方向,別當成保證。

⑧ 帶走清單 · 關聯 · 來源

七條可以今天就改的

  1. 刪掉提示詞開頭的「你是一位 OO 專家」——直接講任務。
  2. 回頭檢視你的 Skills/規則,把為舊模型補短板的那些拿掉。
  3. 別切碎資料;給全局環境 + 工具說明,讓它自主排查。
  4. 預設信任能力:先放手,證明不行才加約束。
  5. 要品質就高頻生成多個變體,你來當評審。
  6. 幻覺用紅藍對抗治:5–10 個對抗實例(可小模型)+ 獨立裁判,絕不自評。
  7. 把你的歷史反饋煉成 rubric,當自動化把關標準。

⓪ 一句話總結

VoxEMW 是一套「完全本地離線」的即時語音對話數字人:從語音輸入到「數字人開口 + 嘴型對上」全程 ≈1.3 秒,跑在單張 RTX 4090 上,零外部 API、零 token 費用。它把即時對話拆成 VAD → STT → LLM → TTS → Avatar 五段流水線,再加一個 Persona 人設蒸餾模組。

真正的看點不是「某個模型」,而是「延遲預算工程」:怎麼把五個 AI 模組的延遲一段段壓到毫秒級、又靠串流與語義判停讓對話「像真人」。這是本頁的重點。

① 為什麼「即時對話」難

人類對話中,超過 ~1 秒 的回話延遲就明顯「卡頓、像在等機器」。但一句 AI 回話要串起五件事——判斷你講完沒 → 聽懂 → 想答案 → 合成聲音 → 對上嘴型——每一步都要吃時間、又都要跑 AI 模型。難點是:

  • 延遲會累加:五段串起來,任何一段慢就毀了整體;
  • 不能等全部做完:若「等 LLM 整段答案生成完才開始合成語音」,延遲會爆;
  • 判停兩難:太快接話會搶話/掉字,太慢又尷尬;
  • 全本地又要快:不能靠雲端大模型,得在一張卡上塞下所有模型還要即時。

VoxEMW 的答案:每段都串流 + 只等「首句/首音」+ 兩階段語義判停。

③ LLM 大腦Qwen 3(8–27B,llama.cpp)~0.8s 首句串流輸出,只等首句
④ TTS 合成VoxCPM2(音色遷移)~0.1s 首音串流合成,只等首音
⑤ Avatar 對齊AVTR-1(TensorRT)~0.2s唇形即時驅動同步
核心招式:「首 token / 首音」而非「整段」。LLM 一產出第一句就餵給 TTS;TTS 一合成第一段音就餵給 Avatar 對嘴。於是使用者感受到的延遲 ≈ 各段「首個輸出」的時間和,而不是「各段全部做完」的時間和——這就是把 1.3s 壓下來的關鍵。

③ 六模組逐一

① VAD 判停:兩階段接力 + 語義複核

最精巧的一塊。不是單純「靜音就當講完」,而是兩棒接力:

  • 第一棒 Silero:先偵測停頓;停頓達 ~64 毫秒觸發第二棒;
  • 第二棒 Smart(SmartTurn v3.2):從語義與語調二次確認——你是「講完了」還是「只是換氣/在想」;
  • 另預留 ~800 毫秒重開寬限:避免搶話與掉字。
為什麼重要:「什麼時候該接話」是即時對話最像/最不像真人的分水嶺。純靠靜音長度會誤判(你只是停頓思考就被搶答)。用一個小模型做「語義判停」,是把體驗拉到「像真人」的關鍵。

② STT:SenseVoiceSmall(FunASR)

阿里 FunASR 生態的小型高速語音辨識模型,~0.1s 完成語音轉文字。小而快是為了守住延遲預算。

③ LLM:Qwen 3(8–27B)本地推理

用 llama.cpp 在本地跑開源 Qwen 3(視訊示範等級約 8–27B),串流輸出快速產出首句。全本地=零 API 費、資料不外流。

④ TTS:VoxCPM2(音色遷移 + 串流)

支援音色遷移(voice cloning/transfer)的語音合成,~0.1s 出首音,同樣串流輸出。音色遷移讓數字人能「用指定人的聲線」說話。

⑤ Avatar:AVTR-1(TensorRT)唇同步

把生成的語音與數字人唇形即時驅動、畫面同步對齊,~0.2s。用 TensorRT 加速推理。還有「傾聽模式」——你說話時數字人有即時注視反應(見下)。

⑥ Persona:人設蒸餾(女娲 · Skill 造人術)

只要輸入目標人名,系統自動深度調研 + 思維框架構建,蒸餾出符合該角色特徵、語調、口癖的完整人設(影片示範還原網紅「大胃袋涼子」的對話風格),並可切換音色與肖像。

④ 系統架構

瀏覽器(WebRTC / WebSocket) │ Opus 音訊編碼 · TURN 轉發 ▼ Orchestrator 編排層(Python)—— 調度四個核心服務,管理串流與打斷 ├─▶ VAD 服務 Silero + SmartTurn ├─▶ STT 服務 SenseVoiceSmall (FunASR) ├─▶ LLM 服務 Qwen 3 (llama.cpp) ── 串流 ├─▶ TTS 服務 VoxCPM2 ── 串流 └─▶ Avatar AVTR-1 (TensorRT) ── 唇同步 ▲ └── 音訊/視訊串回瀏覽器

後端 Python 編排;前端 WebRTC + WebSocket + 原生唇型對齊;推理框架 llama.cpp(LLM)與 TensorRT(Avatar);通訊用 TURN 轉發 + Opus 音訊編碼。編排層是靈魂——它把五個串流接起來、處理打斷與時序。

⑥ 硬體與安裝

硬體:單張 RTX 4090(repo 標示 48GB 版)全棧運行、全離線(無外部 API)。示範環境為 AutoDL 雲主機的 4090。

# AutoDL 4090 一鍵流程(以官方 repo 為準)
cp .env.example .env.local
bash scripts/autodl_setup.sh      # 環境 + 模型
bash scripts/start_assistant.sh   # 一鍵起全棧
bash scripts/tunnel.sh            # 轉發本地埠
# 瀏覽 http://localhost:8000

授權:代碼 MIT;模型各自遵循(speech-to-speech / VoxCPM2 / Qwen 多為 Apache-2.0;AVTR-1 為 Community License)。

⑦ 值得偷師的思路(不只做語音的人也用得到)

  1. 延遲預算工程:先把體驗目標(1.3s)拆成每段的預算,再逐段優化——這是所有即時 AI 系統的通用方法。
  2. 「首輸出」而非「全輸出」:串流 + 只等首句/首音,讓感知延遲 = 各段首輸出之和,而非全做完之和。適用任何多階段 AI 管線。
  3. 用小模型做「決策」:判停不靠規則靠語義小模型(SmartTurn)。把難判斷交給便宜的專用模型,是性價比極高的一招。
  4. 狀態要能被打斷:打斷記憶(保留已聽內容與播放位置)——即時系統必須把「被中斷」當一等公民,呼應 agent 的並發紀律。
  5. 全本地的取捨:零 API 費 + 隱私 + 可控,代價是硬體門檻與工程複雜度。
與站內其他單元的連結:它的「串流壓延遲」「長對話自動摘要」呼應 上下文壓縮;「本地跑開源模型」呼應 訓練小模型;而「多模組編排 + 打斷處理」與 agent harness 的並發設計同源。

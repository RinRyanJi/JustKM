⓪ 一句話定位

OpenTypeless 是「把鍵盤換成嘴巴」的開源桌面語音輸入產品——按住熱鍵、自然說話，文字經 STT（可選 LLM 潤色）後，用鍵盤模擬或剪貼板直接打進你正在用的任意應用。它也附帶一次性語音問答（Ask Anything）、選取改寫與翻譯捷徑。

定位上它是 Wispr Flow／Superwhisper 的開源替代，走語音生產力線，不是 coding agent、也不是 MCP 工具鏈。上游倉庫：tover0314-w/opentypeless（注意 owner 拼寫為 tover0314-w），官網 opentypeless.com，授權 MIT。

寫作當下快照（2026-09-20 台北時間）：GitHub 約 549★（持續變動，請以倉庫為準）；最新正式版標籤 v1.1.59（2026-09-09 UTC）。下文不把星數寫成永恆真理。

① 為什麼值得拆：語音生產力 ≠ 寫碼 Agent

JustKM 已有大量 Agent／harness／MCP 類文章。OpenTypeless 值得另開一篇，是因為它解決的是另一條日常路徑：

  • 產品完整度高：不只是 Whisper 前端，而是熱鍵、浮動膠囊狀態、應用感知潤色、本地詞典、多捷徑、跨平台輸出與可選雲端額度——接近商用語音輸入 App 的產品形狀。
  • 工程可讀：Tauri 殼 + React/TS UI + Rust（音訊、STT/LLM 適配、鍵盤輸出、SQLite），架構邊界清楚，適合當「桌面 AI 生產力 App」範本。
  • 控制權敘事明確：BYOK（自備金鑰／自架端點）與 Cloud words（託管額度）並存；產品宣稱 BYOK 模式下請求直連你選的 provider，不經 OpenTypeless 伺服器。
  • 繁中場景友好：意圖路由明確支援英文、簡體與繁體中文（產品宣稱）。
和 Agent 系列的界線：Agent 管的是「多步驟任務、工具、session」；OpenTypeless 管的是「這一句話怎麼變成當前輸入框裡的好文字」。兩者可並用，但知識歸檔應分線，避免學到一半以為又要裝 MCP。

② 四大語音工作流

上游 README 把核心能力收成四條路徑（產品宣稱）：

工作流你做什麼系統做什麼結果落點
聽寫 Dictation 按住／切換聽寫熱鍵，說話 錄音 → STT →（可選）依應用類別 LLM 潤色 鍵盤打字或剪貼板貼入作用中 App
Ask Anything 按 Ask 熱鍵，問一句話 轉寫問題 → 一次性 LLM → 只顯示答案 小浮窗便簽（可複製）；非聊天頁、無歷史對話
選取改寫 在別的 App 選取文字，再語音下指令 抓選取內容 + 語音指令 → LLM 改寫／摘要／修正 覆寫或輸出回作用中 App
翻譯 Translation 用翻譯捷徑說話或對選取文字操作 送往你設定的目標語言之一（可切換，非死鎖單一語言） 同上輸出路徑

預設熱鍵（對齊 Typeless 風格，產品宣稱）

平台聽寫Ask Anything翻譯選取
macOSFnFn+SpaceFn+LeftShift
WindowsRight AltRight Alt+SpaceRight Alt+LeftShift
LinuxCtrl+/Ctrl+.可配置

Linux 刻意用較保守的 Ctrl 預設：跨桌面環境（尤其 Wayland）全域 Right Alt 監聽不如 Windows 穩定——這點在「平台坑」一節再展開。

上游建議起步組合：STT = Groq whisper-large-v3-turbo；AI 潤色 = Google gemini-2.5-flash（兩者常有慷慨免費額度；實際額度與條款以各家為準）。

③ 核心管線：熱鍵 → 輸出

把產品想成一條可分支的桌面管線：錄音與轉寫是主幹；應用類別／詞典在本地；LLM 潤色可選；最後才落到鍵盤或剪貼板。

④ 應用感知寫作與隱私邊界

應用感知（app-aware writing）會在本地偵測作用中應用，並依內建／自訂「應用類別 → 寫作風格」調整結構與語氣（郵件、聊天、文件、Issue、開發工具等）。你也可以為單一 App 覆寫類別。

產品宣稱的隱私邊界值得單獨記下來：

  • 留在本地：應用偵測結果、per-app 風格映射、詞典詞條、糾錯規則、歷史記錄（SQLite）。
  • 可送給已設定的 LLM 路徑：內部應用類別與經審核的風格中繼資料（metadata）——用於潤色上下文。
  • 產品宣稱不會：把原始視窗標題、文件內容當成應用上下文送去 LLM，也不把這些寫進歷史。
  • 金鑰：BYOK API key 優先存 OS credential vault；產品宣稱不會把 BYOK key 送到 OpenTypeless 伺服器——STT／LLM 請求直連你配置的 provider。
誠實提醒：「不經 OpenTypeless 伺服器」≠「音訊／文字完全不出本機」。BYOK 仍會把音訊送到你選的 STT、把轉寫／指令送到你選的 LLM。若要幾乎離線，需自架 Whisper 相容 STT + 本機 Ollama 等 OpenAI 相容 LLM（產品宣稱可行）。Cloud 模式則會經託管代理做轉寫與額度計帳。

⑤ 意圖路由：聽寫／編輯／翻譯／Ask

除了「你按哪個熱鍵」這種顯式模式，產品還宣稱有語音意圖路由：在英文、簡體中文、繁體中文裡，用較確定性的規則區分聽寫、選取編輯、翻譯、Ask 與受支援的語音動作。

  • 同一套桌面殼，用捷徑切換「這次是打字、問答還是翻譯」。
  • 翻譯目標可切換（20+ 語言，產品宣稱），不必鎖死單一輸出語。
  • Ask 可選讀取「當前選取文字」當上下文，但仍是一次性問答，不是聊天 session。
產品宣稱 vs 實測：意圖路由的覆蓋率、誤判率與繁中口語變體表現，需實際語音驗證；本頁以 README 功能表為準，不臆造規則表。

⑥ Provider 矩陣：STT × LLM

選型自由度是相對系統聽寫／單一 Whisper 桌面殼的主要賣點之一。下列整理自上游功能表（產品宣稱，清單會隨版本變動）：

層選項（節錄）備註
STT Cloud STT、Apple Speech（macOS）、Deepgram、AssemblyAI、GLM-ASR、OpenAI Whisper、Groq Whisper、SiliconFlow、Volcengine Doubao、Qwen3 ASR Realtime（區域）、Custom Whisper URL 錄音時長限制會依 provider 能力調整（較新版本產品宣稱）
LLM Cloud LLM、OpenAI、DeepSeek、Claude（原生 Anthropic Messages 或經 OpenRouter）、Gemini、Groq、Qwen、Moonshot、Ollama 等 OpenAI 相容 較新版本宣稱支援 GPT-5／o 系列請求路徑
輸出 鍵盤模擬、剪貼板貼上／僅複製、Windows SendInput、失敗診斷 Wayland 需 compositor helper（見平台坑）
本地資料 詞典匯入匯出、糾錯規則、Scenes 場景模板、歷史全文搜尋 SQLite + store plugin

⑨ 平台坑：macOS／Windows／Linux Wayland

跨平台「直接打字進任意 App」是產品難點；上游安裝說明已誠實標出常見摩擦：

平台常見坑產品／社群建議（摘要）
Windows SmartScreen「已保護你的電腦」；發行者驗證警告；修飾鍵輸出邊界 「更多資訊 → 仍要執行」；對 .msi 內容屬性勾選解除鎖定。較新版宣稱強化 SendInput／修飾鍵安全。
macOS Gatekeeper／隔離屬性攔截首次開啟（即使 Developer ID 簽名） xattr -cr /Applications/OpenTypeless.app 後再開啟（僅在你信任官方 Releases 來源時）。
Linux Wayland 直接輸入；NVIDIA+Wayland WebKit 崩潰；全域熱鍵因 DE 而異；ARM64 套件較新才有 KWin 用 kwtype；其他 compositor 用 wtype。NVIDIA 可試 WEBKIT_DISABLE_DMABUF_RENDERER=1。helper 不可用時退回剪貼板，不跑不受信腳本。
安全習慣：請只從官方 GitHub Releases 下載。簽名與公證狀態仍在持續完善——這是開源桌面分發的常態，不是「裝了就等同商業 notarized 體驗」。

建議使用情境

  • 每天在郵件、Slack、文件、Issue、IDE 之間切換，打字成為瓶頸。
  • 需要「說完就進輸入框」，且偶而要潤色／翻譯／對選取文字下指令。
  • 想要開源＋BYOK，又不想自己從零組 Tauri 殼。

較不適合

  • 要的是 Agent 編排、工具呼叫、長期 session（請走 JustKM Agent／Skills 線）。
  • 要的是低延遲對話數字人或嵌入式按鍵助手（見 VoxEMW、ESP32 頁）。
  • 只研究 TTS 聲學模型（見 Kokoro）。

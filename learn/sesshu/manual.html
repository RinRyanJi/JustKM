1. Sesshu 幫你做什麼

你跟 AI coding agent 講得越久，它就越貴、越健忘，最後只能 /clear 重來 —— 然後所有脈絡一起消失。

Sesshu 在背景默默把你的對話整理成一份結構化筆記存在磁碟上。當 context 太大時它提醒你可以 /clear；你按下去之後，新對話會自動帶著整理好的脈絡開始，不用重講一遍。

你需要做的事只有一件：看到提示時按 /clear。其餘全部自動。

你會得到說明
對話可以無限接續/clear 之後 agent 仍記得目標、決策、改過哪些檔、踩過哪些坑
省 token整理工作交給本機小模型，不消耗主模型的額度
永久可搜尋的工作紀錄每次壓縮都留下一頁 Markdown，跨 session 可以被搜尋回來
資料不出門用本機 Ollama 時，對話內容完全不離開你的電腦

2. 安裝前的準備

項目需求
Python3.9 或更新版本，且 python 或 python3 在 PATH 中
AI CLIClaude Code、Codex CLI、Gemini CLI 或 GitHub Copilot CLI（擇一或多個）
語言模型端點任何 OpenAI 相容的 /chat/completions 端點：Ollama、LM Studio、vLLM、OpenRouter、OpenAI 都可以
額外套件不需要。執行期只用 Python 標準函式庫
建議用 Ollama 跑在本機。整理摘要是高頻但不難的工作，7B 等級的小模型就夠用；跑在本機既不花錢、速度也夠，而且對話內容不會傳到任何外部服務。

3. 安裝步驟

1安裝套件並註冊 hook

PowerShell（Windows）／ Bash（macOS・Linux）通用

pip install sesshu
sesshu install --runtime claude --scope user

--runtime 可以填 claude、codex、gemini、copilot、both（Claude + Codex）或 all（全部四種）。--scope 填 user（整台電腦通用，預設）或 repo（只在這個專案生效）。

# 只裝 Gemini CLI
sesshu install --runtime gemini --scope user

# 四種 runtime 全裝，但只在目前這個專案生效
sesshu install --runtime all --scope repo
安裝程式會合併而不是覆寫你的設定檔 —— 已存在的其他 hook 不會被移除。既有的 prompts.json 若已存在也會被保留，不會蓋掉你改過的提示詞。

從原始碼安裝（開發者用）

如果你是從 GitHub clone 下來要改程式碼，用隨附的安裝腳本，它會把本地的 src/sesshu 直接複製進 hook 目錄：

PowerShell（Windows）

git clone https://github.com/Nexplico-Ltd/Sesshu.git
cd Sesshu
.\install.ps1 -Runtime claude -Scope user

Bash（macOS・Linux）

git clone https://github.com/Nexplico-Ltd/Sesshu.git
cd Sesshu
bash ./install.sh --runtime claude --scope user

2建立設定檔

sesshu config init

這會產生設定檔，路徑是：

  • Windows：%USERPROFILE%\.sesshu\.env
  • macOS・Linux：~/.sesshu/.env

接下來的第 4 節會說明怎麼填。

3重新啟動 AI CLI

完全關閉再重新開啟。hook 設定與 /sesshu-config 指令都是在啟動時載入的，不重啟不會生效。

安裝後檔案跑到哪裡

4. 設定語言模型端點

做法 A：本機 Ollama（推薦）

預設值就是為 Ollama 準備的，只要把模型抓下來就能直接用：

ollama pull qwen2.5:7b

對應的 .env 內容（sesshu config init 已經幫你寫好，通常不用改）：

SESSHU_LM_URL=http://localhost:11434/v1
SESSHU_LM_MODEL=qwen2.5:7b
SESSHU_LM_API_KEY=ollama

做法 B：雲端或其他端點

任何 OpenAI 相容端點都可以，把三個值換掉即可：

# OpenAI
SESSHU_LM_URL=https://api.openai.com/v1
SESSHU_LM_MODEL=gpt-4o-mini
SESSHU_LM_API_KEY=sk-...

# LM Studio（本機）
SESSHU_LM_URL=http://localhost:1234/v1
SESSHU_LM_MODEL=your-loaded-model
SESSHU_LM_API_KEY=lm-studio
隱私提醒：用雲端端點時，逐字稿的片段（最多每次 20,000 字元）會送到該服務。如果你的專案含有機敏內容，請使用本機端點。
為什麼 SESSHU_DATA_DIR 不能寫在 .env 裡？因為 Sesshu 要先知道資料目錄在哪，才找得到 .env —— 有先後順序問題。它必須設成環境變數，或由安裝程式寫進 hook 命令中（安裝時已自動處理）。

5. 確認安裝成功

重啟 CLI 之後，用這份清單快速檢查：

  • 輸入 /sesshu-config，會列出目前所有設定值 —— 看得到就代表指令檔安裝正確。
  • 資料目錄存在：Windows 看 %USERPROFILE%\.sesshu\，其他系統看 ~/.sesshu/，裡面應有 .env 與 prompts.json。
  • 端點通得到：curl http://localhost:11434/v1/models（Ollama）能回應。
  • 正常聊個十幾分鐘後，~/.sesshu/wiki/sessions/ 底下開始出現 .md 檔案 —— 這代表壓縮真的在跑。
最後一項需要一點耐心：預設每次攝取至少間隔 300 秒，而且要有新的對話內容。想立刻驗證的話，臨時把間隔設成 0：/sesshu-config SESSHU_INGEST_MIN_INTERVAL=0，測完記得改回來。

6. 日常使用

Sesshu 有兩種運作模式，預設是 hitl（由你決定何時壓縮）。

hitl 模式：你會看到什麼

切換到 auto 模式

/sesshu-config SESSHU_MODE=auto

改完要重啟 CLI。auto 模式下 Sesshu 改掛在「CLI 即將自動壓縮」的時機點，搶先把完整 wiki 頁寫下來，然後安靜退出 —— 不會有任何提示訊息。

翻閱你的工作紀錄

所有壓縮產物都是純 Markdown，可以直接用任何編輯器打開：

檔案內容
~/.sesshu/wiki/index.md所有 session 頁面的索引清單
~/.sesshu/wiki/log.md時間順序的活動紀錄（超過 1 MB 會自動輪替）
~/.sesshu/wiki/sessions/一次攝取一頁，檔名是時間戳。每頁固定 12 個章節

每一頁的固定章節是：Goal、Tasks、Plans、Decisions made、Rejected Approaches、Constraints、Code changes、Git operations、Errors & resolutions、Blockers、External References、Current state。

這些檔案可以手動編輯。如果某次摘要寫錯了，直接改掉即可 —— 下一次 /clear 時被讀取的就是你改過的版本。

7. 用 /sesshu-config 調整設定

安裝時會附帶一個斜線指令（Copilot CLI 除外），不用手動編輯 .env。

列出目前所有設定

/sesshu-config

修改單一設定

/sesshu-config SESSHU_THRESHOLD=80000
/sesshu-config SESSHU_VERBOSE=1
/sesshu-config SESSHU_MODE=auto

清空設定，回到預設值

/sesshu-config SESSHU_VERBOSE=

格式錯誤或值不合法時它會拒絕修改並告訴你原因，不會把 .env 弄壞。改完設定需要重啟 CLI 才生效。

8. 依情境調參數

不用背所有變數，照你遇到的狀況查就好：

你的感受調這個說明
提示訊息太晚才出現，我早就卡了 SESSHU_THRESHOLD=80000 調低觸發門檻（預設 120000 字元）
提示訊息太吵 SESSHU_THRESHOLD=200000 調高門檻。或改用 auto 模式完全不提示
每次回話都卡一下 SESSHU_INGEST_MODE=background 攝取改用背景子行程，hook 立即返回
還是卡 SESSHU_INGEST_MIN_INTERVAL=600 拉長攝取間隔（預設 300 秒），呼叫模型的次數減半
摘要太簡略，細節都不見了 SESSHU_MAX_WORDS=1000 放寬摘要字數（預設 600 字）
接續時忘記剛剛在講什麼 SESSHU_KEEP_TURNS=8 保留更多組近期對話原文（預設 4 組）
模型很慢，常常來不及 SESSHU_TIMEOUT=180 拉長逾時（預設 90 秒）。或換更小的模型
想知道它到底有沒有在動 SESSHU_VERBOSE=1 連未達門檻時也顯示狀態訊息
要查問題 SESSHU_DEBUG=1 輸出診斷紀錄到 ~/.sesshu/debug.jsonl（不含對話內容）
想被提醒「以前做過類似的事」 SESSHU_RELATED=1 攝取時偵測相關的歷史 session 並通知（預設關閉）

9. 疑難排解

症狀原因與處理
/sesshu-config 找不到 安裝後沒重啟 CLI；或安裝的是 Copilot CLI（它沒有指令目錄，請直接編輯 .env）
完全沒有任何提示訊息 逐字稿還沒到 120,000 字元。先開 SESSHU_VERBOSE=1 確認它有在運作
wiki/sessions/ 一直是空的 多半是模型端點不通。先 curl 測端點，再開 SESSHU_DEBUG=1 看 debug.jsonl
頁面內容只有檔案清單，寫著 Fallback snapshot 模型當時掛掉或逾時，Sesshu 走了備援路徑。修好端點後下一輪會自動補上完整摘要
每次回話都要等一下 改成 SESSHU_INGEST_MODE=background，或拉長 SESSHU_INGEST_MIN_INTERVAL
/clear 之後沒有帶回脈絡 表示當下還沒有 seed.md（攝取尚未跑過任何一次）。確認端點正常，並讓對話累積久一點
擔心它會不會弄壞我的對話紀錄 不會。Sesshu 只讀取逐字稿，從不寫入、截斷或刪除，而且任何錯誤都靜默退出，不會中斷 agent

10. 解除安裝

用跟當初安裝時相同的 --scope：

sesshu uninstall --scope user

預設只移除 hook 註冊與指令檔，保留 ~/.sesshu/ 底下的所有資料（wiki 頁面、設定、提示詞模板都還在）。要連資料一起刪：

sesshu uninstall --runtime all --scope user --remove-data

從原始碼安裝的話，用對應的腳本：

bash ./uninstall.sh --scope user      # macOS・Linux
.\uninstall.ps1 -Scope user           # Windows
移除後你的 AI CLI 會恢復成原本的行為，其他 hook 不受影響。~/.sesshu/wiki/ 裡的 Markdown 就算 Sesshu 不在了也還是能直接閱讀。

想知道這一切背後的原理 —— 為什麼要用游標、為什麼是 12 個章節、為什麼壓縮不是在 /clear 當下發生 —— 請看同目錄的 sesshu-compression-explained.html。完整的技術參考與各 runtime 差異請看 sesshu-architecture-and-usage-guide.html。

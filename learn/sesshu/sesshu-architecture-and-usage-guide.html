Introduction

Sesshu (摂取, "intake" or "digest") is a Python 3.9+ hook package that compresses long coding-agent sessions by leveraging an OpenAI-compatible language model endpoint. It works with Claude Code, Codex, Gemini CLI, and GitHub Copilot CLI to intelligently summarize transcript history and inject compressed context across /clear or runtime compaction events.

Rather than carrying forward the entire conversation history (incurring compounding input costs), Sesshu intercepts transcript growth at strategic points, produces a structured LLM Wiki-style summary, persists it to a searchable wiki, and restores it as additional context when a fresh session begins.

Core principles:

  • Modularity: Small, single-purpose modules in a runtime-neutral core
  • Safety: All hook paths return exit code 0 to never block the host runtime
  • Gradual rollout: Two operational modes (HITL and Auto) with LM-free fallback

Problem & Motivation

Long coding-agent sessions repeat all prior conversation history as input context, leading to:

  • Exponential input costs: 120K-200K characters of history per request
  • Latency bloat: More context = longer input token processing
  • Runtime compaction overhead: Full-context re-compression by frontier models

Sesshu solves this by maintaining a compact structured wiki summary and injecting it (instead of full history) after /clear or automatic compaction. Example: A 150K-char session compresses to 3-5K wiki page (30-50x reduction, saving ~$16 in input costs).

Architecture Overview

Operating Principles

Two Operational Modes

HITL mode (default, SESSHU_MODE=hitl): Stop hook + manual /clear. After each assistant turn, check if transcript exceeds threshold. If yes and seed exists, suggest /clear. User manually clears when ready; SessionStart hook injects compressed context.

Auto mode (SESSHU_MODE=auto, Claude Code/Codex/Gemini/Copilot): PreCompact/PreCompress hook replaces Stop hook. Runs just before runtime compaction. Generates wiki page and seed silently (no user prompt). SessionStart hook on source: "compact" injects seed into freshly-compacted session.

Three Safety Guarantees

  • Exit code 0: Every hook path returns 0, never crash the host runtime
  • No transcript mutation: Hooks never write, truncate, or delete .jsonl files
  • Graceful degradation: LM endpoint failure, timeout, or misconfiguration triggers fallback (LM-free wiki builder) or silent exit

Data Privacy Boundaries

  • Transcript content sent to SESSHU_LM_URL; use local endpoint for sensitive sessions
  • Wiki pages, search index, and related-session state treated as sensitive derived session data
  • Private file mode (0600): All wiki, seed, cursor, and index files created with user-only read/write

Core Flows

Stop Hook Flow (HITL Mode)

run_ingest() [async or sync] 1. Read cursor.json → chars_processed, session_id, last_ingest_ts 2. Compute transcript diff (new chars since last ingest) 3. Extract structured events from diff (files, git ops, bash, errors) 4. Load prompt templates and expand {structured_events}, {excerpt}, {max_words} 5. Call LM with diff + recent turns 6. Validate 12 required wiki sections; retry up to 2 times if missing 7. Write seed.md, wiki/sessions/*.md, update search.db index 8. Update cursor.json with new chars_processed, last_ingest_ts 9. If SESSHU_RELATED=1, detect related prior sessions, write related_notice.json run_stop() [synchronous reminder gate] 10. If transcript size < SESSHU_THRESHOLD, exit silently (seed kept) 11. If threshold exceeded and seed exists, emit systemMessage + shown.flag 12. If related_notice.json exists, append notice to systemMessage (delete after read)

Key points:

  • run_ingest() blocks until LM responds (unless background mode enabled); hook returns exit 0 immediately in async
  • Cursor tracks incremental progress: only new characters sent to LM each invocation (subject to SESSHU_INGEST_MIN_INTERVAL)
  • Structured events injected as explicit prompt block, improving LM context
  • Fallback: If LM fails, build wiki page from extracted events alone (LM-free)

SessionStart Hook Flow

run_start() [on source: "clear"] 1. Check trigger source: accept only "clear" or "compact" events 2. Read seed.md 3. Sync wiki search index (reconcile new/deleted pages) 4. Extract keywords from seed Goal/Tasks/Current-state/Blockers sections 5. Search wiki using FTS5 (or grep fallback) for related pages 6. Build seed + wiki hint (list of matched pages) 7. Emit additionalContext with compressed history + wiki hint 8. If SESSHU_VERBOSE=1, emit systemMessage: "sesshu: restored prior session context (N pages)" 9. Delete seed.md, shown.flag, cursor.json, related state files

Key points:

  • Seed injection happens only on source: "clear" (manual) or "compact" (automatic)
  • FTS5 search surfaces most-relevant pages; grep fallback if index unavailable
  • Recent pages shown when no keyword match (graceful fallback)
  • Transient files deleted after successful output construction (prevent re-injection)

PreCompact/PreCompress Flow (Auto Mode)

run_precompact() [on PreCompact/PreCompress event] 1. Extract recent transcript slice 2. Generate wiki page (same logic as run_ingest: sections, LM call, validation) 3. Write seed.md and wiki/sessions/*.md 4. Return silently (no systemMessage, no user interaction) On subsequent SessionStart (source: "compact"): 5. run_start() reads seed, injects as additionalContext 6. Delete seed.md

Key points:

  • Non-interactive: user never sees compression prompt
  • Runs just before runtime compaction; seed + context injected into compacted session
  • Supported on Claude Code, Codex, Gemini CLI, Copilot CLI

Runtime Adapters

Each runtime (Claude Code, Codex, Gemini CLI, Copilot CLI) uses a distinct JSON format for hook input/output. Adapters normalize this into a unified protocol:

  • parse_stop(payload) → StopRequest: Extract transcript_path and stop_hook_active flag
  • parse_precompact(payload) → StopRequest: Similar but stop_hook_active=False
  • parse_start(payload) → StartRequest: Extract source ("clear", "compact", etc.)
  • build_stop_output(message) → JSON string: Emit systemMessage in runtime-specific format
  • build_start_output(context, notify) → JSON string: Emit additionalContext + optional systemMessage

Example (Claude Code adapter):

def parse_stop(payload):
    return StopRequest(
        transcript_path=payload.get("transcript_path", ""),
        stop_hook_active=bool(payload.get("stop_hook_active")),
    )

def build_stop_output(message):
    return json.dumps({"systemMessage": message})

Codex, Gemini, and Copilot adapters follow the same pattern but parse and emit runtime-specific fields (e.g., Copilot uses agentStop event type, Gemini uses PreCompress instead of PreCompact).

Trusted Config/Data Directories

Sesshu's configuration and data directories are intentionally restricted to prevent repository-local paths from redirecting LM calls or injecting prompt templates.

VariableDefaultContents
Config dir~/.sesshu/ (or $SESSHU_DATA_DIR).env, prompts.json
Data dir.sesshu/ (if exists) or ~/.sesshu/seed.md, wiki/, debug.jsonl

Behavior:

  • Config dir: Always ~/.sesshu/ unless SESSHU_DATA_DIR env var set (never from project)
  • Data dir: Auto-detects project-local .sesshu/ if it exists; falls back to ~/.sesshu/
  • When SESSHU_DATA_DIR is set: Both config and data use that path
  • Wiki pages created with mode 0600 (user-only read/write)

💡 Tip: For isolated projects, create .sesshu/ in the project root. Sesshu will automatically use it for data while pulling config from ~/.sesshu/.

Transcript Processing

Sesshu reads transcript files as JSONL (JSON Lines). Each line is a JSON object representing a message or tool interaction.

Transcript Format

Sesshu extracts two types of data from the transcript:

  • Recent turns: Last N user-assistant message pairs (extracted by transcript.extract_recent_turns())
  • Transcript diff: New characters since last ingest (computed from cursor.json; sent to LM)

Expected JSONL line types:

{"type": "message", "role": "user", "content": "..."}
{"type": "message", "role": "assistant", "content": [...]}
{"type": "user", "message": {"role": "user", "content": "..."}}
{"type": "assistant", "message": {"role": "assistant", "content": [...]}}

Content fields support both plain strings and block arrays (with type: "text" entries).

Recent Turns Extraction

extract_recent_turns(path, keep_turns=4) returns the last keep_turns * 2 messages (e.g., 4 turns = 8 messages: 4 user + 4 assistant) formatted as Markdown for inclusion in the seed. Each message is truncated to 800 characters.

Structured Event Extraction

Before sending transcript diff to the LM, Sesshu pre-extracts structured events (file edits, git operations, bash commands, errors) and injects them as a STRUCTURED EVENTS block in the prompt. This gives the LM explicit signal without requiring it to parse raw JSONL.

Event Types

  • File edits: Paths from Write, Edit, NotebookEdit tool calls
  • Git operations: Bash commands containing "git "
  • Bash commands: Other Bash commands (limited to 20 unique entries)
  • Errors: Tool results with is_error: true (first 120 chars)

Extraction Algorithm

for each line in transcript_diff:
    if line is JSON:
        if type="tool_use" and name in [Write, Edit, NotebookEdit]:
            → add file_path to file_edits
        elif type="tool_use" and name="Bash":
            → if cmd contains "git": add to git_ops
            → else: add to bash_commands (max 20)
        elif type="tool_result" and is_error:
            → add error text (first 120 chars) to errors

Formatted output (injected into LM prompt):

STRUCTURED EVENTS:
Files edited:
  - /path/to/file1.py
  - /path/to/file2.ts
Git operations:
  - git add -A
  - git commit -m "fix: ..."
Bash commands:
  - npm run build
Errors:
  - Connection refused: localhost:8080

ℹ️ Note: If no events extracted, the STRUCTURED EVENTS block is omitted from the LM prompt.

LM Interaction & Validation

OpenAI-Compatible API Call

Sesshu calls the LM endpoint at {SESSHU_LM_URL}/chat/completions with:

POST /chat/completions
Authorization: Bearer {SESSHU_LM_API_KEY}
Content-Type: application/json

{
  "model": "qwen2.5:7b",
  "messages": [{"role": "user", "content": "...prompt..."}],
  "temperature": 0.3,
  "max_tokens": 1200,
  "stream": false
}

Response parsing: Extracts data["choices"][0]["message"]["content"] and strips whitespace.

Failure Handling

  • HTTP errors (4xx, 5xx): Log and return ""
  • Network errors (URLError, timeout, socket errors): Log and return ""
  • Malformed response (missing keys, non-string content): Log and return ""
  • Response too large (>1 MiB): Log and return "" (DoS protection)
  • Any unexpected exception: Catch and log, return "" (never crash)

Section Validation & Retry

The LM must produce a wiki page with 12 required sections:

## Goal
## Tasks
## Plans
## Decisions made
## Rejected Approaches
## Constraints
## Code changes
## Git operations
## Errors & resolutions
## Blockers
## External References
## Current state

structure.call_lm_with_retry(config, prompt, required=REQUIRED_SECTIONS, max_retries=2):

  1. Call LM with prompt
  2. Validate all 12 headings present
  3. If missing sections: Append correction instruction and retry (up to 2 attempts)
  4. Return best non-empty response (always exits gracefully, never raises)

💡 Tip: Temperature set to 0.3 (low variance). Max tokens 1200 limits response size; wiki pages typically 400-800 words.

Wiki Persistence & Search

Wiki Structure

Wiki pages are Markdown files under $DATA_DIR/wiki/sessions/, named by timestamp: 2024-12-15-093422-session.md.

~/.sesshu/
├── seed.md                    (transient: current session seed)
├── wiki/
│   ├── sessions/              (persisted wiki pages)
│   │   ├── 2024-12-15-093422-session.md
│   │   ├── 2024-12-16-140530-session.md
│   │   └── ...
│   ├── search.db              (SQLite FTS5 index)
│   ├── index.md               (list of all pages)
│   └── log.md                 (timestamped log of page writes)
├── .env                       (config file)
├── shown.flag                 (suppresses duplicate reminders)
├── cursor.json                (tracks ingest progress)
├── related_state.json         (related-session state)
└── debug.jsonl                (debug logs, if SESSHU_DEBUG=1)

FTS5 Search Index

SQLite FTS5 (full-text search) index enables fast keyword-based page retrieval. If unavailable or stale, Sesshu falls back to grep.

Index structure:

CREATE VIRTUAL TABLE pages USING fts5(path UNINDEXED, content)
CREATE TABLE meta (path TEXT PRIMARY KEY, mtime REAL)

sync_missing_pages(wiki_dir) reconciles index with filesystem (detects new, modified, and deleted pages).

Keyword Extraction

Extract meaningful keywords from seed sections (Goal, Tasks, Current state, Blockers):

  • Tokenize: lowercase alphanumeric tokens ≥3 chars containing ≥1 letter
  • Filter: Remove stopwords (a, the, and, or, is, etc.)
  • Rank: Frequency count, return top-20

Wiki Page Selection (SessionStart)

select_wiki_pages(wiki_dir, seed_content):

  1. Extract keywords from seed
  2. Search FTS5 for pages matching keywords (limit 5 results)
  3. If no matches: Return 5 most recent session pages
  4. Exclude current session's own pages from results

⚠ Warning: Related-session pages excluded if already surfaced (to avoid re-injection unless relevance score increases by >0.1).

Fallback Path (LM-Free)

If the LM is unavailable, times out, or returns an empty response, Sesshu builds a minimal wiki page from extracted events alone (no LM required).

build_fallback_page(events: EventSnapshot) → str produces a structurally valid wiki page:

## Goal
_(not recorded)_

## Tasks
_(not recorded)_

## Code changes
- file1.py
- file2.ts

## Git operations
- git add -A
- git commit

## Errors & resolutions
- Connection refused

## Current state
_(not recorded)_

[... other sections ...]

Guarantees:

  • All 12 required sections present
  • Sections without data marked _(not recorded)_
  • File edits, git ops, bash commands, errors listed (if any)
  • No LM call; always succeeds

💡 Tip: Fallback enables graceful degradation: compression works even if LM endpoint is down.

Related-Session Detection (Opt-In)

When SESSHU_RELATED=1, Sesshu scans prior wiki pages after successful ingest to find sessions sharing keywords with the current summary. If a match scores above SESSHU_RELATED_THRESHOLD (default 0.3), a one-shot notice is queued for emission by run_stop().

State Management

  • related_state.json: Tracks current session ID and pages already surfaced (prevents re-surfacing unless relevance increases >0.1)
  • related_notice.json: One-shot notice emitted by run_stop(), deleted immediately after reading

Cleanup

run_start() deletes related-session transient files on accepted source: "clear" or "compact" events, allowing the cycle to repeat cleanly in the next session.

ℹ️ Note: Related notices remain opt-in (default off) and must be factual (page path + score only, no summary contents or instructions).

Testing & Debugging

Running Tests

Sesshu uses pytest with pythonpath configured in pyproject.toml:

pytest -q                           # Full test suite
pytest tests/test_core.py -q        # Single test file
pytest -k "test_stop" -q            # Filter by name
python3 -m py_compile src/sesshu/*.py  # Syntax check only

Debug Logging

Set SESSHU_DEBUG=1 to enable stderr diagnostics and JSONL debug log:

SESSHU_DEBUG=1 PYTHONPATH="$PWD/src" python3 hooks/sesshu_claude_stop.py

Debug output written to $DATA_DIR/debug.jsonl (no transcript content logged, only metadata).

Testing Patterns

  • Fixtures: conftest.py provides fake_lm_server (ThreadingHTTPServer on random port)
  • Filesystem: Use tmp_path pytest fixture for isolated test directories
  • Do NOT mutate: Real ~/.claude/, ~/.codex/, ~/.gemini/, ~/.copilot/ or ~/.sesshu/ in tests
  • Scripts testing: Import via package: from scripts import benchmark_suite (not dynamic loading)

Common Test Scenarios

  • Hook failure paths: endpoint timeout, malformed response, missing transcript
  • Runtime adapters: Correct parsing of Codex/Gemini/Copilot JSON formats
  • Prompt loading failures, corrupt transcript JSONL, event extraction edge cases
  • FTS5 fallback to grep, missing/stale index entries, legacy databases
  • Fallback wiki building from extracted events (LM unavailable)

Privacy & Security

Data Sent to LM Endpoint

The following is sent to SESSHU_LM_URL:

  • Transcript diff (new characters since last ingest)
  • Recent turns (last N user-assistant message pairs)
  • Structured events (file paths, git commands, bash command summaries, error summaries)

⚠ Privacy Warning: Use a local endpoint (e.g., Ollama on localhost) for sensitive sessions. Do not use cloud LM endpoints with proprietary session content.

Sensitive Files & Modes

  • seed.md: Created with mode 0600 (user-only read/write)
  • wiki/sessions/*.md: Created with mode 0600
  • wiki/search.db: Treated as sensitive derived data
  • related_state.json, related_notice.json: Transient session data
  • debug.jsonl: Metadata only (no transcript content)

Config & Supply-Chain Isolation

Trusted config directory is never a project-local path:

  • Config dir (.env, prompts.json): Always ~/.sesshu/ (unless SESSHU_DATA_DIR env var set before hook invocation)
  • LM endpoint and API key read from config only, never from repo
  • Prevents repository from redirecting LM calls or injecting prompt templates

Hook Execution Model

  • Hooks installed in user-scope or repo-scope settings (not workspace-scoped)
  • Hook wrappers under hooks/ must be copied to runtime hook directory at install time
  • Sesshu imports only from standard library at runtime (no third-party dependencies)

Limitations & Extension Points

Known Limitations

  • Stateless hooks: Hooks have no cross-session memory; state persisted to filesystem (seed, wiki, cursor)
  • LM-dependent: Compression quality depends on LM quality; a poor model produces poor summaries
  • Keyword-based search: Wiki search uses simple keyword extraction + FTS5; semantic search not implemented
  • Linear transcript processing: Diff sent to LM line-by-line; structured chunking not implemented
  • No custom sections: Wiki page sections are fixed (12 standard headings); custom sections not supported

Extension Points

  • Custom prompts: Copy data/prompts.json to ~/.sesshu/prompts.json and edit. Customize section names, instructions, templates.
  • Custom adapters: Add new runtime by implementing HookAdapter protocol in src/sesshu/adapters/
  • Semantic search: Replace FTS5/grep in search.py with embedding-based retrieval (e.g., ONNX embeddings)
  • Related-session scoring: Replace cosine similarity in related.py with learned relevance model
  • Fallback enhancements: Extend fallback.py to extract and format priority-tiered events (P1-P4 severity)
  • Ingest modes: Already supported: sync (blocking) and background (async via subprocess lock)

Performance Tuning

  • LM latency: Use python3 scripts/measure_latency.py --url YOUR_ENDPOINT --models MODEL_NAME --runs 5
  • Ingest interval: Increase SESSHU_INGEST_MIN_INTERVAL to reduce LM call frequency
  • Threshold: Adjust SESSHU_THRESHOLD based on typical session duration and cost tolerance
  • Max input: Reduce SESSHU_MAX_INPUT to avoid truncation; increase to include more context

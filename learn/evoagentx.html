🔁 EvoAgentX：自動演化 LLM Agent 工作流的框架

從一句目標，自動生成 → 評估 → 演化多代理工作流 · 把「自我演化 agent」的理論做成能 pip install 的工具

Python · MIT Agent Workflow 框架 4 種 Optimizer

⓪ 一句話總結

EvoAgentX 是一個開源框架，用來自動「構建 → 評估 → 演化」以 LLM 為核心的智能代理與工作流。你給一個目標，它能自動生成多代理工作流，內建評分機制打分，再用演化演算法迭代改進工作流結構與提示——讓 agent「不只會工作，還會學」。

📌 一句話定位：把自我演化 Agent 那套研究理論(反饋驅動的迭代優化)做成能直接 pip install 的工具。維護者 EvoAgentX 社群，授權 MIT，Python 3.11+。

① 它解決什麼痛點

  • 手刻工作流很脆：靜態的提示鏈、手動編排的多代理系統，改一個環節就要全盤重調。
  • 提示調校靠人試：prompt 好不好只能人肉反覆試，沒有系統化的優化迴圈。
  • 沒有回饋迴路：跑完就結束，agent 不會從結果變好。

EvoAgentX 的答案：把「自動生成工作流 + 自動評估 + 自動演化」變成內建能力——類似軟體工程的持續測試與改進，只是對象是 agent 的工作流結構與提示。

② 核心能力

能力說明
自動構建從單一提示生成結構化的多代理工作流
內建評估自動替 agent 行為打分，作為演化的依據
自我演化用演化演算法迭代改進工作流與提示
豐富工具庫20+ 內建工具：Python 解譯器、搜尋、檔案系統、資料庫、瀏覽器自動化
記憶模組短期與長期記憶支援
人類迴圈(HITL)互動檢查點，關鍵步驟可人工介入
即插即用模型OpenAI、Qwen、Claude、Deepseek 等

③ 自我演化的核心：4 種 Optimizer

EvoAgentX 的「演化」不是玄學，而是一組可選的優化器，各自用不同策略改進提示或工作流：

Optimizer策略適合
TextGrad「文字梯度」——用 LLM 產生的自然語言回饋當梯度來改提示單點提示的精修
MIPRO模型無關的黑盒迭代優化(來自 DSPy 生態)多階段提示 + 少量標註評估
AFlow用蒙地卡羅樹搜尋(MCTS)做 RL 風格的工作流結構演化整個工作流的結構搜尋
EvoPrompt反饋驅動的動態提示演化提示的持續演化
怎麼選：要改單一提示→ TextGrad / EvoPrompt;要改多階段管線→ MIPRO;要動整個工作流的結構(誰接誰)→ AFlow。

④ 快速開始

# 安裝
pip install evoagentx
# 從一句目標自動生成多代理工作流
from evoagentx.workflow import WorkFlowGenerator
from evoagentx.models import OpenAILLM

llm = OpenAILLM(config=openai_config)
workflow_graph = WorkFlowGenerator(llm=llm).generate_workflow("你的目標描述")
# 之後可再接評估與 optimizer(TextGrad / MIPRO / AFlow / EvoPrompt)迭代演化
提醒：API 細節與參數以官方 GitHub / 文件最新版為準;此處僅示意最小流程。需要 Python 3.11+,依賴 LiteLLM、DSPy 等。

⑤ 模型與工具整合

  • 模型：原生 OpenAI / Qwen;或透過 LiteLLM、SiliconFlow、OpenRouter 使用 Claude、Deepseek 等。
  • 工具：20+ 內建工具包——Python 解譯器、Google 搜尋、MongoDB、FAISS、瀏覽器自動化等;支援 MCP 與 Docker。
  • 生態：建於 LiteLLM + DSPy 之上,優化器與 DSPy 系(MIPRO)一脈相承。

⑥ 在「自我演化」地圖上的位置

對照 自我演化 Agent 綜述 的三大維度,EvoAgentX 主要落在:

  • 環境中心 · Agentic 拓撲演化：AFlow 這類「工作流結構自動搜尋」正是拓撲演化的代表(綜述裡 AFlow、EvoAgent 同屬此類)。
  • 模型中心 · 推理時演化：TextGrad / EvoPrompt 的提示自我修正,屬「不改參數、改怎麼想」。
一句話:綜述頁講「有哪些演化路線」,EvoAgentX 是把其中「提示優化 + 工作流結構搜尋」這兩條做成可用框架的實作。想動手,從這裡開始。

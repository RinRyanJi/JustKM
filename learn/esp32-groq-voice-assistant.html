🔊 ESP32-S3 + Groq 語音助手:一顆 MCU 靠雲端 AI

techiesms 的開源專案:整個語音助手跑在單顆 ESP32-S3——按住按鈕說話、聽它答。所有 AI(聽/想/說)都走 Groq 雲端、一把免費 key 搞定:Whisper STT + gpt-oss-120b + Orpheus TTS,端到端約 2.2 秒。和站內「全本地」的路線正好相反——MCU 只管音訊 I/O 與串流。

⓪ 一句話總結

一顆 ESP32-S3 + 一顆 I2S 麥克風 + 一顆 I2S 擴大機,就是一台完整語音助手:按住 BOOT 鍵說話、放開,答案就念出來。MCU 本身不跑任何 AI——它負責錄音、把音訊串流上 Groq 雲、再把回傳的語音串流播出。三個模型都在 Groq:whisper-large-v3-turbo(聽)、openai/gpt-oss-120b(想)、orpheus-v1-english(說)。

端到端實測約 2221ms(STT 297 + LLM 1119 + TTS 805),一把 Groq 免費 key 即可。這是「端側裝置 + 雲端 AI」的極簡範例——和站內 Gemma Translator、VoxEMW「全本地」的取向剛好對照。

為什麼有意思:把「聽→想→說」整條鏈全丟雲端,MCU 只做它擅長的即時音訊 I/O + 串流。因為 ESP32-S3 記憶體極小(WiFi/TLS 後只剩 ~130KB heap),這個專案最精彩的工程,其實是「絕不緩衝整段音訊、只能邊錄邊傳邊播」——限制逼出漂亮的串流設計。

① 是什麼、為什麼有意思

市面上多數「本地語音助手」把模型塞進強力硬體(見站內 VoxEMW/4090、Gemma Translator/Pi 5)。這個專案走相反路線:硬體極廉價(一顆 MCU),智慧全外包給雲端。ESP32-S3 的角色只有兩個:

  • 即時音訊 I/O:用 I2S 收麥克風(INMP441)、推擴大機(MAX98357A)。
  • 串流搬運:錄音時邊上傳到 Groq,回話時邊接收邊播——因為記憶體根本放不下整段音訊(見 ④)。
兩條路線的取捨:雲端路線硬體便宜、模型隨時最新、能跑 120B 大模型,代價是要連網、要 API key、有額度限制、延遲吃網路;本地路線反之(隱私、離線、零 token 費,但硬體貴)。這個專案是「雲端路線」把成本壓到極致的示範。

④ 關鍵工程限制:記憶體逼你「只能串流」

這個專案最漂亮的工程,不在雲端,而在 MCU 端一個殘酷的算術:

← 左右滑動看完整圖 →
▲ 上傳用 HTTP chunked transfer encoding(不預先知道長度)把音訊邊錄邊送;下行音訊塊從 socket 收到、略緩衝就直送 I2S。整條鏈沒有一次持有完整音訊。
可偷師:在資源極小的裝置上,「串流」不是效能優化,而是可行性前提。當一次性資料量超過記憶體,就得把「先收完再處理」改成「邊收邊處理邊丟」——這和站內即時語音/語者分離的串流管線是同一種思路,只是被逼得更徹底。

⑤ 免費額度與成本

  • 一把免費 Groq key(console.groq.com/keys)就能跑全部三個模型。
  • 免費層總額 2000 requests;每個對話回合吃 3 個請求(STT/LLM/TTS 各一)→ 約可用 666 回合。
  • 即時剩餘額度會回在回應標頭裡;超額回 HTTP 429,依錯誤訊息等待。
  • Orpheus TTS 首次使用要在 Groq playground 接受一次條款(否則回 HTTP 400)。
成本觀點:硬體約幾百元台幣、AI 免費起步——這是它相對「本地大模型」最大的優勢:入門成本極低。代價是規模化後要付 Groq 費用、且離線就不能用。

⑥ 軟體設定與控制

環境與依賴

  • 板子套件:「esp32 by Espressif」3.x(README 用 3.3.11);2.x 不相容(缺 ESP_I2S.h)。
  • 函式庫:ArduinoJson 7.x;WiFi.h / WiFiClientSecure.h / ESP_I2S.h 隨板子套件附帶。
  • 設定:把 secrets.h.example 複製成 secrets.h,填 WiFi 與 Groq key;Tools 設 Board=ESP32S3 Dev Module、PSRAM=Disabled、USB CDC On Boot 依連接埠類型。
  • 草稿頂端有單一「設定區」:帳號/網路、模型選擇(含 reasoning effort / temperature / token 上限 / system prompt)、音量與 pre-buffer、麥克風(取樣率/時長/靜音門檻)、對話記憶深度、腳位對應。

⑦ 值得偷師的思路 / 來源

  1. 把智慧外包、讓 MCU 只做 I/O。端側裝置不必自己跑模型;它最擅長的是即時音訊搬運,AI 交給雲端,硬體就能壓到極廉價。
  2. 在小記憶體上,串流是可行性前提。130KB heap 放不下 320KB 音訊 → 只能 chunked 邊錄邊傳、邊收邊播;沒有「先存整段」的選項。
  3. 用 OpenAI 相容/單一供應商把三模型串起來。STT+LLM+TTS 都在 Groq、一把 key,大幅簡化嵌入式端的實作與憑證管理。
  4. 把限制當設計指南。PSRAM 停用、逐腳位串流、pre-buffer 調音——這台的每個設計幾乎都是被 MCU 資源逼出來的,反而乾淨。
  5. 雲端 vs 本地是取捨,不是對錯。雲端=便宜/最新/大模型,但要網路與額度;本地=隱私/離線/零 token 費,但硬體貴。按場景選(對照站內 Gemma Translator / VoxEMW)。

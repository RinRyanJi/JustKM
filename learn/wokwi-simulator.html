🔌 Wokwi:瀏覽器裡的真·指令級電子模擬器(含 AI 代理 & CI)

Wokwi 是一個線上電子模擬器:在瀏覽器裡接線、寫韌體、跑模擬 Arduino / ESP32 / STM32 / Raspberry Pi Pico 等板子與上百種零件。關鍵在於它不是畫動畫——它把你的程式編譯成真實的二進位韌體,再一條指令一條指令地執行,就像真的 MCU。再加上虛擬 WiFi 連真網路、8 通道邏輯分析儀、GDB、自訂晶片,以及能給 CI 與 AI 代理用的無頭模擬。

⓪ 一句話總結

一個在瀏覽器裡「跑真韌體」的電子模擬器。你把 Arduino/ESP32/Pico 的程式丟進去,Wokwi 編譯成二進位,再像真晶片一樣逐指令執行,同時模擬接在腳位上的 LED、感測器、顯示器、馬達。你不用買零件、不會燒板子、分享只要一個連結。它一路長成了認真的工程工具:虛擬 WiFi 連真網路、邏輯分析儀匯出 VCD、GDB 除錯、用 C/Rust 寫自訂晶片,還能無頭跑進 GitHub Actions 做韌體自動測試,甚至讓 Claude Code / Cursor / Codex 這類 AI 代理「沒有板子也能測自己寫的韌體」。

為什麼這頁放在「嵌入式」群組:站內 NavBot-EN01 韌體、ESP32-S3 語音助手 這些 ESP32 專案,正是 Wokwi 能「先在瀏覽器裡跑起來、再燒上板」的那類東西。作者是 Uri Shaked(也是開源 AVR 模擬引擎 AVR8js 的作者)。個人使用免費,商用有付費方案。

① 它到底在做什麼:逐指令跑真韌體

很多「模擬器」只是把 digitalWrite 畫成亮燈的動畫。Wokwi 不是。官方 FAQ 說得很直白:它把你的程式碼編譯成二進位韌體,然後一次一條指令地執行那個二進位,就像真的微控制器一樣。這代表時序、暫存器、周邊、函式庫都是真的在跑——所以你在模擬裡遇到的 bug,通常真板上也會遇到。

③ 場景就是一個 diagram.json

整個電路不是圖片,是一份 diagram.json:哪些零件(parts)、擺在哪(座標/旋轉)、屬性(attrs),以及怎麼接線(connections)。因為是純資料,它好分享、好版本控制、也好被程式或 AI 生成與檢查。

{
  "version": 1,
  "author": "Uri Shaked",
  "editor": "wokwi",
  "parts": [
    { "id": "esp", "type": "board-esp32-devkit-c-v4", "top": 0, "left": 0 },
    { "id": "led1", "type": "wokwi-led", "left": 100, "top": 50, "attrs": { "color": "red" } }
  ],
  "connections": [ [ "esp:D13", "led1:A", "green" ], [ "led1:C", "esp:GND", "black" ] ]
}
// 每個 part 的 id 必須唯一;wokwi-cli lint 可檢查未知零件/接腳/重複 id

零件 type 像 wokwi-led、wokwi-esp32-devkit-v1、board-pi-pico-w、board-esp32-c3-devkitm-1…;若專案含程式,diagram 裡就要放一顆對應的 MCU 來跑它。這套零件外觀也有開源的 Wokwi Elements 元件庫。

④ 虛擬網路與 IoT:連得上真的網際網路

這是 Wokwi 最「不像模擬器」的地方:它模擬一個能連真網路的 WiFi。ESP32 掃到一個開放 AP Wokwi-GUEST(免密碼),連上後就能發 HTTP/HTTPS、WebSocket、MQTT、NTP 對時——拿來原型 IoT 專案剛剛好。

// ESP32 (Arduino) 連上虛擬 WiFi;指定通道 6 可省掉約 4 秒掃描
#include <WiFi.h>
void setup() {
  Serial.begin(9600);
  WiFi.begin("Wokwi-GUEST", "", 6);
  while (WiFi.status() != WL_CONNECTED) { delay(100); Serial.print("."); }
  Serial.println(" Connected!");
}
  • 對外(ESP32 當 client 連出去):開箱即用。
  • 對內(在 ESP32 裡跑 HTTP server、想從你瀏覽器連進去):需要 Wokwi 私有 IoT 閘道(Private IoT Gateway),它也讓模擬裡的板子連上你本機的區域網路——多機通訊就靠這招。
  • MicroPython 用 network.WLAN + urequests / umqtt;Rust 用 esp-idf-svc 的 EspWifi。

⑤ 除錯三寶:邏輯分析儀 / GDB / 自訂晶片

← 左右滑動看完整圖 →
▲ 邏輯分析儀把腳位錄成 VCD,拖進 PulseView 就能看 I2C/UART 波形並自動解碼;自訂晶片讓你把 Wokwi 沒有的感測器/記憶體/儀器自己寫出來。
  • 邏輯分析儀:8 通道(D0–D7)、1GHz 取樣、活動 LED、可設觸發(例如按鍵或 SPI SS 啟動才錄)。停止模擬會下載 wokwi-logic.vcd(Value Change Dump),用 PulseView / GTKWave 開並解碼 UART / I2C / WS2812 等。VS Code 版會自動存成 wokwi.vcd。
  • GDB:F1 → Start Web GDB Session,對 Arduino / Pi Pico 原始碼逐行除錯(tbreak / c / layout src / next)。
  • Chips API(beta):用 C 寫自訂晶片,核心是 chip_init() + chip_state_t + 腳位監看/定時器;printf() 輸出到「Chips Console」分頁。也能用任何編到 WASM 的語言(Rust、AssemblyScript),Verilog 為實驗性。

⑥ 從玩具到工程:VS Code 擴充 + Wokwi CI

Wokwi for VS Code

把模擬搬進你原本的開發環境:用 PlatformIO / ESP-IDF / Pi Pico SDK / Zephyr / NuttX / Rust / Arduino CLI / MicroPython / Sming 等工具鏈自己編譯出真韌體(ELF),Wokwi 直接模擬它。設定只有兩個檔:wokwi.toml(指向韌體路徑等)+ diagram.json(電路)。需要一次性的免費授權:F1 → Wokwi: Request a new License 走瀏覽器領取。也支援離線模式。

Wokwi CI / GitHub Actions ——「Wokwi in the Loop」

把模擬變成自動化測試:每次 commit 都在雲端跑你的韌體,把 Serial 輸出串回 CI,比對預期值、不符就讓測試失敗。這套方法叫 WITL(Wokwi in the Loop)——兼具單元測試的快與硬體測試的真。

⑦ 給 AI 代理用:沒有板子也能測韌體

這條線正好接上站內 Crucible、agent-desktop 的精神——給 AI 代理一個能實際驗證自己成果的介面。Wokwi 的做法:

  • Agent skills:教 Claude Code / Cursor / Codex / Copilot 用 wokwi-cli 測韌體——找記憶體洩漏、測顯示器 UI、除錯當機、驗證 ESP-IDF build。代理寫完韌體,不必桌上有板子就能跑起來看結果。
  • MCP 支援(實驗性):wokwi-cli 內建 Model Context Protocol 支援,讓 AI 助手直接驅動 Wokwi 的模擬能力——跑自動測試、模擬硬體行為、把 Wokwi 接進 AI 開發工作流。
為什麼這對嵌入式 AI 很關鍵:韌體最難自動驗證——真板要燒錄、要接線、要有人看燈。Wokwi 把「跑真韌體 + 讀 Serial + 操作虛擬輸入」變成一個無頭、可程式、可比對的迴圈,AI 代理於是能像對待一般程式測試那樣迭代韌體。這正是站內 NavBot 韌體 那類專案可以搭的驗證環。

⑧ 收費 · 開源 · 重點 · 來源

收費與開源

  • 個人使用免費;商用/專業有付費方案(Hobby / Hobby+ / Pro),差別在 CI 分鐘、單場時長、上傳二進位到 SD 卡等。
  • 核心的雲端模擬平台是商業產品(非全開源),但關鍵引擎與元件是開源的:AVR8js(JS 寫的 AVR 模擬引擎)、Wokwi Elements(零件外觀元件庫)。ESP32 WiFi 模擬是靠逆向硬體做出來的。(各元件確切授權請以官方倉庫為準。)
  • 作者 Uri Shaked;社群在 Discord。名字「Wokwi」是刻意挑的無意義短詞。

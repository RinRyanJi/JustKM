📊 CharTool:給多模態模型掛「工具」的圖表推理

2026 · 上海交大 X-LANCE · 一個 7B 小模型,靠「該切圖時切圖、該寫程式時寫程式」的智慧體策略,在複雜圖表推理上媲美甚至打敗大數十倍的閉源大模型

⓪ 一句話總結

CharTool 不是「更大的看圖模型」,而是「會用工具看圖的智慧體」。它把一個 7B 的多模態模型(Qwen2.5-VL)改造成 agent:遇到細小刻度看不清,就主動裁剪放大局部;遇到數值比較/累加/比率,就寫 Python 交給解釋器算,而不是用參數硬湊。透過雙源數據集 DuoChart + 強化學習,模型自己學會「何時該切圖、何時該寫碼、何時直接答」。

為什麼收進 JustKM:它是「工具整合視覺推理(tool-integrated visual reasoning)」的一個乾淨範例——把大模型的兩個老毛病(看不清細節、算術會幻覺)用「按需採樣 + 數值程式化」兩把工具解掉。這套「與其把模型做大,不如教它用對工具」的思路,遠不只用在圖表。

① 兩個痛點:大模型看複雜圖表為什麼會錯

多模態大模型(MLLM)直接「看」一張複雜圖表時,常在兩個地方翻車:

痛點為什麼會發生典型錯誤
👁️ 看不清細節高密度、多子圖、字體極小的區域,被壓進固定解析度輸入後,細小刻度/標籤的像素資訊直接丟失讀錯座標軸數字、認錯圖例、把兩條靠近的線看混
🧮 數值計算幻覺比較、累加、比率、趨勢這類運算,靠模型參數「心算」,本質是用機率生成數字,不是真的在算加總算錯、比率算反、「A 比 B 多幾%」給出一個看似合理但錯的數

關鍵洞察:這兩件事,大模型再大也不容易根治——前者是輸入解析度的物理限制,後者是「生成」與「計算」的本質差異。與其堆參數,不如給它「放大鏡」和「計算機」。

② 核心機制:給模型掛兩個外部工具

CharTool 用智慧體(Agent)架構,讓模型在「邊想邊做」的過程中,按需呼叫兩個外部工具,把工具回傳的結果(放大後的圖塊 / 程式輸出)再餵回去繼續推理。

工具解決哪個痛點怎麼做

🐍 Python 代碼執行數值計算幻覺比較/累加/比率/趨勢等運算,生成 Python 腳本交由解釋器執行,確保算術 100% 精確,而非用參數硬算

③ 決策與訓練:讓模型學會「何時用哪個工具」

掛上工具只是第一步。真正難的是:模型要自己判斷「這一題,該切圖?該寫碼?還是直接答就好?」亂用工具反而拖慢又出錯。CharTool 靠訓練把這個「工具使用策略」學起來。

訓練兩階段:SFT 冷啟動 → 強化學習

(這裡對「純 RL」的印象做個修正:CharTool 是兩階段訓練。)

  1. SFT 冷啟動:先用「帶推理與工具調用軌跡」的資料做監督微調,讓模型先會基本的「邊想邊呼叫工具」格式。
  2. 強化學習:再在 DuoChart 上用 RL(以 VeRL 框架、在隔離沙箱裡端到端訓練、搭配工具感知獎勵 tool-aware reward)——獎勵「有效地用對工具 + 答案正確」,讓模型自主收斂出好的工具使用時機。

DuoChart:雙源數據管線

訓練資料來自 DuoChart——一條「合成圖表 + 真實世界圖表」的雙源數據管線。合成資料可規模化、標註乾淨、覆蓋各種圖型與計算;真實圖表則保留雜訊與多樣性,避免模型只會做「乾淨的考題」。兩者搭配,兼顧量與真實度。

為什麼要 RL 而非只靠 SFT:「何時該動工具」是一個決策問題——同一題可能有多條解法,對錯要看最終答案。用 RL 以「答案正確 + 工具用得有效」當獎勵,比硬塞固定範例更能讓模型學到靈活、泛化的策略。這與站內 提示/流程自動優化 是同一種「把試錯變成可搜尋的優化」的精神。

④ 以小博大:為什麼給人「更強/更快」的印象

CharTool 最吸睛的地方,是用 7B 打贏大數十倍的模型。論文報告的關鍵數字:

指標提升意義
CharXiv(推理集)+8.0%(7B);+10.1%(3B)最難的「圖表推理」評測,大幅提升
ChartQAPro+9.78%進階圖表問答,近一成提升
平均分(論文報告)66.52高於 GPT-4o(61.52)、Claude 3.5 Sonnet(63.62),並小勝體積大十倍的 Qwen2.5-VL-72B(66.02)

「更強又更輕」的兩個原因

  • 以小博大:7B 的推理表現媲美甚至擊敗體積龐大數十倍的閉源多模態模型——因為它把「看不清、算不準」這兩個大模型也治不好的病,用工具直接解掉。
  • 感知負擔更輕:不需要把全圖塞成超高 token 的全解析度輸入,而是按需精準局部採樣 + 數值程式化,在複雜推理上大幅降低「純靠視覺注意力硬解」帶來的錯誤率與計算負載。

⑤ 定位:它站在哪條研究光譜上

CharTool 不是憑空出現,而是 2025–2026「讓模型用工具/程式來推理視覺」這條線的一員。理解它在光譜上的位置,更能看清它的取捨:

路線代表與 CharTool 的關係
用 RL 教模型「用圖思考」DeepEyes(thinking with images)「主動切圖放大」這一招的概念前身;CharTool 把它和程式計算合併
Code-as-Thought(以程式當思路)Visual Programmability、ChartReasoner「寫 Python 算數值」的思路來源;把圖表理解轉成可執行程式
放大式視覺搜尋V*(zoom-in visual search)、program-of-thought更上游的通用概念:局部放大 + 程式化思考
同期圖表推理競品Chart-RVR、ChartAgent、Chart-FR1…2026 圖表推理是熱門賽道,CharTool 以「雙工具 + Agentic RL + 雙源數據」切入
一句話定位:CharTool = 「DeepEyes 的切圖放大」×「Code-as-Thought 的程式計算」,再用 Agentic RL 學會兩者的使用時機,並用 DuoChart 餵資料。它的貢獻不在單一創新,而在把這幾條線整合成一個能自主調度工具的圖表智慧體。

⑥ 值得偷師的思路(不做圖表也用得到)

  1. 先分辨「感知問題」還是「計算問題」。看不清 → 給放大鏡(局部採樣);算不準 → 給計算機(程式執行)。很多「模型不準」其實是用錯了肌肉。
  2. 把不擅長的事外包給工具,而不是堆參數。算術交給解釋器保證 100% 精確,比訓練更大的模型去「心算」划算得多——這是 工具整合推理 的通則。
  3. 按需採樣,別把全部塞進 context。與其把全圖/全文以超高 token 硬灌,不如讓模型自己決定要放大哪一塊,降低感知負擔與錯誤率。
  4. 「何時用工具」本身要學。用 RL 以「答案對 + 工具用得有效」當獎勵,讓模型學會靈活調度,而非寫死規則或濫用工具。
  5. 合成 + 真實雙源資料。合成保量與覆蓋、真實保多樣與雜訊——DuoChart 的配方適用於幾乎所有需要規模化訓練資料的任務。

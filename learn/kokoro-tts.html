🗣️ Kokoro-82M:82M 參數的開源 TTS 怎麼做到又小又快

Kokoro 是一個只有 8,200 萬參數、Apache-2.0 開放權重的文字轉語音模型,卻能逼近大模型的音質,而且明顯更快、更省。本頁從原始碼層拆解它的兩層設計(語言盲的 KModel × 語言感知的 KPipeline)、StyleTTS 2 血統的模型架構、聲線向量、多語 G2P、長文本切塊,以及部署與 ONNX。

⓪ 一句話總結

Kokoro-82M 是「小到能塞進本機、卻不太犧牲音質」的開源 TTS。它走 StyleTTS 2 的非自迴歸、以「時長預測 + 對齊」為核心的路線,不是自迴歸也不是擴散,所以推論快;用 iSTFTNet 這種輕量聲碼器直接以反短時傅立葉(iSTFT)出波形;文字端靠 misaki 這個字素轉音素(G2P)庫把文字變音素。輸出 24kHz 單聲道。

程式上它刻意拆成兩個角色:KModel(語言盲)只吃音素 + 一個聲線向量就吐音訊;KPipeline(語言感知)負責各語言的 G2P、切塊、與管理聲音包。權重是 Apache-2.0,可商用、可部署到生產或個人專案。

最快上手:pip install kokoro soundfile + 系統裝 espeak-ng,然後 KPipeline(lang_code='a') 選一個聲音(如 af_heart)就能生成。底層 G2P 用的是 misaki。

① 82M 憑什麼:小模型的定位

現在很多高品質 TTS 動輒數億到數十億參數,推論貴、難落地。Kokoro 反其道:只有 82M 參數,卻靠架構選擇把「音質 / 速度 / 成本」拉到一個很實用的平衡點:

面向Kokoro 的取捨帶來的好處
參數量82M(輕量)可跑 CPU / 一般 GPU / Apple Silicon;記憶體與延遲都低
生成範式非自迴歸 + 時長預測(StyleTTS 2 式)一次前傳算完整段,不像自迴歸逐 token,速度快
聲碼器iSTFTNet(以 iSTFT 出波形)比純神經聲碼器省算力,合成快
授權權重 Apache-2.0可商用、可自由部署,不綁 API 額度
音色來源預存「聲線向量」(voicepack)換聲音只換一個向量,不需重訓

它也被加入社群的 TTS Spaces Arena 作為競爭者,以這個體量拿到超出預期的評價。訓練資料方面,作者致謝頁提到大量合成訓練資料的貢獻者——換句話說它走的是「用合成語料把小模型餵到夠好」的路。

誠實邊界:小模型不是萬能——極端表現力、罕見腔調、複雜情感的細膩度,仍可能不及最大型商用 TTS。Kokoro 的價值在「本機、可控、夠好、可商用」,不是「全面第一」。本頁的架構細節取自其開源 kokoro 套件原始碼;主觀評價字眼請自行聽 samples 驗證。

② 兩層設計:KModel(語言盲)× KPipeline(語言感知)

Kokoro 最關鍵的工程決策,是把「懂語言的部分」和「純聲學合成」徹底切開:

  • KModel 是語言盲的。它只認音素字串 + 一個聲線向量 ref_s,輸出音訊。它內部存 vocab(音素→input_ids),所以不需要知道你講哪國語言。一個 KModel 實例可被多個 KPipeline 共用,避免重複佔記憶體。
  • KPipeline 是語言感知的。它做兩件事:(1) 對特定語言做 G2P(字素轉音素)並切塊;(2) 管理與惰性下載聲音包。原則是每種語言一個 KPipeline,但共用同一個 KModel。
← 左右滑動看完整圖 →
▲ 懂語言的髒活(G2P、切塊、選聲線)全在 KPipeline;KModel 只做純聲學合成,因此可跨語言重用同一份權重與記憶體。

③ 模型架構拆解:StyleTTS 2 的骨架

從 KModel 原始碼可以清楚看到五個子模組,對應 StyleTTS 2 的設計。給定音素 input_ids 與聲線向量 ref_s,一次前傳的流程是:

← 左右滑動看完整圖 →
▲ 五個子模組:PL-BERT(CustomAlbert)→ ProsodyPredictor(時長 + F0 + 能量)→ 對齊 → TextEncoder → iSTFTNet Decoder。時長預測是「非自迴歸卻能對齊」的關鍵。

逐步對照原始碼

  1. PL-BERT 取上下文:bert(input_ids)(一個 CustomAlbert,即音素級 BERT)→ 經 bert_encoder 線性投影成 d_en。
  2. 時長預測:ProsodyPredictor 用聲線向量的語調半段 s = ref_s[:, 128:],跑 LSTM + duration_proj,sigmoid 後除以 speed 得到每個音素要佔幾影格。
  3. 建對齊:用 repeat_interleave 依時長把每個音素展開,得到硬對齊矩陣 pred_aln_trg(這就是非自迴歸還能對齊語音的手法)。
  4. 韻律:F0Ntrain 產出 F0_pred(音高曲線)與 N_pred(能量)。
  5. 聲學展開:TextEncoder 的輸出經同一對齊矩陣變成 asr。
  6. 合成波形:decoder(asr, F0_pred, N_pred, ref_s[:, :128]) —— iSTFTNet 結合音色半段,以反短時傅立葉出波形。
為什麼快:沒有自迴歸逐步生成(不像早期 Tacotron/AR TTS),整段時長一次算完、對齊一次展開、聲碼器用 iSTFT 而非逐點神經生成——三者疊起來,就是 82M 也能即時的原因。

④ 聲線向量 ref_s:一個向量把「音色」與「語調」分兩半

Kokoro 換聲音不靠重訓,而是換一個預存的聲線向量(voicepack,一個 .pt 張量)。原始碼裡它被切成兩半各司其職:

切片送到哪負責什麼
ref_s[:, 128:](後半)ProsodyPredictor語調 / 韻律風格:影響時長、音高、能量的走向
ref_s[:, :128](前半)iSTFTNet Decoder音色 / 音質:影響最終聲音聽起來像誰

這種「風格向量分段注入」正是 StyleTTS 2 的招牌:把「怎麼唸」(prosody)和「像誰的嗓」(timbre)解耦,所以你可以只換向量就換一個人聲,甚至(見下一節)把兩個聲線向量平均出一個新音色。

⑤ 語言與 G2P:misaki 為主,espeak-ng 補位

把文字變成音素(G2P)是 KPipeline 的核心。不同語言走不同引擎:

lang_code語言G2P 引擎需要安裝
a美式英語misaki en.G2P + espeak OOD 補位misaki[en] + espeak-ng
b英式英語同上(british=True)同上
j日語misaki ja.JAG2Pmisaki[ja]
z中文(普通話)misaki zh.ZHG2P(可帶英文 callback)misaki[zh]
e / f / h / i / p西/法/印地/義/巴葡espeak EspeakG2Pespeak-ng
  • 英語走 misaki + espeak 補位:遇到訓練沒見過的字(OOD)時,用 EspeakFallback 補音素;若連 fallback 都沒有,未知詞會被直接略過(unk='')。
  • 中文有專屬 v1.1 檢查點:hexgrad/Kokoro-82M-v1.1-zh(權重檔 kokoro-v1_1-zh.pth),ZHG2P 會用 version='1.1',還能透過 en_callable 處理句中夾雜的英文。
  • espeak 系語言尚未實作切塊:原始碼會警告——這些語言的長文本可能被截斷,除非你自己用 \n 分段。
espeak-ng 是硬相依。英語 OOD 補位與多個非英語語言都靠它。Windows 要裝 .msi、conda 環境可能要 libstdcxx 才能正確載入 espeak(見 ⑧)。

⑥ 聲音包(voicepacks)與「混音」

聲音就是 HF 上 voices/{名稱}.pt 的張量,用到才惰性下載並快取。命名有規律,例如 af_heart、af_bella:第一碼是語言(a=American)、第二碼是性別(f=female),後面是名字。

兩個實用招式

  • 多聲線平均 = 混出新音色:load_voice('af_bella,af_jessica') 會把多個聲線向量堆疊後取平均,得到一個介於兩者之間的新聲音(分隔符預設逗號)。
  • 直接餵張量:也可以 torch.load('path/to/voice.pt') 後把 tensor 當 voice= 傳進去,不必用名稱。
  • 語言要對齊:聲線名稱開頭若和 pipeline 的 lang_code 不符,會發出「語言不匹配」警告——聲線是配合特定語言調出來的。
# 混兩個聲音成新音色
gen = pipeline(text, voice='af_bella,af_jessica')   # 兩個 voicepack 取平均

# 或直接載入聲線張量
voice_tensor = torch.load('path/to/voice.pt', weights_only=True)
gen = pipeline(text, voice=voice_tensor)

⑦ 長文本切塊:510 音素上限與「標點瀑布」

模型的上下文長度來自 ALBERT 的最大位置數;程式強制 音素數 + 2 ≤ context_length,實務上一段最多約 510 個音素 token。所以長文本必須切塊,而 Kokoro 的切法很講究——盡量切在自然停頓處,靠 waterfall_last 這個「標點瀑布」:

← 左右滑動看完整圖 →
▲ waterfall_last:優先在句末標點切,退而求其次冒號分號,再退逗號破折號,同時確保每段 ≤510 音素、收尾標點不被切散。

你也能在呼叫時用 split_pattern=r'\n+' 先按換行粗切,generator 會逐段回傳 (字素, 音素, 音訊),方便你邊生成邊存檔或串流播放。

⑧ 部署、加速與 ONNX

安裝與相依

  • 基本:pip install kokoro>=0.9.4 soundfile;系統裝 espeak-ng(Linux apt-get install espeak-ng)。
  • Windows:到 espeak-ng releases 下載對應 .msi 安裝。
  • conda 相依問題:官方建議的 environment.yml 會裝 libstdcxx~=12.4.0 以正確載入 espeak。
  • 中文 / 日文:另外 pip install misaki[zh] 或 misaki[ja]。

裝置與加速

  • 自動選裝置:有 CUDA 用 cuda;否則若開了 PYTORCH_ENABLE_MPS_FALLBACK=1 且有 MPS 就用 mps;再不然 cpu。
  • Apple Silicon:M1/M2/M3/M4 設 PYTORCH_ENABLE_MPS_FALLBACK=1 啟用 GPU 加速。
  • CPU 也能跑:82M 的體量讓純 CPU 推論仍可用,適合沒有 GPU 的環境。

ONNX

原始碼提供 KModelForONNX 包裝,把 forward_with_tokens(input_ids, ref_s, speed) 暴露成適合匯出的介面(回傳 waveform, duration),方便匯出 ONNX 到非 PyTorch 的推論環境部署。

# 最小可跑範例
from kokoro import KPipeline
import soundfile as sf

pipeline = KPipeline(lang_code='a')          # 'a' = 美式英語
gen = pipeline("Hello from Kokoro.", voice='af_heart', speed=1)
for i, (gs, ps, audio) in enumerate(gen):
    sf.write(f"{i}.wav", audio, 24000)         # 24kHz 輸出

⑨ 重點 · 關聯 · 來源

八個帶得走的重點

  1. 82M、Apache-2.0、24kHz——小、可商用、可本機。
  2. 血統是 StyleTTS 2(由 @yl4579 設計),非自迴歸 + 時長對齊,所以快。
  3. KModel 語言盲、KPipeline 語言感知,一個 KModel 可被多語言 pipeline 共用。
  4. 五模組:PL-BERT → ProsodyPredictor(時長/F0/能量)→ 對齊 → TextEncoder → iSTFTNet Decoder。
  5. 聲線向量分兩半:後半給韻律、前半給音色;換聲音只換向量。
  6. G2P 用 misaki,espeak-ng 補位;espeak 系語言尚未做切塊。
  7. voicepack 可平均混音,也可直接餵張量。
  8. 長文本靠「標點瀑布」切塊,每段 ≤510 音素。

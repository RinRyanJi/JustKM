✂️ 用小模型找長文最佳斷點:Jina 的 RAG 分段實驗

Jina AI「分塊系列」第三部(2024/10/25,Alex C-G、Andrei Ungureanu)。前兩部講了後期分塊如何抵抗不佳的邊界;這一部把焦點放在「斷點該切哪」。關鍵前提是:既然後期分塊已扛住語境損失,選斷點時就能純粹為可讀性著想。他們以 qwen2-0.5b-instruct 訓練了三個分段小模型,並和 Jina Segmenter API 做 ROUGE-L 基準對比。本頁完整拆解模型、資料、訓練數字、結果與方法論。

⓪ 一句話總結

把「文件怎麼切」從規則升級成一個小模型學的任務。這是 Jina「分塊系列」第三部:前兩部證明後期分塊(late chunking)能抵抗不佳的邊界、減少嵌入時的語境損失;因此這一部主張——選斷點時可以純粹為「可讀性」著想(對人與 LLM 都好讀),不必再怕語義/上下文流失。他們以 qwen2-0.5b-instruct 訓練了三個分段模型(simple/topic/summary),在程式碼、表格、清單這類結構化內容上切得比傳統方法連貫。

一句話結論:在 ROUGE-L 基準上,三個新模型都勝過 Jina Segmenter API,其中 topic-qwen-0.5(受思維鏈啟發、依主題切)平均分數最高,尤其適合多主題長文。

① 分割問題:RAG 的核心

分割是 RAG 系統的核心。「怎麼把長文件切成連貫、可管理的片段」直接影響檢索與生成的品質——從答案相關性到摘要品質都受它牽動。傳統切法有結果,但有共同的局限:

  • 固定 token 長度 / 固定句數:簡單,但完全不看語義邊界。
  • 正則 / 規則式:比較進階,但規則寫死,遇到模糊主題時容易產生破碎片段。

兩類方法的共同問題:不考慮語義邊界、處理模糊主題時破碎。作者的觀點是——就算有後期分塊撐腰,「每個片段本身要盡可能有意義」仍然關鍵:LLM 依賴連貫、結構良好的資料才能生成準確回應;片段殘缺,再好的後期分塊也救不回上下文與準確度。

② 關鍵前提:後期分塊扛語境,分割專注「可讀性」

這篇最重要的心法,其實在一開始就講明:

「後期分塊可以處理好的與不好的斷點,所以可讀性成為你的主要考量。」——既然嵌入階段的語境損失已被後期分塊吸收,決定斷點時就不必再糾結語義流失,而能專心把每段切得對人與 LLM 都好讀、好理解。

但這不代表可以亂切:斷點對人類和 LLM 的可讀性仍然重要。所以他們訓練分段模型,目標是「維持語義連貫 + 妥善處理複雜結構」,把可讀性做到最好。也就是說——後期分塊與好的分割是兩件互補的事(見 ⑨),無論用不用後期分塊,穩固的分割策略對有效的 RAG 都是必要的。

③ 為什麼選小型語言模型(SLM)

他們做 SLM,是為了解決傳統技術的具體痛點——特別是程式碼片段,以及表格、清單、公式這類複雜結構。傳統方法靠 token 計數或死板的結構規則,很難維持語義連貫內容的完整性:例如程式碼常被切成好幾段,上下文被打斷,下游系統更難理解或準確檢索。

訓練一個專門的 SLM,目的是讓模型智慧地辨識並保護有意義的邊界,讓相關元素待在一起。好處不只是 RAG 檢索品質,還包括下游的摘要、問答等任務——這些都需要連貫、上下文相關的片段。相較傳統方法的僵硬邊界,SLM 提供的是更具適應性、更任務特異的解法。

④ 三個模型 + 「只輸出片段頭部」機制

三個變體全部以 qwen2-0.5b-instruct 為基礎,對應「從單純到精緻」的三種策略:

← 左右滑動看完整圖 →
▲ 三個模型策略不同,但共用同一個聰明設計:只輸出「片段頭部」,不複製整段內容。
  • simple-qwen-0.5(jinaai/text-seg-lm-qwen2-0.5b):依文件的結構元素辨識邊界,最簡單、對基本需求高效。
  • topic-qwen-0.5(…-cot-topic-chunking):受思維鏈(CoT)推理啟發,先辨識文本中的主題(例如「第二次世界大戰的開始」),再用主題定義邊界。確保每段主題連貫,初步測試最接近人類直覺,適合多主題文件。
  • summary-qwen-0.5(…-summary-chunking):除了切段,還為每段生成摘要;對長文問答等 RAG 任務很有優勢,但訓練需要更多資料。
關鍵設計——「只回片段頭部」:三個模型都不生成完整片段,只輸出每段的截斷版(片段頭部:關鍵點或子主題)。這逼模型專注「語義轉換」而非把輸入原封不動複製到各段,因此邊界偵測與連貫性都更好,而且生成文字更少 → 更快。檢索時,再依這些片段頭部把原文切開、重建完整片段。

⑤ 資料集與資料增強

基底資料:wiki727k

用 wiki727k——從維基百科文章抽出的大規模結構化文本片段集,超過 727,000 個文本部分(介紹、章節、小節等),出自論文《Text Segmentation as a Supervised Learning Task》。

用 GPT-4 生成訓練配對

對每篇文章,先用簡單規則切段(先在 \n\n\n 切、再在 \n\n 切),然後請 GPT-4 為每個片段生成「5–10 字的主題 + 一句摘要」,組成 {sections, topics, summaries} 的 JSON 訓練結構(依模型變體取用不同欄位)。

刻意加噪聲 + 補足複雜結構

  • 加噪聲:洗牌資料、隨機插入字元/單詞/字母、隨機移除標點,並一律移除換行字元——逼模型別只靠換行等表面線索。
  • 補複雜結構:上述還不夠;為了讓模型能產生連貫片段而不破壞程式碼,再用 GPT-4o 生成的程式碼、公式、清單擴充資料集,提升它處理各種文件結構的能力。

⑥ 訓練設置與數字

設置

  • 框架:Hugging Face transformers + 整合 Unsloth 做優化——省記憶體、加速訓練,讓小模型能吃大資料集有效訓練(據「我們學到了什麼」段:可在單張 Nvidia 4090 上跑)。
  • 優化器 / 調度器:AdamW + 線性學習率調度器,設預熱步驟穩定初期訓練。
  • 實驗追蹤:Weights & Biases 記錄訓練/驗證損失、學習率、整體表現。

⑦ 分割結果對照

作者用 Jina Reader 抓一篇 Jina 部落格文章的純文本(含頁首頁尾等),再丟給各方法切。結果差異鮮明:

方法切出來長怎樣
Jina Segmenter API非常精細,靠 \n、\t 等字元切,產生極小片段;前幾段甚至只切出導覽列的 search\n、notifications\n、NEWS\n,與文章內容無關,且每段保留的上下文極少。
simple-qwen-0.5依語義結構切成較長、各自連貫的段落。
topic-qwen-0.5先辨識文件主題,再依主題分段。
summary-qwen-0.5辨識段落邊界,並為每段內容生成摘要。

直觀差別:Segmenter API 把網頁切得太碎(連導覽列雜訊都成了片段);三個 SLM 都能切出「一段講一件完整事情」的區塊。

⑧ 基準測試:ROUGE-L

方法

  • 抓 8 篇 Jina 部落格文章,用 GPT-4o 生成 6 個問題 + 標準答案。
  • 每種分段法(含 Segmenter API)切段後,用 jina-embeddings-v3 生成嵌入,不做後期分塊、不做重排序,各自建索引,再用 RAG 查詢。
  • 公平起見:測 topic/summary 時只索引片段本身,不索引生成的主題/摘要(否則可能更強)。
  • 指標:ROUGE-L 的 F1(與標準答案比,越高越好);另量速度與磁碟空間(嵌入數 × 單個 1024 維向量大小)。

單題範例(僅示意,別以單題論英雄)

問題:「什麼因素影響 jina-embeddings-v2-base-en 的數字比較能力?」標準答案:tokenization 與 training data。

方法ROUGE-L F1答得如何
Jina Segmenter API0.167答不出具體因素
simple-qwen-0.50.279正確:tokenization + training data
topic-qwen-0.50.190對但多列了格式細節(這題偶然偏低)
summary-qwen-0.50.318正確:tokenization + training data
別被單題誤導:這題 topic-qwen-0.5 偏低純屬偶然。整體來看,topic-qwen-0.5 的平均 ROUGE 是所有分段法中最高的。

重要發現

把三個變體互比、並與 Segmenter API 對照後:三個新模型在分數上都更好,尤其是主題分段(topic)。這也回頭印證了 ①——就算有後期分塊,穩固的分割策略對 RAG 效能仍是必要的。

⑨ 分段 ≠ 後期分塊(late chunking),兩者互補

容易混淆的一點:分段模型和 Jina 系列前兩部的後期分塊功能不同,但正好互補。

← 左右滑動看完整圖 →
▲ 後期分塊決定「怎麼嵌入」、扛住語境損失;分段決定「切在哪」、專注可讀與連貫。正因前者撐腰,後者才能純為可讀性著想。

⑩ 重點 · 延伸 · 來源

八個帶得走的重點

  1. 這是 Jina 分塊系列 Part 3;核心心法:後期分塊扛語境,分割專注可讀性。
  2. 三個模型全以 qwen2-0.5b-instruct 為底:simple(結構)、topic(CoT 主題)、summary(段+摘要)。
  3. 只輸出「片段頭部」(截斷版),檢索時據此重建完整片段——邊界更準、更快。
  4. 資料:wiki727k + GPT-4 生 topic/summary + GPT-4o 生程式碼/公式/清單 + 噪聲注入(含一律去換行)。
  5. 訓練:transformers + Unsloth、AdamW + 線性預熱、W&B;simple/topic 各 10k 樣本(loss 0.16 / 0.45),summary 30k(loss 0.81,需更多資料)。
  6. 基準:ROUGE-L F1,8 文 6 問、jina-embeddings-v3、不後期分塊/不重排;三模型全勝 Segmenter API。
  7. topic-qwen-0.5 平均最高(別用單題論英雄)。
  8. 分段(切在哪)≠ 後期分塊(怎麼嵌入),互補。

延伸:更廣的「SLM + KB」版圖

這個實驗可放進更大的趨勢:在學術/垂直專業場景,用「小模型(能力)+ 知識庫(上下文)」取代「什麼都問大模型」——省算力、降幻覺(KB 提供精確文獻)、可私有部署、更新只需改 KB。以下兩個方向為使用者提供之延伸脈絡,屬第三方研究、建議查證原始論文:

  • KBLaM(Knowledge Base augmented Language Model):嘗試把知識庫向量直接整合進注意力機制,省去傳統 RAG 的外部檢索模組。
  • LightReasoner(香港大學):指出在特定推理任務中,小模型甚至可當「老師」教大模型,提升整體效率。

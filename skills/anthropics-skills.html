① 這 repo 是什麼 / 怎麼用

官方 · Anthropic 多數 Apache 2.0 document skills：source-available GitHub ↗

定位：Anthropic 官方的 Agent Skills 示範庫。Skill 是一個「資料夾」——裝著指令、腳本與資源，讓 Claude 按需載入、在特定任務上表現更好、而且做法可重複。這個 repo 同時是 agentskills.io 開放標準的參考實作，附 spec/ 規範與 template/ 範本。

授權：多數 example skills 為 Apache 2.0（開源）；四個 document skills（docx/pdf/pptx/xlsx）為 source-available（可看原始碼、非開源）。官方也註明這些 skill 供示範／教育用途，正式產品中的實作可能不同。

倉庫結構

目錄內容
skills/17 個示範 skill，涵蓋文件、創意設計、開發技術、企業溝通四類
spec/agent-skills-spec.md：Agent Skills 規範（SKILL.md 格式、frontmatter 欄位、漸進揭露）
template/SKILL.md 最小範本，複製即可開新 skill
.claude-plugin/把 repo 當作 Claude Code 外掛市集發佈的設定

三種用法

# A. Claude Code：把 repo 當市集加進來，再裝技能組
/plugin marketplace add anthropics/skills
/plugin install document-skills@anthropic-agent-skills
/plugin install example-skills@anthropic-agent-skills

# B. Claude.ai：付費方案可在介面直接「上傳自訂 Skill」

# C. Claude API：透過 Skills API 使用內建或上傳自訂 Skill
安全提醒：Skill 會被 agent 當指令執行、且常帶可跑的腳本。安裝任何 skill 前先讀過 SKILL.md 與其腳本，確認沒有非預期動作。

② Skill 的最小骨架

一個 skill 最少只需要一個資料夾 + 一個 SKILL.md。template/SKILL.md 的內容幾乎就是最小示範：

---
name: template-skill
description: Replace with description of the skill and when Claude should use it.
---

# Insert instructions below

兩個必填欄位

  • name：唯一識別名（小寫、連字號分隔）。
  • description：說清楚「這 skill 做什麼」以及「Claude 何時該用它」——這行是觸發判斷的關鍵，描述得愈精準、模型愈能在對的時機叫它。

正文（frontmatter 底下）就是給 Claude 的指令、範例與規則。需要更多內容時，把大檔案放進 scripts/、references/、assets/ 等子資料夾，由正文按需指路——這就是漸進揭露（progressive disclosure）：SKILL.md 保持精簡（skill-creator 建議 500 行內），龐大資源分開擺、用到才讀。

值得偷師：好的 skill 不是把所有東西塞進一頁，而是「一頁精要 + 需要才展開的附件」。描述欄位寫得像觸發條件表（做 X／提到 Y 檔案時用），而不是空泛介紹。詳細欄位規則以 spec/agent-skills-spec.md 官方 repo 為準。

③ Document Skills（4）

把 Office / PDF 檔當成可程式化操作的物件：多數 Office 檔其實是 XML 的 zip 包，這批 skill 教 Claude 用對的函式庫建立、編輯、讀取，並在交付前驗證。這四個是 source-available。JustKM 本站的 docx/pdf/pptx/xlsx 就是這一脈。

docx
Word 文件（.docx / .dotx）
用途
建立、讀取、編輯、操作 Word 文件與範本——報告、信件、含目錄／頁碼／浮水印的正式文件。
觸發時機
使用者提到 Word doc、.docx/.dotx，或要產出有格式的專業文件。
做法重點
依任務分流：建立用 docx（npm）寫 Node.js 腳本；編輯解壓改 word/document.xml 再壓回；讀取用 pandoc 轉 Markdown。渲染驗證用 LibreOffice。
值得偷師
大量記錄 XML 格式「地雷」（頁面尺寸、表格寬度、目錄需要正確 heading 層級），把踩過的坑寫成規則，讓輸出穩定。
pdf
PDF 全生命週期
用途
抽取文字／表格、合併／拆分／旋轉、加浮水印、建立新 PDF、填表單、加解密、抽圖、掃描檔 OCR。
觸發時機
任何牽涉 .pdf 檔或要產出 PDF 的需求。
做法重點
依操作挑對的函式庫：pypdf（結構操作：合併/拆分/旋轉/加密）、pdfplumber（保留版面抽文字與表格）、reportlab（產生 PDF）、pytesseract/pdf2image（OCR）。
值得偷師
「一個任務、一個最合適工具」的分工思維——不強求單一函式庫全包，而是把每種操作對應到最擅長的工具。
pptx
PowerPoint 簡報（.pptx / .potx）
用途
建立投影片、編輯既有簡報、抽取內容、驗證輸出。把 .pptx 當 XML 的 zip 包做精準控制。
觸發時機
提到「deck / slides / 簡報」或牽涉 .pptx/.potx 檔——無論之後要拿內容做什麼。
做法重點
建立用 pptxgenjs；編輯解壓改 XML 再壓回；讀取用 markitdown 或 scripts/thumbnail.py 看版面。附 schema／關聯／content-type 驗證套件。
值得偷師
明講 python-pptx 的限制（不擅長複製投影片、保留格式），誠實標注工具邊界，避免踩雷。
xlsx
試算表（.xlsx / .csv 等）
用途
開啟／讀取／編輯試算表、加欄位、算公式、格式化、製圖、清理雜亂表格、格式互轉——交付物就是試算表本身。
觸發時機
試算表是主要輸入或輸出時；使用者用檔名／路徑點名某個試算表要動它。
做法重點
有公式用 openpyxl；大量資料用 pandas；快速檢視用 markitdown。動過公式後強制跑 recalc.py 確認能正常計算。
值得偷師
硬性品質關卡：用公式而非硬寫死值、零公式錯誤、交付前一定驗算。把「驗證」寫進流程而非靠自覺。

④ Example：創意與設計（5）

這批示範「怎麼把美感與創意變成可觸發的工作流」，共同套路：先立設計哲學／宣言，再落地成作品，並刻意避開 AI 生成的樣板味。

algorithmic-art
生成式演算法藝術
用途
用 p5.js 產生生成式藝術，帶種子隨機與互動參數，做原創而非臨摹既有藝術家。
觸發時機
要生成／演算法藝術、流場、粒子系統、噪聲驅動、可調參的互動視覺。
做法重點
兩階段：先寫 4–6 段「演算法哲學」宣言，再用 p5.js 實作成自足 HTML artifact——含種子導覽（上一個/下一個/隨機/跳號）、參數滑桿、重生按鈕。種子相同就能重現。
值得偷師
「過程重於成品」——美感從演算法執行中湧現，每次運行都不同卻保持一致性。概念種子藏在參數裡而非明說。
canvas-design
博物館級靜態視覺（PDF/PNG）
用途
產生海報、藝術品等原創靜態視覺，視覺優先於文字。
觸發時機
使用者要海報、artwork、design 等需要原創創意表達的靜態作品。
做法重點
命名一個「美學運動」（4–6 段宣言）→ 推導主題 DNA 藏進作品 → 以極簡整合文字渲染，追求「像花了無數小時」的職人級成品。所有元素須在畫布邊界內、留白得當、禁止重疊。
值得偷師
把「品質標準」寫死成規則（博物館級、禁卡通感、禁抄襲、耐看回味），用明確的反例框住輸出下限。
frontend-design
有記憶點的前端視覺方向
用途
建新 UI 或重塑既有介面時，給出獨特而刻意的視覺方向：色彩、字體搭配、版面、招牌元素。
觸發時機
設計網頁介面、想要「難忘」而非「通用」的成品。
做法重點
兩趟：先寫精簡設計計畫（4–6 個命名色值、字體選擇、版面概念、一個招牌元素），再對著 brief 自我批判是否夠貼「這個專案」。原則：「hero 就是論點」、用結構與字體承載意義而非裝飾、動效只用在關鍵處。
值得偷師
點名三種 AI 設計陳腔（奶油色+襯線、暗底+螢光色、報紙分欄）要刻意避開；「大膽只花在一個地方」。
theme-factory
artifact 主題套用工具
用途
替投影片、文件、報告、HTML 頁面套一致的字體與配色主題。
觸發時機
需要對各類 artifact 施加一致視覺風格時。
做法重點
展示主題陳列 → 詢問偏好 → 取得明確確認 → 全篇套用色與字。內建十套主題（Ocean Depths、Sunset Boulevard、Midnight Galaxy…），各附 hex 與字體配對；不合用可生成自訂主題。
值得偷師
「先展示、要確認、再套用」的互動節奏——把主觀的美感選擇交還使用者拍板，而非替他決定。
slack-gif-creator
Slack 動畫 GIF
用途
做符合 Slack 規格的動畫 GIF（emoji 128×128、訊息 480×480）。
觸發時機
「幫我做一個 X 在做 Y 的 Slack GIF」這類請求。
做法重點
三件組：PIL 逐幀繪圖（ImageDraw 基本圖形）＋ GIFBuilder 組幀並壓到 Slack 檔案限制 ＋ 動畫概念庫（彈跳/脈動/旋轉/淡入/爆發，配緩動函式）。提供減色／降 FPS／縮尺寸的瘦身策略。
值得偷師
把「平台硬限制」（尺寸、檔案大小）當成一級約束寫進工具，並附可執行的驗證，而非事後才發現超標。

⑤ Example：開發與技術（5）

把「工程最佳實踐」變成 agent 能照做的流程——從蓋 MCP server、測試網頁，到做 Claude.ai artifact，再到 skill 本身怎麼做。

mcp-builder
蓋高品質 MCP server
用途
用 Python（FastMCP）或 TypeScript（MCP SDK）建 MCP server，讓 LLM 透過設計良好的工具存取外部服務。
觸發時機
要接外部 API／服務、設計給 LLM 用的工具、或替 MCP server 建評估框架時。
做法重點
四階段：研究規劃 → 實作（專案結構、核心設施、工具）→ 審查測試（MCP Inspector）→ 評估（寫測試題驗證 LLM 真能完成任務）。
值得偷師
成敗以「LLM 能否完成任務」衡量，而非端點覆蓋率；工具名要動作導向、錯誤訊息要能引導 agent 自救。
webapp-testing
用 Playwright 測本地網頁
用途
互動與測試本地 web app：驗證前端功能、除錯 UI、擷取截圖、看瀏覽器日誌。
觸發時機
要驗證前端行為、debug UI、擷取應用狀態時。
做法重點
決策樹：靜態 HTML 直接測，動態則先起 server 再檢視互動。核心是「先偵察再動作」——截圖、從 DOM 找選擇器、再自動操作；動態頁等 networkidle 再檢視。
值得偷師
把 helper 腳本當黑盒：先跑 --help 而非讀原始碼，刻意節省 context——這是給 agent 用的省 token 設計哲學。
web-artifacts-builder
複雜 claude.ai HTML artifact
用途
用現代前端技術做多組件、需要狀態管理／路由／元件庫的 claude.ai artifact。
觸發時機
複雜互動應用——不是單檔簡單 HTML。
做法重點
腳本初始化 React + TypeScript 專案 → 用 Vite / Tailwind / shadcn/ui 開發 → 打包成單一自足 HTML。內建 40+ shadcn/ui 元件與全套 Radix 依賴，自動把 JS/CSS/資產內聯。
值得偷師
明列要避開的「AI slop」設計（過度置中、紫色漸層、一律圓角）——把反模式寫進技能，主動防呆。
claude-api
Claude API / Anthropic SDK 參考
用途
建 Claude 驅動的應用：model ID、定價、參數、串流、tool use、MCP、agents、快取、token 計數的完整參考。
觸發時機
提到 Claude/Anthropic、或做 LLM 形狀的任務（agent/RAG/摘要…）卻沒指定供應商時；用別家（OpenAI/Gemini…）則跳過。
做法重點
先掃專案有無非 Anthropic 標記 → 偵測語言（Python/TS/Java/Go…）→ 讀對應文件 → 一律用官方 SDK 而非裸 HTTP。
值得偷師
description 就是一張精細的「觸發／略過條件表」，示範怎麼寫觸發規則避免誤觸或漏觸。（版本與 model ID 以官方 repo 為準）
skill-creator
做 / 改 / 評測 skill 的元技能
用途
從零建 skill、改進既有 skill、跑 eval 量測表現、優化 description 讓觸發更準。
觸發時機
要建、改、量測 skill，或改善 skill 被 Claude 叫用的準確度時。
做法重點
捕捉意圖 → 寫草稿 → 用子 agent 並行跑「有 skill / 無 skill」對照 → 產生量化斷言、評分、彙整統計 → 依回饋迭代 → 優化 description。
值得偷師
漸進揭露（SKILL.md 500 行內）、「解釋為什麼」而非死規則、從回饋泛化不過擬合測試例、並行跑 baseline 省迭代時間。

⑥ Example：企業與溝通（3）

把「公司的品牌與寫作規範」變成可重複套用的工作流——讓輸出符合組織既定的風格與格式。

brand-guidelines
套用 Anthropic 品牌識別
用途
把 Anthropic 官方品牌色與字體套到任何適合的 artifact 上。
觸發時機
需要品牌風格、設計一致性、企業美感時。
做法重點
系統化：色盤（深 #141413、淺 #faf9f5、灰階、橘/藍/綠三色強調）＋字體（標題 Poppins、內文 Lora，備援 Arial/Georgia）＋依字級自動分派字體、以強調色上圖形。
值得偷師
不需安裝字體、用系統預設＋備援機制，確保跨環境都能可靠呈現——把「可攜性」設計進規範。
internal-comms
內部溝通寫作
用途
寫各類內部溝通：團隊更新、電子報、FAQ、事故報告、主管備忘。
觸發時機
要寫 3P 更新、公司電子報、狀態報告、專案／主管更新、incident report 等內部文件時。
做法重點
三步：從請求分類溝通類型 → 取對應的 examples 指南文件 → 套用該格式的語氣、結構與內容規則。
值得偷師
每種文體各有專屬指南檔（典型漸進揭露）；遇到不符標準分類的請求會反問澄清而非亂猜格式。
doc-coauthoring
結構化共筆文件
用途
引導使用者以結構化流程共同撰寫文件（PRD、design doc、decision doc、RFC）。
觸發時機
提到寫 doc／draft proposal、或指名某種文件類型、或有實質結構化寫作專案時。
做法重點
三階段：蒐集脈絡（Claude 反問補洞）→ 逐段精修（腦力激盪、取捨、成稿）→ 讀者測試（用全新 Claude instance 抓盲點）。編輯用外科式替換而非整篇重印。
值得偷師
「讀者測試」用另一個乾淨 instance 檢查作者看不見的假設與歧義；從最不確定的章節先寫。

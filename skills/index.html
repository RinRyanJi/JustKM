⓪ 什麼是 Skill

Skill（技能包）是一組「包裝好、可按需載入」的指令與資源，讓 AI agent 在遇到特定任務時，臨時把一套專業做法叫進來照著做——而不是把所有知識都塞在系統提示裡。

以 Claude / Agent Skills 為例，一個 Skill 通常是一個資料夾，核心是一份 SKILL.md：

  • Frontmatter：name + description——description 決定「什麼任務會觸發它」，是整個 Skill 最關鍵的一行。
  • 正文：精簡的做法指引（做什麼、步驟、注意事項）。
  • 附帶資源：可選的 references/、範本、腳本、資料檔——需要時才讀，稱為漸進揭露(progressive disclosure)。
一句話：Skill = 「可重用、可觸發、可版本控管的能力包」。它把「你每次都要重打的一長串 prompt」變成「打一次、之後自動在對的時機被叫出來」的東西。

① 為什麼 Skill 重要

  • 把一次性 prompt 變成資產：好做法不再散落在對話裡，而是沉澱成可複用、可分享、可迭代的檔案。
  • 省 context：只有被觸發時才載入，平時不佔系統提示的篇幅——這正是「漸進揭露」的價值。
  • 穩定與一致：同一種任務每次都走同一套流程，減少 AI 的隨機性。
  • 可組合：多個小 Skill 各司其職，比一個巨大提示更好維護。
呼應 learn 區的主題：不靠「更強的模型」，而靠「更好的環境與溝通」。Skill 就是把「溝通」制度化——用結構取代每次臨場發揮。

② 分析任何 Skill 的 6 個維度

拿到任何一個 Skill，用這六題就能快速判斷它好不好、該不該用：

維度要問什麼好的訊號
1 · 觸發description 寫得準嗎？該觸發時會觸發、不該時不誤觸？描述具體、列出關鍵字與情境，邊界清楚
2 · 意圖 / 範圍解決什麼問題？邊界在哪？不做什麼？單一明確職責，不貪多
3 · 漸進揭露SKILL.md 精簡嗎？細節有沒有拆到 references？主檔短、深資料按需載入
4 · 工具 / 資源用哪些工具？附範本、腳本、資料嗎？自帶可執行資源，不用臨場拼湊
5 · 執行模式行內執行還是丟子代理？輸出是什麼形式？模式與任務相稱，輸出可預期
6 · 品質信號冪等？可組合？有失敗處理與維護嗎？可重跑、與別的 Skill 相容、有在更新

③ 各類 Skill 巡覽與分析

把常見 Skill 依「產出什麼」分成五大類。每一類的觸發時機與分析重點不同：

A · 文件產出類

以「檔案為主要輸入／輸出」的任務。觸發判斷通常看目標交付物的副檔名。

Skill幹嘛的觸發重點
docx建立/讀取/編修 Word 文件交付物是 .docx / 報告 / 公文 / 信件 / 範本
pptx簡報製作與讀取提到 deck / slides / 簡報 / .pptx
pdfPDF 讀取/合併/拆分/填表/OCR提到 .pdf 或要產生 PDF
xlsx試算表建立/清理/公式/圖表主要輸入或輸出是試算表
分析要點：這類 Skill 的價值在「正確操作二進位檔格式」，觸發準確度靠副檔名與交付物判斷，最怕「明明只是要純文字卻誤觸」。

B · 視覺 / 設計類

Skill幹嘛的觸發重點
dataviz任何圖表 / 儀表板的設計與配色寫任何 chart/plot 程式或選色之前就該載入
artifact-designArtifact 頁面的設計原則要做 HTML/網頁型 artifact 時
artifact-diagramming圖解 / 內嵌 SVG 的畫法需要示意圖、機制圖時
分析要點：這類的關鍵是「在動手前就被叫出來」——設計決策一旦寫下去再改成本高，所以觸發時機要早。

C · 元技能（做技能的技能）

Skill幹嘛的
skill-creator建立、修改、優化、評測其他 Skill；還能調 description 提升觸發準確率
update-config改 settings.json：權限、hooks、環境變數等自動化設定
為什麼重要：元技能讓「Skill 生態」能自我演進——用 skill-creator 的評測與 variance 分析，可以量化一個 Skill 到底好不好、觸發準不準。

D · 工作流 / 程式碼類

Skill幹嘛的
code-review對 diff / PR 做正確性與簡化審查，可依 effort 調範圍
simplify只做重用/簡化/效率清理（不抓 bug）
security-review對變更做安全審查
run啟動並實際跑起專案，驗證改動
loop把某個任務/指令按固定間隔重複跑
分析要點：工作流類最看「邊界清楚」——例如 simplify 明講「不抓 bug、只清理」，避免與 code-review 職責重疊、互相誤觸。

E · 平台 / 整合類

Skill幹嘛的
session-start-hook幫 repo 設定 Web 版 Claude Code 的啟動 hook（確保能跑測試/lint）
morning把「晨間簡報」渲染成 artifact，或設成週間排程
claude-apiClaude API/SDK 參考：模型 id、定價、串流、工具使用、快取

④ 好 Skill 的特徵 vs 反模式

面向✅ 好 Skill⚠️ 反模式
description具體、含觸發關鍵字與情境、講清楚何時不要用模糊如「幫忙處理文件」→ 誤觸或漏觸
職責單一、邊界清楚一個 Skill 想做十件事
篇幅主檔精簡，深資料拆 references把所有細節塞進 SKILL.md
相容與其他 Skill 職責不重疊、可組合與別的 Skill 搶觸發、彼此打架
可驗證用 eval 量化觸發準確率與效果憑感覺，沒量測
最常見的失敗：不是內容不好，而是 description 沒寫好——該觸發時沒被叫出來，或不相干時亂觸發。分析一個 Skill，先看它的觸發設計。

⑤ 想自己做一個 Skill？

  1. 先定義觸發：這個 Skill 該在什麼任務、什麼關鍵字出現時被叫出來？寫進 description。
  2. 收斂職責：只解一個問題；把「不做什麼」也寫清楚。
  3. 主檔精簡：SKILL.md 只放核心步驟，細節與範本拆到 references/。
  4. 附可執行資源：能給腳本/範本就別叫模型臨場重寫。
  5. 用 skill-creator 評測：跑 eval 看觸發準不準、效果穩不穩，再迭代 description。
這一頁本身就是一個「分析框架 Skill」的雛形——之後可以把每個具體 Skill 的深入拆解，各自獨立成一頁掛在這個專區底下。

① 這個 repo 是什麼 / 適用工具

精選技能包 · CommandCodeAIMITGitHub ↗

README 一句話定位：「A curated list of practical Skills for enhancing workflows and capabilities of coding agents.」——一份精選、可實戰的 coding agent 技能清單。與多數「純工程」技能包不同，它的範圍橫跨開發、雲端、設計、商務、內容，超過 40 個 skill、分九大類。

倉庫結構單純：所有技能都放在 skills/ 目錄下，每個技能一個資料夾、內含 SKILL.md（外加腳本、範本、資源）。這正是 Anthropic Agent Skills 的通用模組結構——metadata 常駐、SKILL.md 觸發時載入、附帶資源按需載入的漸進揭露設計。

為誰打造、能在哪裡用

  • 為 Command Code 平台打造，但因為採用標準 SKILL.md 模組結構，同一份技能可被支援 Agent Skills 的其他 agent 通用取用（以官方 repo 說明為準）。
  • 取材廣：可見到與 Anthropic 官方同源的 docx/pdf/pptx/xlsx、skill-creator、mcp-builder，也有平台自製的商務、設計、雲端技能。
本頁挑選各類代表性技能逐一深拆（用途 / 何時用 / 做法重點 / 值得偷師）；類別內技能太多時，其餘僅列名並誠實標示未逐一深拆。內容以撰寫時各技能 SKILL.md 為準。

② 軟體開發

本類共 12 個技能：artifacts-builder、brainstorming、changelog-generator、mcp-builder、playwright、receiving-code-review、requesting-code-review、skill-creator、using-git-worktrees、webapp-testing、writing-plans、writing-skills。以下深拆 5 個代表，其餘列名。

artifacts-builder · 複雜前端 artifact 產生器

用途：一套工具鏈，用現代前端技術（React、Tailwind CSS、shadcn/ui）打造多元件的 claude.ai HTML artifact，超越單檔 HTML 的能力。

何時用：artifact 需要狀態管理、路由或 shadcn/ui 元件時。單純的單檔 HTML/JSX 就別動用它。

做法重點：

  • scripts/init-artifact.sh 起專案（React + TypeScript + Vite + Tailwind + shadcn/ui）→ 開發 → scripts/bundle-artifact.sh 打包成單一 HTML → 當 artifact 分享。
  • 刻意「先出貨、後測試」以降延遲：先呈現，有問題再測。
值得偷師：SKILL.md 明列反面清單——避免「AI slop」美學：別滿版置中、別紫色漸層、別到處圓角、別一律用 Inter 字體。把「不要做什麼」寫死，比只講「要好看」有效得多。

mcp-builder · 高品質 MCP Server 建構指南

用途：指導打造高品質 MCP（Model Context Protocol）server，讓 LLM 透過設計良好的工具與外部服務互動。

何時用：要用 Python（FastMCP）或 Node/TypeScript（MCP SDK）把外部 API / 服務包成 MCP server 時。

做法重點：四階段流程——

  1. 研究與規劃：先吃透「以 agent 為中心」的設計原則（設計工作流而非照搬 endpoint、為 context 限制最佳化），研讀 MCP 協定與目標 API 文件，產出含工具取捨、I/O 設計、錯誤處理的實作計畫。
  2. 實作：建專案骨架與共用基礎（API helper、錯誤處理、格式化），逐一實作工具（Python 用 Pydantic、TS 用 Zod 驗證，附完整 docstring 與 annotation）。
  3. 審查與精修：DRY、可組合、一致性、型別安全的程式碼審查；用評測 harness 測試，避免直接跑 server 造成卡住的程序。
  4. 評估：出 10 題複雜、真實、獨立、唯讀的評估題，手動驗證答案，以指定 XML 格式輸出。
值得偷師：「工作流優先於 endpoint」＋「為 context 限制最佳化」是設計 agent 工具的心法；把評估寫成 10 題唯讀基準，讓工具品質可被反覆量測。

skill-creator · 技能的技能

用途：Frontmatter 原句——「Guide for creating effective skills... extends Claude's capabilities with specialized knowledge, workflows, or tool integrations.」教你把專門知識、工作流、工具整合打包成模組化 skill。

何時用：要新建或更新一個 skill 時。

做法重點：理解需求（用具體使用例）→ 規劃可重用內容（腳本 / 參考 / 資產）→ init_skill.py 產模板 → 撰寫祈使句式的 SKILL.md → package_skill.py 驗證打包成 zip → 依真實測試迭代。

值得偷師：核心設計原則是漸進揭露——metadata 常駐（約 100 字）、SKILL.md 觸發才載入（<5k 字）、附帶資源按需載入。這是整個 Agent Skills 生態的共通地基。

writing-plans · 實作計畫產生器

用途：在動手寫程式前，把多步驟任務拆成「小到不能再小」的實作計畫，並假設接手工程師對本 codebase 零背景。

何時用：已有規格 / 需求、要在獨立 worktree 內規劃實作路徑時。

做法重點：

  • 任務切成 2–5 分鐘的原子動作（測試 → 執行 → 實作 → 驗證 → commit）。
  • 寫到「零猜測」：精確檔案路徑、完整程式碼樣本、含預期輸出的指令。
  • TDD：先寫失敗測試，再寫最小實作。存到 docs/plans/YYYY-MM-DD-<feature>.md。
值得偷師：座右銘「DRY. YAGNI. TDD. Frequent commits.」＋「假設工程師很強但不熟你的工具鏈」——所以要給足脈絡卻不假設領域知識。

using-git-worktrees · 安全隔離工作區

用途：建立隔離的 git worktree，智慧選目錄＋安全驗證，讓多分支能同時進行、不必來回切換。

何時用：開始需要與現有工作區隔離的功能開發、或執行需要乾淨環境的實作計畫時。

做法重點：目錄選擇有優先序（既有 .worktrees/ → 查 CLAUDE.md 偏好 → 問使用者）；安全驗證用 git check-ignore 確認被 gitignore，沒有就補上並立即 commit；自動偵測依賴安裝（npm/cargo/pip/poetry/go）；跑 baseline 測試確認乾淨起點才繼續。

值得偷師：「系統化目錄選擇＋安全驗證＝可靠隔離」。把「先確認被 gitignore」變成硬性關卡，避免把 worktree 誤 commit 進主庫。

本類其餘技能（未逐一深拆）

brainstorming（開工前用提問打磨想法）、changelog-generator（把 git commit 轉成好讀的發布說明）、playwright（瀏覽器自動化與表單填寫）、requesting-code-review（派子代理在合併前抓問題）、receiving-code-review（帶技術查證地處理審查回饋）、webapp-testing（用 Playwright 測本地 web app）、writing-skills（以 TDD 方式建 skill）。

③ 雲 / AWS

本類共 4 個技能：aws-agentic-ai、aws-cdk-development、aws-cost-operations、aws-serverless-eda。深拆 2 個代表。

aws-agentic-ai · Bedrock AgentCore 部署

用途：涵蓋 AWS Bedrock AgentCore 七大核心服務的部署與管理——Gateway、Runtime、Memory、Identity、Code Interpreter、Browser、Observability，含 MCP target 部署、憑證管理、schema 最佳化。

何時用：建 AI agent 基礎設施時——把 REST API 轉成工具、跑無伺服器 agent、管理對話狀態、處理憑證、監控 agent 效能。

做法重點：先依需求選服務（Gateway 對 API、Runtime 對部署、Memory 對狀態、Identity 對憑證）；Gateway target 流程為「上傳 OpenAPI schema 到 S3 → 建憑證 provider → 綁 schema 到 target → 驗證狀態」；憑證用 Identity provider 以 ARN 引用、季度輪替、CloudWatch 監控。

值得偷師：硬性要求「有 AWS MCP 工具就用它查證答案，沒有就引導使用者裝設」——把「別憑記憶答雲端設定」寫進技能本身。

aws-cost-operations · 成本與維運最佳實踐

用途：AWS 成本最佳化、監控與維運最佳實踐，內建多個 MCP server 做帳單分析、成本估算、可觀測性與安全評估。

何時用：要降成本、事前估算部署費用、建立可觀測性與告警、稽核 AWS 活動、評估安全態勢時。

做法重點：三條工作流——成本（Pricing MCP 估算 → Billing MCP 追蹤 → Cost Explorer MCP 細分 → 落實優化）、監控（CloudWatch 指標告警 → Application Signals APM → 查 log）、安全（CloudTrail 稽核 → Well-Architected 安全評估 → 修補）。整合約 8 個 MCP server。

值得偷師：把「一致標記所有資源、每月檢視花費、依實際用量 right-size、設預算告警」這種平常靠人記的維運紀律，直接編成技能的固定檢查項。

本類其餘技能（未逐一深拆）

aws-cdk-development（用 AWS CDK 寫基礎設施即程式碼）、aws-serverless-eda（事件驅動架構模式）。

④ Cloudflare

本類共 2 個技能，皆聚焦「在 Cloudflare 上蓋 agent 基礎設施」。深拆 1 個代表。

building-mcp-server-on-cloudflare · Workers 上的遠端 MCP Server

用途：在 Cloudflare Workers 上建帶工具、OAuth 驗證與生產部署的遠端 MCP server——產生 server 程式碼、設定 auth provider、部署到 Workers。

何時用：要建遠端 MCP server、把工具以 MCP 對外、加 OAuth 或部署 MCP 到 Cloudflare Workers 時。

做法重點：用 server.tool() 註冊工具（Zod schema 驗證參數）→ 設進入點路由（通常 /mcp）→ npm start 本地測、用 MCP Inspector 驗證 → npx wrangler deploy 部署 → 客戶端連遠端 endpoint。

值得偷師：用 Zod schema 自動做輸入驗證與型別安全；在 tool handler 內用 this.env 存取 D1、KV 綁定；用 serveSSE() 撐客戶端連線；OAuth 走 provider 模板（GitHub / Google / Auth0）。

本類其餘技能（未逐一深拆）

building-ai-agent-on-cloudflare（用 Cloudflare Agents SDK 建 AI agent）。

⑤ 內容 / 溝通

本類共 4 個技能：content-research-writer、internal-comms、meeting-insights-analyzer、notebooklm。深拆 2 個代表。

content-research-writer · 會查證的寫作夥伴

用途：邊研究邊寫作——加引用、改善開頭鉤子、迭代大綱、逐段即時回饋，同時保留作者本人的聲音與風格。

何時用：寫部落格 / 文章 / 電子報、教學內容、思想領導文、案例研究，或需要正式引用來源、想逐段拿到回饋時。

做法重點：先用釐清問題定義主題 / 受眾 / 長度 / 目標 / 文風 → 共同建大綱並標出研究缺口 → 找可信來源與引用 → 提供多個鉤子替代版 → 逐段檢視清晰度 / 流暢度 / 證據 → 引用格式依使用者偏好（inline / 編號 / 註腳）。

值得偷師：「保留作者聲音」被寫成明確原則——用建議而非規定、先學使用者風格再動筆，避免 AI 把每篇文章寫成同一個腔調。

meeting-insights-analyzer · 會議行為模式分析

用途：分析會議逐字稿 / 錄音，挖出行為模式與溝通洞察——例如迴避衝突、贅字、發言壟斷等習慣，用來提升領導與主持效能。

何時用：要追蹤跨會議的溝通模式、拿主持風格回饋、辨識「迴避難談的事」、為績效檢討準備具體實例時。

做法重點：掃描資料夾找逐字稿（.txt/.md/.vtt/.srt/.docx）並辨識講者標籤與時間戳 → 問使用者想檢視哪些行為 → 分析 hedging 語言、發言比例、提問對陳述比 → 給帶時間戳的引用與更好的替代說法 → 匯總優勢、成長點與發言統計。

值得偷師：洞察一律搭「時間戳＋原句引用＋為何重要＋更好做法」，讓抽象的「你常迴避衝突」變成可對照、可拿去績效面談的具體證據。

本類其餘技能（未逐一深拆）

internal-comms（寫公司電子報、更新、狀態報告）、notebooklm（查詢 Google NotebookLM 筆記本、取得有來源依據的答案）。

⑥ 視覺 / 媒體

本類共 6 個技能：canvas-design、image-enhancer、slack-gif-creator、theme-factory、video-downloader、youtube-transcript。深拆 2 個代表。

canvas-design · 美術層級的視覺創作

用途：Frontmatter 原句——「Create beautiful visual art in .png and .pdf documents using design philosophy.」用「先立美學流派、再視覺表現」的兩階段流程做原創設計。

何時用：使用者要海報、藝術品、需要精緻「博物館級」輸出的靜態視覺件時。

做法重點：先寫一份設計宣言（.md）命名一個美學流派、闡述其在形體 / 空間 / 色彩 / 構圖上的原則 → 埋入巧妙的小眾指涉 → 在 canvas（.pdf/.png）以重複圖樣、系統性標記、極簡臨床式排版表現 → 精修時只打磨既有構圖、不加元素。

值得偷師：核心原則「資訊活在設計與視覺層級裡，不在說明文字裡」——逼作品看起來像業界頂尖者反覆勞作出來的，而非堆字說明。

theme-factory · artifact 主題工具箱

用途：替 artifact（簡報、文件、HTML 頁）套主題的工具箱，內含 10 組專業預設主題，也能即時生成客製主題。

何時用：要替簡報 / artifact 套上一致、專業的視覺識別時。

做法重點：先展示主題預覽 PDF → 問使用者偏好 → 取得明確確認 → 全套套用該主題的顏色與字體。每組主題都附 hex 色票與標題 / 內文的字體配對，規格存在 themes/ 目錄；主題涵蓋航海、極簡、科技、植物、宇宙等情境。

值得偷師：「先看預覽 → 明確確認 → 才套用」的握手流程，避免 agent 自作主張改掉整份文件的視覺；把顏色與字體配對綁成一個可挑選的整體。

本類其餘技能（未逐一深拆）

image-enhancer（提升影像解析度與清晰度）、slack-gif-creator（做 Slack 最佳化的動態 GIF）、video-downloader（從 YouTube 等平台下載影片）、youtube-transcript（抽取影片逐字稿與字幕）。

⑦ 商務營運

本類共 4 個技能：brand-guidelines、competitive-ads-extractor、domain-name-brainstormer、lead-research-assistant。深拆 2 個代表。

brand-guidelines · 品牌識別自動套用

用途：把品牌官方色與字體套到任何受惠於品牌一致性的 artifact（此技能以 Anthropic 品牌為示範：主色深 #141413、淺 #faf9f5、中灰 #b0aea5，加橘 / 藍 / 綠強調色）。

何時用：設計需符合企業識別的文件、簡報、素材時。

做法重點：標題用 Poppins（24pt+）、內文用 Lora，字體不可用時自動退回 Arial / Georgia；依背景脈絡自動選色，並讓強調色在非文字形狀間輪替以維持層級。無需安裝字體，跨平台優雅降級。

值得偷師：「依背景自動選色＋強調色在形狀間輪替＋字體優雅降級」——把品牌規範寫成會自我約束的規則，而不是丟一堆色票要人手動對照。

competitive-ads-extractor · 競品廣告拆解

用途：從廣告庫（Facebook、LinkedIn 等）抓取並分析競品廣告，理解哪些訊息、痛點與創意手法有效。

何時用：研究競品廣告策略、找自家 campaign 靈感、理解市場定位與訊息時。

做法重點：從廣告庫抽取廣告 → 截圖存視覺副本 → 分析訊息中的問題 / 使用情境 / 價值主張 → 依主題 / 受眾 / 格式分類 → 找出成功手法的共通模式 → 產出洞察。

值得偷師：建議「每月監測競品變化、建立參考庫、把競品模式當假設拿去自家實測」——把一次性競品調查變成可持續累積的情報流程。

本類其餘技能（未逐一深拆）

domain-name-brainstormer（發想創意網域名並查可用性）、lead-research-assistant（辨識並篩選目標潛在客戶）。

⑨ 資料 / 自動化

合併 README 的「資料分析」與「工作流自動化」兩類，共 4 個技能：developer-growth-analysis（資料分析）、file-organizer、invoice-organizer、raffle-winner-picker（自動化）。深拆 1 個代表。

invoice-organizer · 報稅用發票整理

用途：自動整理發票與收據以備報稅——讀凌亂檔案、抽關鍵資訊、一致地重新命名、分類到合理資料夾。

何時用：報稅季整理、跨廠商管理商業支出、把一堆雜亂收據歸檔、為會計準備資料時。

做法重點：掃描找出所有發票檔（PDF / 圖片 / 文件）→ 抽出廠商 / 日期 / 發票號 / 金額 / 描述 → 決定分類策略（依廠商 / 類別 / 日期 / 稅務分類）→ 標準化檔名 YYYY-MM-DD Vendor - Invoice - Description.ext → 建 年/類別/廠商 資料夾 → 複製而非移動檔案 → 產出含明細的 CSV 供會計軟體用。

值得偷師：「保留原檔、只整理副本」是關鍵安全設計——批次改名 / 搬移最怕弄丟資料，先複製再動就把風險壓到零。

本類其餘技能（未逐一深拆）
